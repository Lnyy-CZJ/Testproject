# 接口自动化测试框架开发计划

> **执行要求：** 使用 Superpowers 的 subagent-driven-development 或 executing-plans 工作流，按阶段执行 TDD、规格审查、代码质量审查和完成前验证。

## 一、目标与执行前提

基于已确认的设计方案，分 5 个阶段完成 Python + Pytest 接口自动化框架，并覆盖 Gateway 信封、身份订阅、媒体搜索、权益扩展、Jenkins 持续检查。

- 每阶段独立实现、测试、审查和验收，通过后进入下一阶段。
- 只创建本计划列出的必要文件，避免计划外架构和无关重构。
- 公共类、公共方法及复杂逻辑使用中文注释，包含功能、参数、返回值和异常说明。
- 仅执行安全联调集：读取、会话、参数校验和可追溯搜索。订单、支付、反馈等写入场景默认只运行 mock 测试。
- 权益夹具、飞书和 Jenkins 采用适配器先行；缺少真实协议或凭据时不阻塞代码交付，真实联调测试明确跳过。

## 二、核心接口与配置约定

- `GatewayClient.invoke(...)`：构造 Gateway 信封、保持幂等请求 ID、解析响应并记录脱敏诊断。
- `GatewayResponse`、`GatewaySubResponse`、`CommContext`：Pydantic 模型，允许服务端新增字段。
- `assert_gateway_received()`、`assert_business_success()`、`assert_business_error()`：统一双层断言。
- `CaseContext`：保存 token、user、media、task、candidate 等当前用例动态数据。
- `TaskWaiter.wait_terminal()`：按照 2 秒/3 秒间隔轮询，最大等待 20 秒。
- Service 层只封装业务参数，不直接处理 HTTP。
- `EntitlementFixtureAdapter`：权益发放/撤销协议，提供禁用实现和 mock 实现。
- `FeishuNotifier.publish()`：飞书通知接口，未配置 Webhook 时安全跳过。
- `runtest.py`：统一解析环境、suite、marker、并发和报告参数。

配置优先级：`命令行 > Jenkins 环境变量 > env.<name>.yaml > 默认值`。敏感数据仅通过环境变量或 Jenkins Credentials 注入，`user_id` 不默认写入 Gateway `comm`。

## 三、分阶段实施

### 阶段 1：框架基座

- 创建依赖、Pytest、忽略规则、README、配置和统一运行入口。
- 实现 Gateway Client、统一信封模型、超时与有限重试。
- 实现递归脱敏、YAML/JSON 数据加载、结构校验、缓存、数据工厂和上下文。
- 实现双层断言、Allure/JUnit 输出及 Home 示例契约用例。
- 验证配置优先级、缓存失效、信封、解析、重试、脱敏、报告和安全只读联调。

### 阶段 2：身份与订阅契约

- 实现 Identity、Subscription、Billing Service。
- 实现匿名会话 fixture、账号三元组上下文及最新 token 原子替换。
- 实现稳定幂等 ID，迁移 TC-001、TC-002、TC-007～TC-015 可执行子集。
- 订单、验单、恢复和 Billing 写接口只做 mock 契约测试并标记风险标签。
- 安全联调仅执行会话及订阅读取接口。

### 阶段 3：媒体与搜索主链路

- 实现 Media Service、COS PUT Client、Search Service。
- 未提供 `TEST_MEDIA_PATH` 时跳过真实上传。
- 实现创建搜索、兼容启动、任务查询、候选列表/详情和历史。
- 实现 20 秒 Task Waiter，迁移 TC-005、TC-006、TC-016～TC-023。
- 验证输入边界、幂等、三种允许终态、状态倒退、未知状态和超时。

### 阶段 4：权益夹具与扩展流程

- 定义权益适配器、禁用实现、mock 实现和真实 HTTP 扩展入口。
- 实现 Report、ProfileFeedback、RefineTask、AddReportPhotos、SubmitFeedback。
- 迁移 TC-025～TC-030 当前可执行子集。
- TC-024、真实支付回调、沙箱交易和自动数据清理保持禁用。

### 阶段 5：Jenkins 与治理

- 创建 Jenkinsfile，支持环境、执行集、marker、并发和报告参数。
- 默认排除真实支付、破坏性和未授权写入用例。
- 集成 JUnit、Allure 30 天趋势、1 MB 失败附件限制。
- 实现飞书通知适配器的 dry-run/禁用模式并补充运行手册。

门禁规则：合并请求执行 contract + P0 非写入；每日执行 smoke + P0；发布前 P0 阻断、P1 人工确认；支付与兼容扩展仅手工触发。

## 四、测试与验收

- 每个功能严格执行 RED → GREEN → REFACTOR。
- 单元测试覆盖配置、加载、脱敏、模型、断言、等待器和通知适配器。
- mock 契约测试覆盖写接口、支付接口、权益夹具和异常响应。
- 安全联调仅运行已授权范围；缺少凭据时有明确 skip 原因。
- 检查代码、日志和报告不包含 token、refresh token、预签名 URL。
- 不修改原始接口文档、Excel 用例和历史日志。

总体完成标准：阶段 1–5 离线测试全部通过；可用条件对应的安全联调通过；P0/P1、TC 编号、Allure/JUnit 和 Jenkins 门禁可用；公共代码包含有效中文注释；无计划外架构和无关重构。

## 五、锁定假设

- Requests 为唯一 HTTP 客户端，Pydantic 使用 v2。
- 依赖通过 `pyproject.toml` 声明并生成带哈希的 `requirements.lock`。
- 无测试图片时跳过 COS 真实上传，不引入未经授权的人像。
- 权益、飞书和 Jenkins 真实凭据后补，第一版交付可替换适配器与 mock 测试。
- 每阶段通过测试、规格审查和代码质量审查后进入下一阶段。
