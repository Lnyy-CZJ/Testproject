# 客户端接口文档 3\.0



更新时间：2026\-06\-29



本文档面向 iOS / Android 客户端，覆盖当前通过 `gateway` 对外开放的客户端接口。3\.0 的核心变化是：搜索输入从“单字段查询”升级为“一组结构化线索 clues”，并补齐候选集列表、报告 UI sections、报告页补图刷新、首页内容和个人中心反馈。



## 当前状态



- 测试环境 gateway：`http://gateway.spark-jam.top`

- 统一入口：`POST /gateway/invoke`

- 图片二进制不经过 gateway，客户端直传 COS。

- 搜索接口以 `clues` 为 3\.0 主入口。

- 顶层 `query_type + xxx_query` 是旧版兼容字段，新客户端不要再使用。

- `FULL_NAME` 是当前 people search 主流程必填线索，必须正好 1 条。

- `LOCATION` 是独立 clue，不放在 `full_name_query` 下面。

- `PHOTO` 和 `SOCIAL_LINK` 支持多条 clue。

- `PHOTO` 是图片线索补齐和反查，不是确定身份识别。

- App Store / Google Play 真实购买闭环需要客户端提供平台交易凭证。

- SearchAPI/SerpApi Google Lens \+ TinEye \+ Pipl/PDL 是目标链路；环境是否启用取决于后端第三方 key 配置。

    

## Gateway 调用格式



所有客户端接口都走同一个 envelope：



```JSON
{
  "comm": {
    "auth_token": "access_token，可选接口可不传",
    "device_id": "客户端持久化设备 ID",
    "install_id": "客户端安装 ID，可选",
    "client_request_id": "客户端幂等请求 ID，可选",
    "trace_id": "可选，不传则 gateway 生成",
    "platform": "ios",
    "app_version": "1.0.0",
    "locale": "zh-CN",
    "timezone": "Asia/Shanghai",
    "advertising_id": "IDFA/GAID，可选；兼容字段 did",
    "app_package": "iOS bundle id / Android package name，可选；兼容字段 pkg/bundle_id/package_name"
  },
  "execution": {
    "mode": "sequential",
    "stop_on_error": false
  },
  "requests": [
    {
      "id": "r1",
      "service_name": "tool.identity.IdentityService",
      "method_name": "CreateAnonymousSession",
      "params": {
        "consent_policy_version": "2026-06-01"
      }
    }
  ]
}
```



`comm` 说明：



- `device_id`：客户端持久化设备 ID，必填。

- `user_id`：客户端不需要传。服务端登录成功后返回 `user_id`，后续由 `auth_token` 解析。

- `advertising_id`：广告 ID，可选。iOS 通常是 IDFA，Android 通常是 GAID；如果客户端暂时只能传 `did`，gateway 会兼容。

- `app_package`：应用包标识，可选。iOS 是 bundle id，Android 是 package name；gateway 兼容 `pkg`、`bundle_id`、`package_name`。

- `advertising_id/app_package` 只用于分析归因，不参与鉴权，不覆盖服务端 `user_id`。

    

响应格式：



```JSON
{
  "code": 0,
  "message": "OK",
  "request_id": "gw_req_xxx",
  "trace_id": "trace_xxx",
  "responses": [
    {
      "id": "r1",
      "code": 0,
      "message": "OK",
      "success": true,
      "business_error_code": "",
      "http_status": 200,
      "data": {}
    }
  ]
}
```



客户端判断规则：



- 网络失败或 HTTP 非 2xx：按网络/网关异常处理。

- HTTP 2xx 只代表 gateway 收到并返回 envelope。

- 业务是否成功看 `responses[].success` 或 `responses[].code == 0`。

- 业务分支优先看 `business_error_code`，数字 `code` 用于日志、埋点和排查。

- 时间字段在 HTTP JSON 中统一是 Unix milliseconds。

- 创建类接口必须使用稳定 `client_request_id`，失败重试继续使用同一个值。

- `FULL_NAME`

- `SOCIAL_LINK`

- `PHOTO`

- `LOCATION`

`SearchTaskStatus`：



- `CREATED`

- `QUEUED`

- `SEARCHING`

- `PARTIAL_SUCCEEDED`

- `SUCCEEDED`

- `FAILED`

- `EXPIRED`

- `CANCELED`

- `REJECTED`

    

`EntitlementDecision`：



- `ALLOW`

- `REQUIRE_SUBSCRIPTION`

- `QUOTA_EXCEEDED`

- `CONCURRENCY_EXCEEDED`

- `SUBSCRIPTION_EXPIRED`

- `RISK_BLOCKED`

- `REGION_BLOCKED`

    

`AdditionalDetailType`：



- `PROFESSION`

- `EMPLOYER`

- `SCHOOL`

- `OTHER`

    

`FeedbackType` 建议值：



- `wrong_person`：候选人物明显不相关

- `not_relevant`：结果整体相关性低

- `too_few_results`：结果太少

- `stale_info`：信息过期

- `privacy_concern`：用户认为结果涉及隐私或敏感内容

- `other`：其他问题

    

## 推荐主流程



```Plain Text
CreateAnonymousSession
-> ListSubscriptionProducts
-> CreateSubscriptionOrder
-> 客户端拉起 App Store / Google Play 购买
-> VerifySubscriptionPurchase
-> GetEntitlement
-> 如有图片：GetMediaUploadConfig -> PrepareMediaUpload -> PUT COS -> CompleteMediaUpload
-> CreateIntentTask(clues)
-> GetTask 轮询到 SUCCEEDED / NO_RESULT / FAILED
-> 成功后调用 ListTaskCandidates 展示候选列表
-> 用户点击候选时调用 GetTaskCandidateDetail
-> 报告页用户补图时 AddReportPhotos -> GetTask(refresh_task_id) -> ListTaskCandidates(refresh_task_id)
-> 用户不满意时 SubmitFeedback 或 RefineTask
```



搜索结果模型边界：



- `task` 是一次搜索任务，客户端用 `task_id` 轮询状态。

- `report` 是服务端内部结果快照容器，用于落库、审计、反馈、后台排查，不作为 C 端页面入口暴露。

- `candidate` 是客户端展示和点击的人物结果。候选列表用 `ListTaskCandidates`，候选详情用 `GetTaskCandidateDetail`。

- C 端协议不返回 `report_id`。所有搜索页、历史页、详情页都使用 `task_id`；候选详情额外使用 `candidate_id`。

    

## IdentityService



### CreateAnonymousSession



`device_id`、`advertising_id/did`、`app_package/pkg` 放在 gateway `comm` 里，不放在 `params` 里。`user_id` 由服务端生成并返回，客户端不要在登录请求里传。



```JSON
{
  "service_name": "tool.identity.IdentityService",
  "method_name": "CreateAnonymousSession",
  "params": {
    "consent_policy_version": "2026-06-01"
  }
}
```



`data`：





|字段|类型|说明|
|---|---|---|
|`user_id`|string|用户 ID|
|`access_token`|string|后续放到 `comm.auth_token`|
|`expires_time`|int64|access token 过期时间|
|`refresh_token`|string|刷新 token|
|`refresh_expires_time`|int64|refresh token 过期时间|
|`is_new_user`|bool|是否新用户|





### RefreshSession



```JSON
{
  "service_name": "tool.identity.IdentityService",
  "method_name": "RefreshSession",
  "params": {
    "refresh_token": "refresh_xxx"
  }
}
```



`data` 返回新的 `access_token`、`expires_time`、`refresh_token`、`refresh_expires_time`。

### GetSubscriptionStatus



```JSON
{
  "service_name": "tool.subscription.SubscriptionService",
  "method_name": "GetSubscriptionStatus",
  "params": {
    "product_code": "people_insight",
    "scenario": "search"
  }
}
```



`data` 主要字段：



|字段|类型|说明|
|---|---|---|
|`has_active_subscription`|bool|当前是否有可用订阅；只有 `active` 时为 true|
|`subscription_status`|string|三态：`inactive` 未激活 / `active` 已激活 / `expired` 已过期|
|`product_code`|string|产品代码|
|`plan_code`|string|套餐代码；未激活时通常为 `free`，已过期时返回最近过期套餐|
|`tier_code`|string|等级代码；已激活或已过期时尽量返回|
|`vip_level`|int|VIP 等级|
|`expires_time`|int64/null|订阅/权益过期时间，Unix milliseconds|
|`unavailable_reason`|string|不可用原因：`not_subscribed` / `subscription_expired` 等|
|`entitlement`|object|权益判定快照|



状态语义：



- `inactive`：未激活过有效订阅，或订阅被撤销/退款后当前不可用。

- `active`：当前有可用订阅，`has_active_subscription = true`。

- `expired`：曾经有订阅，但最近订阅已过期，`has_active_subscription = false`，`unavailable_reason = subscription_expired`。

## MediaService



图片搜索前必须先把图片上传为 `media_asset_id`。图片内容不要 base64 放进 gateway。



图片上传流程：



```Plain Text
GetMediaUploadConfig -> PrepareMediaUpload -> 客户端 PUT 上传 -> CompleteMediaUpload -> 获得 uploaded 的 media_asset_id
```



`PHOTO` clue、反馈截图、个人中心反馈图片、报告页 Add Photo 都只传 `media_asset_id`。



### GetMediaUploadConfig



```JSON
{
  "service_name": "tool.people_insight.MediaService",
  "method_name": "GetMediaUploadConfig",
  "params": {}
}
```



客户端可按 `cache_expires_time` 缓存配置。



`data`：





|字段|类型|说明|
|---|---|---|
|`config_version`|string|配置版本|
|`config_cache_ttl_seconds`|int64|缓存秒数|
|`cache_expires_time`|int64|缓存过期时间|
|`allowed_content_types`|array|当前支持 `image/jpeg`、`image/png`、`image/webp`|
|`max_size_bytes`|int64|最大文件大小|
|`recommended_max_width`|int|建议宽度|
|`recommended_max_height`|int|建议高度|
|`recommended_jpeg_quality`|float|建议 JPEG 质量|
|`strip_exif`|bool|是否建议清理 EXIF|
|`face_detection_required`|bool|是否要求客户端本地检测人脸|
|`upload_url_ttl_seconds`|int64|上传 URL 有效秒数|
|`asset_ttl_seconds`|int64|media asset 有效秒数|
|`complete_retry`|object|complete 重试建议|

```JSON
            "types": ["country", "political"]
          }
        ],
        "source": "google_places"
      }
    }
  ],
  "additional_details": [
    {
      "type": "PROFESSION",
      "value": "Software Engineer"
    },
    {
      "type": "EMPLOYER",
      "value": "Google"
    }
  ]
}
```



P0 限制：



- `FULL_NAME` 必填，必须正好 1 条。

- `FULL_NAME.full_name` 必填。

- `LOCATION` 是独立 clue，不放在 `FULL_NAME` 下面，最多 1 条。

- `PHOTO` 可重复。客户端当前最多选 3 张图，可以提交 1 到 3 条 `PHOTO` clue；后端上限预留为 5。

- `SOCIAL_LINK` 可重复，后端上限 5。

- `clues` 总数上限 12。

- `match_strategy` 只支持 `UNION`。

- `SOCIAL_LINK` 必须传 `url`。

- `PHOTO` 必须传已完成上传的 `media_asset_id`。

- `PHOTO` 用于图片线索补齐、来源反查、疑似盗图判断、候选人物召回，不输出确定身份断言。

- `additional_details` 最多 20 条，`value` 最长 256 字符。

- `additional_details` 是搜索 hint，不是唯一主线索；主线索仍然放在 `clues`。

    

地址说明：



- `location_query.location` 是用户输入的原始地址文本，建议始终传。

- `formatted_address`、`place_id`、`geo_point`、`address_types`、`address_components` 是可选结构化地址信息。

- `address_types` 和 `address_components[].types` 使用 Google\-style 开放字符串，例如 `locality`、`country`、`administrative_area_level_1`。

- 后端不会把地址类型做成 enum，避免 Google 或其他 provider 后续新增类型时需要改协议。

    

三方召回说明：



- PDL `FULL_NAME` 链路由后端控制，客户端不需要感知 Identify / Person Search 的选择。

- 后端会先调用 PDL Identify；如果最佳 `match_score >= 60`，直接使用 Identify 候选。

- 如果 Identify 低置信或不唯一，后端会用 `full_name` 加可选 `LOCATION`、`EMPLOYER`、`SCHOOL` 线索调用 PDL Person Search 扩展候选召回。

- Person Search 候选仍统一映射到现有候选列表结构，不暴露 PDL 原始结构。

- 只有 `full_name` 的 Person Search 候选默认低置信；加公司等强线索后才可能进入 `MEDIUM`。客户端仍按候选列表顺序展示。

`params`：





|字段|类型|必填|说明|
|---|---|---|---|
|`client_request_id`|string|是|幂等 ID；同一个用户重复提交同一个值会返回同一条反馈|

|字段|类型|说明|
|---|---|---|
|`feedback_id`|string|反馈 ID|
|`status`|string|当前固定为 `submitted`|
|`create_time`|int64|提交时间|





反馈关联关系：



```Plain Text
task_id -> search_queries.raw_query / 结构化线索字段
服务端内部 report_id -> report_snapshots
feedback -> 用户选择的问题类型、文字说明、客户端上下文
```



当前后端已经记录：



- 用户提交的搜索线索：`search_queries.raw_query`，以及 `full_name`、`url`、`media_asset_id`、`location`、`clues`、`additional_details` 等结构化字段。

- 搜索结果快照：`report_snapshots`。

- 第三方原始响应引用：`provider_requests.response_ref`，原始响应不进 MySQL。

    

这样可以避免客户端重复传敏感信息，也能保证反馈关联的是当时那份搜索输入和报告结果。

## BillingService



P0 客户端订阅优先使用 `SubscriptionService`。`BillingService` 是底层订单能力，当前主要用于支付闭环、掉单恢复和测试。

## 客户端本地建议



- `device_id` 首次安装生成并持久化。

- `client_request_id` 对创建类接口必须稳定，重试使用同一个值。

- `trace_id` 可不传，gateway 会生成；如果客户端有自己的链路 ID，可以传入。

- 图片上传前建议裁切、压缩、清理 EXIF。

- 客户端不要保存 signed upload URL 长期使用，过期就重新 `PrepareMediaUpload`。

- `GetTask` 不要高频轮询，避免触发限流。

- 购买成功后即使 UI 已展示成功，也要保存待 verify 任务直到后端验单成功。

- `FULL_NAME` 当前是主流程必填；如果后续要支持无姓名的纯图片/社媒反查，建议新建搜索模式，不混进当前 people search 主流程。

    

## 待联调/缺失清单



- 真实 App Store sandbox 购买需要客户端提供 `transaction_id` / `original_transaction_id` 或相关 JWS/receipt 后才能闭环。

- Google Play 购买需要客户端提供 `purchase_token` 和 `package_name`。

- SearchAPI/SerpApi Google Lens 主召回 provider 仍需要配置 key 并联调。

- TinEye provider 需要配置 key 并联调真实图片结果质量。

- PDL 已接入 worker：`FULL_NAME` 默认 Identify first，低置信时自动 fallback 到 Person Search；Pipl 后续配置 key 后可切换或与 PDL 同时开启。

- 图片搜索、候选集和报告 `ui_sections` 的最终展示字段建议和客户端 UI 再确认一次。
