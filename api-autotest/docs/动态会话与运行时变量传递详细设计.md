# 动态会话与运行时变量传递详细设计

## 1. 目标

在保持现有 Gateway 单接口数据驱动结构的基础上，增加以下能力：

- 自动创建匿名会话，并在 access token 距离过期不足一天时刷新会话。
- 在一次 pytest 会话内保存 token、用户身份及接口响应提取值，不将动态值写回配置文件。
- 支持用例通过 `{{变量名}}` 引用前序接口提取的运行时变量。
- 支持 `PrepareMediaUpload` 返回的上传地址及上传请求头驱动二进制 PUT 上传。
- 通过显式流程定义执行存在前后依赖的接口，不依赖 pytest 用例收集顺序。

## 2. 配置与运行时数据分层

### 2.1 默认配置

`config/settings.yaml` 保存各环境共享且非敏感的固定配置，例如超时、平台、版本和地区。

### 2.2 环境配置

`config/env/{env}.yaml` 保存特定环境的固定差异，例如 Gateway 地址及固定 `device_id`。系统环境变量 `DEVICE_ID` 可以覆盖 YAML 值。

### 2.3 运行时上下文

一次 pytest 会话使用一个内存字典保存动态值，包括：

- 会话值：`access_token`、`expires_time`、`refresh_token`、`refresh_expires_time`、`user_id`。
- 上传值：`upload_url`、`upload_headers`、`media_asset_id`。
- 业务流程值：`task_id`、`candidate_id` 等。

运行时上下文不写入 YAML 或其他磁盘文件，测试结束后释放。

## 3. Gateway comm 聚合

每次请求前按以下优先级构造 `comm`：

1. `settings.yaml` 的公共 `comm`。
2. `config/env/{env}.yaml` 覆盖后的 `comm`。
3. 运行时上下文中的 `access_token`、`user_id`。
4. 本次请求动态生成的 `client_request_id`。

空字符串和 `None` 不序列化。`device_id` 使用环境配置中的固定值或 `DEVICE_ID` 环境变量覆盖值。

## 4. 会话生命周期

时间字段 `expires_time`、`refresh_expires_time` 均按 Unix 毫秒时间戳处理。

普通鉴权请求执行前检查会话：

1. 没有 `access_token`：调用 `CreateAnonymousSession`。
2. `expires_time - 当前时间 >= 86_400_000` 毫秒：继续使用当前 access token。
3. access token 距过期不足一天，且 refresh token 仍有效：调用 `RefreshSession`。
4. refresh token 已过期、刷新接口网络失败或刷新业务失败：重新调用 `CreateAnonymousSession`。

刷新与创建接口自身跳过会话前置检查，避免递归。成功响应覆盖运行时上下文中的全部会话字段。

## 5. 变量替换与响应提取

### 5.1 变量替换

请求 YAML 统一使用 `{{变量名}}`：

```yaml
params:
  task_id: "{{task_id}}"
```

框架递归处理字典、列表和字符串。完整字符串占位符保留变量原始类型；缺少变量时立即抛出包含变量名的配置错误，不把未解析占位符发送到服务端。

### 5.2 响应提取

`extract` 路径以 Gateway 目标子响应的 `data` 为根节点：

```yaml
extract:
  task_id: $.task_id
```

关键提取规则：

- `CreateAnonymousSession` 和 `RefreshSession`：提取五个会话字段。
- `PrepareMediaUpload`：提取 `upload_url`、`upload_headers`、`media_asset_id`。
- `CreateIntentTask`：提取 `task_id`。
- `ListTaskCandidates`：使用 `$.items[0].candidate_id` 提取首个候选 ID。该路径对应完整响应的 `responses.data.items[0].candidate_id` 业务数据位置。

路径不存在、数组为空或提取值为空时给出明确错误。

## 6. 二进制 PUT 上传

`PrepareMediaUpload` 通过 Gateway POST 调用。响应的 `upload_headers` 已包含 `Content-Length` 和 `Content-Type`，框架在 PUT 时直接使用该请求头对象，不再自行维护这两个运行时变量。

上传步骤：

1. 读取流程指定的本地媒体文件字节。
2. 根据实际文件大小构造 `PrepareMediaUpload.params.size_bytes`。
3. 调用 `PrepareMediaUpload` 并提取 `upload_url`、`upload_headers`、`media_asset_id`。
4. 使用提取的 URL、全部上传请求头和文件字节执行 PUT。
5. PUT 成功后调用 `CompleteMediaUpload`，传递 `media_asset_id`。

PUT 以 HTTP 2xx 为成功，错误响应包含状态码并保留脱敏后的诊断日志。

## 7. 流程执行

存在依赖的接口由流程 YAML 显式排序：

1. `CreateAnonymousSession`
2. `PrepareMediaUpload`
3. PUT 媒体文件
4. `CompleteMediaUpload`
5. `CreateIntentTask`
6. `GetTask`
7. `ListTaskCandidates`
8. `GetTaskCandidateDetail`

流程复用现有 case YAML，不复制接口请求和断言。独立接口仍由现有单接口测试执行；依赖运行时变量的用例由流程测试执行，避免依赖 pytest 文件顺序。

## 8. 修改范围

修改现有文件：

- `utils/custom/config_loader.py`
- `api/gateway_api.py`
- `utils/custom/http_client.py`
- `test_cases/conftest.py`
- `test_cases/test_single_api.py`
- 产生或使用运行时变量的相关 case YAML
- `test_cases/test_framework.py`（补充单元测试）

新增必要文件：

- `utils/custom/runtime_context.py`：变量替换、响应路径提取与会话状态保存。
- `data/flows/anonymous_session_media_search.yaml`：依赖流程定义。
- `test_cases/test_gateway_flow.py`：流程执行测试。

媒体文件由流程配置引用用户已有文件；框架不擅自创建业务测试图片。

## 9. 测试策略

- 单元测试覆盖毫秒时间戳及一天刷新边界。
- 覆盖无 token 创建会话、临期刷新、refresh token 过期重建、刷新失败重建。
- 覆盖嵌套字典/列表变量替换及缺失变量报错。
- 覆盖 `$.items[0].candidate_id` 提取与路径错误。
- 覆盖 PUT 使用 `upload_headers` 原值和二进制请求体。
- 运行现有框架测试，确认配置聚合、请求构造、断言和日志脱敏无回归。

## 10. 风险控制

- 会话创建和刷新响应只有通过 Gateway 与业务断言后才更新上下文。
- 自动恢复最多执行一次刷新或重建，不无限重试。
- token、refresh token、Authorization 等字段写日志前统一脱敏。
- 当前先保证单进程 pytest 会话正确；并行 worker 各自维护独立上下文。
