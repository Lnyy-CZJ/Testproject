Gateway 接口自动化 MVP｜设计框架

技术栈：Python + pytest + requests + PyYAML。目标是以最少代码跑通单一 Gateway 接口，并为后续流程编排、报告和 CI 预留位置。

1. 设计原则与 MVP 边界

配置驱动

接口参数和断言在 YAML；代码只负责加载、请求和校验。

分层独立

数据按全局、接口、场景、断言拆分；测试用例只做组合。

最小可运行

本期只支持单接口、单子请求 requests[0]，不引入 Flow、插件或 Allure。

2. 推荐目录

. ├── config/ │ ├── settings.yaml # 非敏感默认配置：超时、comm 默认字段 │ └── env/ │ ├── test.yaml # test 环境：gateway_base_url 等 │ └── dev.yaml # 后续环境可按此扩展 ├── data/ │ ├── global/ # 全局数据（当前仅预留） │ ├── api/ # 接口级数据：URL、方法、请求头 │ │ └── gateway_invoke.yaml │ ├── cases/ # 单接口用例数据 │ │ └── get_me.yaml │ ├── flows/ # 多接口流程数据（本期预留） │ ├── scenarios/ # 场景业务数据（本期预留） │ └── assertions/ # 可复用断言数据（本期预留） ├── api/ │ └── gateway_api.py # Gateway 请求体构造与调用入口 ├── utils/ │ ├── custom/ # 自定义工具 │ │ ├── config_loader.py # 合并默认配置与指定环境配置 │ │ ├── http_client.py # requests Session、超时、脱敏日志 │ │ ├── assertions.py # HTTP / Gateway / 子响应断言 │ │ └── logger.py # 日志初始化 │ └── third_party/ # 第三方集成（本期预留，不放实现） ├── test_cases/ │ ├── conftest.py # pytest fixture：加载 --env 配置 │ └── test_single_api.py # 加载 data/cases 下的单接口 YAML 并执行 ├── reports/ # pytest 输出与未来 Allure 报告目录 ├── runtest.py # 唯一执行入口 ├── requirements.txt ├── .env.example # AUTH_TOKEN / USER_ID / DEVICE_ID 示例 └── README.md

3. 执行主流程

runtest.py解析 --env、--module、--tag，拼装 pytest 参数
pytest / conftest.py加载 config/settings.yaml + config/env/{env}.yaml，并读取环境变量凭证
test_cases/test_single_api.py加载目标 case YAML，取得 request 与 assert 配置
api/gateway_api.py合成 comm + 单元素 requests，调用 POST /gateway/invoke
utils/custom/assertions.py按 YAML 校验 HTTP、顶层 Gateway、responses[req_0] 与业务字段
终端 + reports/输出 pytest 结果；失败时记录脱敏请求和完整响应

4. 数据职责与引用关系

层级保存内容是否本期实现
config执行行为、默认 comm、按环境变化的 Gateway 地址是
data/api固定 HTTP 方法、路径、请求头；不放真实地址和 token是
data/cases接口路由、params、用例名称、断言组合是
data/global / scenarios / assertions未来共享变量、业务流入参、可复用断言片段仅建目录
data/flows多接口依赖、变量提取、等待与编排仅建目录

5. 最小数据样例

config/env/test.yaml

gateway_base_url: http://gateway.spark-jam.top
timeout: 15
comm:
  platform: ios
  app_version: 1.0.3
  locale: zh-Hans-CN
  country: CN
  timezone: UTC+08:00

data/api/gateway_invoke.yaml

method: POST
path: /gateway/invoke
headers:
  Content-Type: application/json

data/cases/get_me.yaml

name: 获取当前用户
tags: [smoke, identity]
request:
  service_name: tool.identity.IdentityService
  method_name: GetMe
  params: {}
assert:
  http_status: 200
  gateway: { code: 0, message: ok }
  response: { id: req_0, success: true, code: 0, message: ok }
  data_fields: [user_id]

6. 代码职责

文件仅负责
runtest.py把用户参数转换为 pytest 参数；不写业务请求逻辑。
config_loader.py读取 YAML、按 --env 合并配置、读取敏感环境变量并校验必填项。
gateway_api.py生成 client_request_id，构造 comm + requests，调用 HTTP 客户端。
http_client.py统一 Session、超时和失败日志；日志掩码 auth_token。
assertions.py定位 id=req_0 子响应并做通用断言；不耦合具体业务字段。
test_single_api.py参数化发现 YAML、组装各层数据并调用 API/断言。

7. 统一执行入口

# 执行 test 环境全部用例
python runtest.py --env test

# 按模块（目录/文件关键字）筛选
python runtest.py --env test --module single_api

# 按 YAML tags 映射为 pytest marker 后筛选
python runtest.py --env test --tag smoke

# 透传额外 pytest 参数
python runtest.py --env test --tag smoke -- -x -vv

初期只需要实现 --env；--module 与 --tag 可先完成参数约定和基础筛选，不必引入复杂标签系统。环境变量由 shell 或本地未提交的 .env 注入：

export AUTH_TOKEN='***'
export USER_ID='user_xxx'
export DEVICE_ID='device_xxx'
python runtest.py --env test

8. MVP 验收与后续扩展

本期验收

  • 一条 GetMe YAML 可运行。
  • 更换 YAML 路由/参数无需改框架。
  • 失败信息能定位 HTTP、顶层或子响应断言。
  • 真实 token 不进入仓库或普通日志。

下期优先

  • 多单接口 YAML 与环境矩阵。
  • 公共断言和全局测试数据复用。
  • 变量提取与顺序 Flow。

保留扩展点

  • reports/ 接入 Allure。
  • utils/third_party/ 接入 Jenkins、飞书。
  • data/flows 承载复杂场景。
