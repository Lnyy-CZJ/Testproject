# 01 · 项目总览与架构

## 1. 项目定位

Truthy_Search（searchTool v1.3）是一套**人物检索系统评测工具集**，服务于对 "People Insight" 检索服务的版本对比与质量评估。它解决的核心问题是：

> 给定一批已知目标人物（带姓名、社交链接等线索），批量调用检索接口，把返回的候选人与**人工维护的基准资料（Baseline）**进行字段级对比，量化"找没找到、找得准不准、资料全不全、花了多少钱"，并沉淀为不可变的评测报告。

系统由两大部分组成：

1. **CLI 采集工具**（[search_tool.py](../../search_tool.py)）：命令行批量执行检索并落盘 JSONL 结果，可独立运行；
2. **本地分析平台**（[web_app.py](../../web_app.py) + [analysis_service.py](../../analysis_service.py) + [analysis_store.py](../../analysis_store.py)）：单用户 Flask Web，完成数据导入、字段处理、基准对比、复核与报告生成；
3. 另有 **Excel 导出链**（[result_to_excel.py](../../result_to_excel.py) → [result_to_excel_builder.mjs](../../result_to_excel_builder.mjs)）作为离线交付物生成器。

关键约束：**本地单用户系统**，默认只监听 `127.0.0.1:5002`，无登录与权限体系，不得暴露到公共网络。

### 分层职责

| 层 | 组件 | 职责 |
|---|---|---|
| 接入层 | `web_app.py` | HTTP 路由、表单/上传处理、后台任务提交、页面渲染 |

## 3. 核心业务流程（端到端）

Web 平台上一条完整评测的主线（对应 README 中"历史 Run 无成本修复、基准与报告"章节）：

```text
1. 创建 Evaluation（评测容器）
   └─ 可选绑定版本化参考线方案 ThresholdProfile（阈值快照）

2. 导入数据
   ├─ Query Dataset（JSONL / 固定 Queries Sheet Excel）→ 可执行数据集
   ├─ 历史结果（v1.2/v1.3 results.jsonl 或规范化 Excel）→ 历史 Run
   └─ Baseline 基准（JSONL / 基准数据 Sheet Excel）→ 版本化人物基准

3. 采集 Run（source_type=EXECUTION）
   └─ 后台单线程顺序执行 FULL_NAME / FULL_NAME_SOCIAL 两阶段 Query
      每条 Query：CreateIntentTask → GetTask 轮询 → （Admin Debug/Cost）
      → ListTaskCandidates → 逐候选人 GetTaskCandidateDetail
      落库：run_queries / candidates / raw_records / failures

4. 人物关联（可选，历史 Run 场景）
   └─ 将 run_queries 与 baseline_people 按 person_id 绑定（仅精确姓名建议 + 人工确认）

5. 字段处理 Process
   ├─ 选择版本化 FieldSchema（受限路径 + 白名单转换器，不可变）
   ├─ 从已保存 Raw 提取结构化字段 → processed_queries / processed_candidates
   ├─ 自动身份判定（RULE）：Social Link 冲突/匹配、照片相似度 ≥80
   │     → HIT / NOT_HIT / SUSPECTED
   └─ 人工覆写（MANUAL）：Query 级归类页 / 候选人复核页（乐观锁保护）

6. 指标计算 metrics-v4（按 Process 固化的 rule_version 严格分派，历史不重算）

7. 报告 report-model-v5 / v6-compare
   ├─ 不可变 ReportModel 快照（report_model.json）
   ├─ 静态 HTML（不依赖网络/JS，预渲染全部 Query 与候选人）
   └─ processed Excel（英文稳定 Sheet 名供平台自动化读取）

复核或重新处理发生后，旧报告标记 STALE（不覆盖、不重算）。
```

## 5. 关键设计原则

以下原则贯穿全部模块，是理解代码行为的前提：

### 5.1 不可变与版本化
- **FieldSchema**：每次发布生成新 `schema_version`，旧版本永不修改；
- **Process**：每次处理生成新 `process_id`，旧结果与 Raw 不覆盖；
- **报告**：快照生成时的指标/配置/基准/规则版本；复核或重处理后旧报告标记 `STALE`；
- **参考线方案**：不可变版本，调整必须"复制为新版本"；Evaluation 绑定时复制独立 `thresholds_json` 快照；
- **Raw**：`raw_records` 为 append-only。

### 5.2 严格版本分派，历史数据不被新口径污染
指标计算按 Process 固化的 `rule_version` 分派（v1→metrics-v1 … v5→metrics-v4），未知规则直接拒绝；报告模型同理（v2…v6-compare）。旧报告按历史版式打开，不重算。

### 5.3 脱敏优先
- `search_tool.sanitize_raw` 递归删除敏感键：`password / session_token / auth_token / authorization / cookie / set_cookie / headers / http_headers / device_id / user_id`；
- Raw 记录不含 `comm` 鉴权段与 HTTP Header；Admin Token 仅存内存；
- 页面不展示 `.env`、Token、Cookie、完整 Header、Device/User ID。

### 5.4 无成本重处理
字段规则变更、人物关联修正均只读取已保存的 Raw 创建新 Process，**不调用 CreateIntentTask 或任何检索接口**，不产生费用；仅当历史已保存 Admin Raw 时才能补齐成本字段。

### 5.5 失败隔离与降级
- 候选人 Detail 失败：写占位项 + 候选级失败记录，继续下一候选人；
- Query 级（Create/Get/List）失败：写失败文件，继续下一 Query；
- Admin 公共信息失败：只降级为状态字段（`NOT_CONFIGURED/AUTH_FAILED/FAILED`），不阻断主检索链路；
- 成本缺失保持 `null`，**绝不补 0**。

### 5.6 并发与恢复
同一时刻只允许一个执行 Run（`ActiveRunError` 拦截）；后台为单线程 `ThreadPoolExecutor`；应用重启时遗留 `RUNNING` Run 标记 `INTERRUPTED`，已完成 Query 与 Raw 保留，失败 Query 支持页面触发重跑。

### 5.7 防重复导入与防覆盖
导入以"文件角色 + 内容" SHA-256 去重（`DuplicateImportError`）；CLI 输出文件同日同输入已存在时按 `ALLOW_DUPLICATE_RUN` 决定拒绝或递增 `_run02` 后缀；已有文件永不覆盖。

### 5.8 受限的字段处理
字段配置只支持点路径、固定数组索引、数组通配（`profiles[*].url`）与 7 个白名单转换器；**不支持 eval、函数、条件过滤或用户脚本**。
