# 07 · 依赖关系与运行方式

## 1. 第三方依赖

### 1.1 Python（[requirements.txt](../../requirements.txt)，建议 Python ≥ 3.10，Docker 镜像为 3.12）

| 包 | 版本 | 用途 |
|---|---|---|
| `requests` | >=2.31,<3 | 检索接口与 Admin 接口 HTTP 调用（search_tool） |
| `python-dotenv` | >=1.0,<2 | `.env` / 平台 Secret 文件读取（`dotenv_values`、`load_dotenv`） |
| `Flask` | >=3.0,<4 | 本地 Web 应用（web_app） |
| `openpyxl` | >=3.1,<4 | Excel 导入解析（analysis_service）；Web 端不写 Excel |

标准库承担了其余全部工作：`sqlite3`（存储）、`threading/concurrent.futures`（后台执行）、`subprocess`（Excel 导出链）、`hashlib`（SHA-256 去重）等。

### 1.2 Node（可选，仅 processed Excel 导出需要）

| 依赖 | 说明 |
|---|---|
| Node.js 可执行文件 | 定位顺序：`SEARCHTOOL_NODE` > 内置 Codex runtime > 系统 `node` |
| `@oai/artifact-tool` | 生成带格式 xlsx 的 spreadsheet runtime；缺失时 Web 报告/静态 HTML 仍成功，仅 Excel 降级 |

Docker 服务默认 `SEARCH_REPORT_EXCEL_ENABLED=false`（容器内无 artifact-tool）。

## 2. 模块间依赖关系

```text
web_app.py ──────────────► analysis_service.py ──► analysis_store.py ──► SQLite
    │   (路由/后台执行器)         │  (业务编排)            (连接/事务/DDL)
    │                            │
    │                            ├──► search_tool.py（process_one / FlowError /
    │                            │     extract_admin_task_fields / sanitize_raw）
    │                            │         │
    │                            │         └──► 外部检索/Admin 接口（requests）
    │                            │
    │                            └──► subprocess: result_to_excel.py processed
    │                                        └──► node result_to_excel_builder.mjs
    │
    └──► search_tool.Config/SearchClient（RunCoordinator 延迟构造）

CLI 独立链路：
search_tool.py（直接运行）──► output/*_results.jsonl / *_failures.jsonl
                                      │
result_to_excel.py single/compare ◄───┘（读取 JSONL 生成对比工作簿）
```

依赖方向要点：

- `analysis_store` 是纯存储层，不依赖任何业务模块；
- `analysis_service` 只使用 store 的 `fetch_one / fetch_all / transaction` 三类 API；
- `search_tool` 不依赖 analysis_*，可完全独立运行（也被 Web 复用）；
- `web_app` 不直接写业务 SQL，全部走 service。

## 3. 安装与配置

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env      # 填写真实值
```

### 3.1 环境变量总表

**主链路（CLI 必填）**：`SEARCH_API_URL`、`AUTH_TOKEN`、`DEVICE_ID`、`USER_ID`。

| 分类 | 变量 | 默认值 | 说明 |
|---|---|---|---|
| 采集 | `SEARCH_HTTP_HEADERS_JSON` | — | 固定请求头，必须为 JSON 对象 |
| 采集 | `POLL_INTERVAL_SECONDS` / `MAX_POLL_COUNT` / `HTTP_TIMEOUT_SECONDS` | 5 / 60 / 30 | GetTask 轮询间隔、次数、HTTP 超时 |
| 采集 | `PLATFORM / APP_VERSION / LOCALE / TIMEZONE` | ios / 1.0.0 / zh-Hans-CN / UTC+08:00 | comm 段报文 |
| IO | `SEARCH_INPUT_FILE` / `SEARCH_OUTPUT_DIR` / `ALLOW_DUPLICATE_RUN` | input/tasks.jsonl / output / false | CLI 输入输出与同日重复策略 |
| Web | `SEARCH_WEB_HOST` / `SEARCH_WEB_PORT` | 127.0.0.1 / 5002 | 监听地址 |
| Web | `SEARCH_WEB_BASE_PATH` / `PLATFORM_HOME_URL` | 空 / 空 | 平台模式前缀（测试平台固定 `/truthy-search`） |
| Web | `SEARCH_WEB_MAX_UPLOAD_BYTES` / `SEARCH_WEB_SECRET_KEY` | 50MB / 本地默认 | 上传上限 / session 签名 |
| 数据 | `SEARCH_DATA_DIR` / `SEARCH_DB_FILE` | data / data/searchtool_v1_3.db | 数据目录与 SQLite 文件 |
| 数据 | `SEARCH_IMPORT_DIR` / `SEARCH_RAW_DIR` / `SEARCH_REPORT_DIR` | data/imports / data/raw / output/reports | 归档、规范化结果、报告产物 |
| 展示 | `SEARCH_DISPLAY_TIMEZONE` | Asia/Shanghai | 仅控制可见时间；存储仍为 UTC |
| 报告 | `SEARCH_REPORT_EXCEL_ENABLED` | true（Docker 内 false） | Web 自动 Excel 导出开关 |
| Admin | `SEARCH_ADMIN_ENABLED` | false | 公共信息采集开关 |
| Admin | `SEARCH_ADMIN_LOGIN_API_URL` / `SEARCH_ADMIN_API_URL` | — | Login 与 Debug/Cost 网关 |
| Admin | `SEARCH_ADMIN_USERNAME` / `SEARCH_ADMIN_PASSWORD` | — | 必须经平台只读 Secret 注入 |
| Admin | `SEARCH_ADMIN_REASON` / `SEARCH_ADMIN_DEBUG_SERVICE` / `SEARCH_ADMIN_COST_LIMIT` | 默认文案 / worker / 100 | 采集参数 |
| 日志 | `SEARCH_QUERY_LOG_ENABLED` / `SEARCH_QUERY_LOG_DIR` | true / log | 人物级链路日志 |
| Excel | `EXCEL_*`（RESULTS/FAILURES/OUTPUT/RUN_LABEL/SYSTEM_VERSION/EVALUATION_ID/METADATA，及 BASELINE_/CANDIDATE_ 变体） | — | result_to_excel 的 .env 模式 |
| 调试 | `SEARCHTOOL_NODE` | — | 指定捆绑 Node 可执行文件 |

**配置优先级**：CLI 参数 > 进程环境变量 > `.env` 文件 > 代码默认值。接口凭证只在真正启动执行 Run 或 Query 重跑时读取，每次重新解析 Secret 文件、不缓存到进程环境。

## 4. 运行方式

### 4.1 CLI 采集（search_tool）

```bash
# 准备输入（每行一条任务：input_id + 非空 clues 必填，match_strategy 默认 UNION）
cp input/tasks.example.jsonl input/tasks_v01.jsonl

# 运行
python search_tool.py
python search_tool.py --input input/tasks_v02.jsonl --output output --env-file .env
```

输出按日期与输入文件名生成（`output/20260722_tasks_v01_results.jsonl` 等）；同日重复运行在 `ALLOW_DUPLICATE_RUN=true` 时递增 `_run02`。退出码：0 全部成功，1 无法启动，2 存在失败。

### 4.2 本地 Web

```bash
python3 web_app.py --env-file .env
# 访问 http://127.0.0.1:5002
```

未配置真实接口凭证也可先启动浏览/导入历史数据。

### 4.3 Docker Compose

```bash
docker compose up -d --build
docker compose logs -f searchtool
docker compose down          # 不要加 -v（会清理业务数据）
```

- 端口仅发布到宿主机 `127.0.0.1:5002`；`.env` 只读挂载到 `/run/secrets/searchtool.env`；
- 数据卷：`./data`（库+归档+raw）、`./output`（结果+报告）、`./input`（只读）、`./log`（人物日志持久化）；
- 健康检查：`/health`（10s 间隔）。

**独立模式 vs 测试平台模式**：独立模式根路径运行（`SEARCH_WEB_BASE_PATH=` 空）；平台模式固定 `SEARCH_WEB_BASE_PATH=/truthy-search`、`PLATFORM_HOME_URL=/`。两模式挂载同一 SQLite，**必须互斥运行**；切换前确认 `runs` 表无 RUNNING 记录。

### 4.4 测试

```bash
python3 -m unittest discover -s tests -v                    # 全量
python3 -m unittest discover -s tests -p 'test_analysis*.py' -k stage7 -v   # 阶段7闭环
python3 -m unittest discover -s tests -p 'test_analysis_store.py' -k backup -v
```

测试使用 `tests/fixtures/` 脱敏夹具，不调用真实接口；容量测试生成 400 条合成 Query 只写临时目录。

### 4.5 Excel 导出

见 [06 章](./06_模块详解_result_to_excel.md#4-使用示例)。Web 报告流程会自动以 processed 模式调用；CLI 的 single/compare 模式直接读取 search_tool 产出的 JSONL。

## 5. 典型工作流（Web 内）

```text
1. 顶部"字段配置"确认/发布 FieldSchema；"参考线"创建阈值方案
2. 导入数据：Query Dataset（可执行）/ 历史结果 / 基准版本
3. 创建 Evaluation（绑定数据集与方案）→ 启动采集 Run（后台串行）
   或：对历史 Run 进入"管理人物关联"绑定 Baseline person_id
4. Run 页选择字段配置（+基准版本）启动处理/重处理（重处理零接口费用）
5. 身份归类与复核：规则自动判定为主，仅规则无法判定时人工覆写
6. 查看 metrics-v4 指标 → 生成报告快照（Web + 静态 HTML + processed Excel）
7. 报告中心按 Evaluation/版本/类型/状态筛选；STALE 报告需重新生成
```

## 6. 备份与恢复

**备份范围**必须同时包含：SQLite 库、`data/imports` + `data/raw`、`output/reports`、`log/`（.env 配置说明单独保管，含凭证文件不得入库）。推荐停 Web/CLI 后用 SQLite backup API 创建一致性快照（README 提供完整脚本，`tests/test_analysis_store.py` 的备份测试演示同法）。

**恢复**：复制到新目录，创建独立 `.env.restore` 指向恢复目录的 `SEARCH_DATA_DIR/SEARCH_DB_FILE/SEARCH_IMPORT_DIR/SEARCH_RAW_DIR/SEARCH_REPORT_DIR`，`python3 web_app.py --env-file .env.restore` 验证后再切换为正式目录。

**数据迁移**：同版本环境用完整备份恢复；v1.2/旧数据重新走 Web 导入（生成 `LEGACY_PARTIAL_RAW` 标记）；字段规则变更发布新 FieldSchema 后重处理旧 Raw；`schema_info.schema_version` ≠ 4 时拒绝启动，禁止手改版本号。

## 7. 常见排障（摘自 README）

| 现象 | 处理 |
|---|---|
| 5002 端口被占用 | `lsof -nP -iTCP:5002 -sTCP:LISTEN` 找占用进程，或改 `SEARCH_WEB_PORT` |
| `.env` 已填但提示缺配置 | 确认命令带 `--env-file`；变量名须为 `SEARCH_API_URL/AUTH_TOKEN/DEVICE_ID/USER_ID` |
| `SEARCH_HTTP_HEADERS_JSON` 报错 | 必须是完整 JSON 对象，双引号、无尾逗号 |
| Dataset 下拉为空 | 需先导入"Query Dataset"；历史结果导入只建 Run 不建 Dataset |
| 报告 STALE | 复核/重处理发生在快照之后；需重新生成报告 |
| Excel 未生成 | 检查 `SEARCH_REPORT_EXCEL_ENABLED=true` 与 Node/artifact-tool 环境；Web 报告与静态 HTML 不受影响 |
| 公共信息 NOT_CONFIGURED / AUTH_FAILED | 检查 Admin 开关、两个 URL、Secret 注入的账号密码；不影响原检索结果 |
| 相同文件无法再次导入 | SHA-256 防覆盖策略；数据有变化应生成内容不同的新文件作为新 Run |

## 8. 已知限制

- 本地单用户系统：无登录/角色/权限，禁止暴露公共网络；
- 同一时刻只执行一个采集 Run；进程重启不自动续跑当前 Query（标记 INTERRUPTED，可手动重跑）；
- 仅支持 `FULL_NAME` / `FULL_NAME_SOCIAL` 两种 Query 阶段；照片输入及 PUT 流程未实现；
- List Candidates 分页字段仅预留，当前一次响应取全部候选人（page_size=100）；
- 成本/PDL/耗时字段依赖 Admin Raw；历史 Run 仅在已保存 Admin Raw 时可无成本补齐；
- 历史 Excel 缺完整 Raw 时标记 `LEGACY_PARTIAL_RAW`，不伪造数据；
- 人物日志不提供在线查看/下载/轮转；静态 HTML 含人物级案例，应作为受控数据保管。
