# searchTool 数据库说明

## 1. 数据库连接信息

| 项目 | 说明 |
|---|---|
| 数据库类型 | SQLite 3（本地文件数据库） |
| 数据库文件 | `data/searchtool_v1_3.db`（由 `.env` 的 `SEARCH_DB_FILE` 配置） |
| 当前 Schema 版本 | v3（`schema_info.schema_version = 3`） |
| 数据库账号 | 不适用 |
| 数据库密码 | 不适用 |
| 连接方式 | Python 标准库 `sqlite3` 直接打开数据库文件 |
| 应用连接设置 | 开启 `foreign_keys`、WAL 日志模式和 5 秒 busy timeout |

SQLite 是单文件嵌入式数据库，不运行独立数据库服务，因此没有 PostgreSQL/MySQL 形式的主机、端口、账号或密码。数据库文件本身及其所在目录的操作系统文件权限决定访问权限。

示例：

```bash
sqlite3 data/searchtool_v1_3.db
```

> 直接使用 SQLite 命令行时，如需校验外键，请先执行 `PRAGMA foreign_keys = ON;`；应用程序连接会自动开启该设置。

## 2. 数据关系概览

```text
evaluations ─┬─ runs ─┬─ run_queries ─ candidates ─ raw_records
             │        ├─ failures
             │        └─ process_runs ─┬─ processed_candidates ─ reviews
             │                          └─ processed_queries
             └─ reports

datasets ────┬─ dataset_queries
             └─ runs

threshold_profiles ─ evaluations（逻辑引用）
field_schemas ─────── process_runs
baseline_sets ───────┬─ baseline_people
                     └─ process_runs
```

通用约定：

- 所有 `*_id`、`*_pk`、`*_version` 字段均为业务标识，通常采用文本 UUID 或版本号。
- 所有 `*_json` 字段使用 SQLite `TEXT` 存储 JSON 原文，避免在 MVP 阶段过度拆表。
- 所有 `*_at` 字段使用 UTC ISO 8601 时间文本。
- `status`、`stage`、`scope` 等枚举的具体取值由业务流程控制；数据库主要负责保存，不在 Schema 层限制枚举值。

## 5. 运维注意事项

- SQLite 在 WAL 模式下运行时，数据库文件旁可能出现 `-wal` 和 `-shm` 文件；它们是运行时日志文件，不应在数据库仍被写入时单独复制。
- 需要备份时，使用 SQLite backup API 或先停止 Web 与 CLI 任务后再处理文件，避免得到不一致快照。
- 数据库含有 Query、候选人和原始响应等业务数据；虽然没有数据库密码，仍应限制 `data/` 目录的文件访问权限。
