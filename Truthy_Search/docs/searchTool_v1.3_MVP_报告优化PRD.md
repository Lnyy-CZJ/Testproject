# searchTool v1.3 MVP 报告优化 PRD

> **指标口径补充（2026-07-30）**：报告中原“检索成功率”更名为“目标人物命中率”，分母为全部成功执行的 Query、每个 Query 最多记一次命中。首屏新增“候选人返回率”（有返回候选人的 Query / 成功执行 Query）和“有候选人条件下命中率”（命中目标人物的 Query / 有返回候选人的 Query）。原“命中完整度”“命中准确度”分别更名为“命中资料完整度”“命中信息准确度”；字段明细新增“基准字段覆盖度”，用于区分候选人实际返回资料与其相对基准字段的覆盖情况。

> 文档版本：v1.1  
> 状态：需求与开发关键约束已确认，待开发实现  
> 适用范围：searchTool v1.3 MVP Web 报告与静态 HTML 报告  
> 需求依据：《检索功能常态化测试方案与方法V1.0》、现有 `report-model-v3/v4` 报告能力  
> 核心原则：先展示结论，再解释变化，最后提供 Query、候选人、字段和证据下钻。

## 1. 背景

当前平台已经能够生成单次报告和版本对比报告，并展示检索成功率、命中完整度、命中准确率、非命中完整度、执行状态、字段质量、版本配对、成本与置信度等数据。

但现有报告仍以数据处理状态和技术模型信息为主要组织方式，存在以下问题：

1. 首屏被 `report_id`、ReportModel、指标版本、字段配置版本、`READY` 等技术信息占用，核心指标不突出；
2. 未就绪原因和风险说明位于执行摘要之前，用户无法快速判断本次检索表现；
3. 未选择参考线时仍展示“参考线与建议”“已配置 0 项”“NOT_CONFIGURED”等无效内容；
4. 报告只有聚合指标和部分案例，缺少 `Query → 全部候选人 → 模块 → 字段 → 证据` 的完整下钻链路；
5. 命中候选人与非命中候选人的指标职责没有在页面中直观区分；
6. 大量内部状态码、原始小数和空表增加阅读成本；
7. 主报告、问题诊断和技术审计信息混在同一层级，无法同时满足汇报和问题定位需求。

因此，本次优化重点不是单独调整颜色或字体，而是重新组织报告的信息优先级、条件展示规则和候选人明细浏览方式。

## 2. 需求目标

### 2.1 业务目标

1. 用户打开报告后，可以在首屏快速判断当前检索能力；
2. 核心指标与《检索功能常态化测试方案与方法V1.0》的口径保持一致；
3. 每个 Query 都能查看本次返回的全部候选人，而不是只查看命中人物或典型案例；
4. 每个候选人能够继续下钻到模块、字段、基准值、候选值、比较结果和证据；
5. 单次报告与版本对比报告根据实际数据展示不同内容；
6. 未选择、未配置或没有有效数据的可选模块不占用报告页面；
7. 将技术信息和问题诊断移至报告底部，保留审计能力但不干扰核心结论。

### 2.2 成功标准

1. 首屏展示检索成功率、命中准确率、命中完整度和非命中完整度；
2. 所有百分比同时展示分子、分母和百分比；
3. 每个 Query 展示实际返回的全部候选人，候选人数与入库记录一致；
4. 命中候选人展示命中准确度和命中完整度，非命中/疑似候选人展示非命中完整度；
5. 未配置参考线时，页面不出现参考线元数据、参考线章节、建议或 `NOT_CONFIGURED`；
6. 单次报告不展示无意义的版本变化和配对表；
7. 风险和数据质量问题默认位于报告底部；只有阻断报告有效性的严重问题在顶部展示简短警告；
8. 汇总指标能够下钻到 `person_id/query_id`、候选人、字段和证据；
9. Web 报告和静态 HTML 报告使用相同数据口径和章节顺序。

### 2.3 非目标

1. 本期不修改检索接口和 Candidate Detail 采集流程；
2. 本期不增加新的外部数据源；
3. 本期不新增复杂图表引擎或 BI 系统；
4. 本期不实现 LLM 自动撰写评测结论；
5. 本期不修改身份命中规则、字段比较规则和现有指标计算公式；
6. 本期不解决尚未提供正式接口路径的成本、PDL、Evidence 等字段采集问题；
7. 本期不实现多人协作、权限审批或报告在线编辑。

## 3. 用户与使用场景

### 3.1 测试负责人

1. 快速判断一次评测是否达到预期；
2. 查看不同 Query 条件和不同版本之间的变化；
3. 定位未命中、准确率低或资料不完整的人物；
4. 下钻检查候选人的身份判定、字段比较和原始证据；
5. 导出报告用于评审或阶段汇报。

### 3.2 产品与开发人员

1. 查看检索能力的总体表现；
2. 查看改善、退化和持续未命中的人物；
3. 定位 Social 冲突、照片不匹配、字段缺失或处理错误；
4. 从报告进入候选人详情和原始响应进行排查。

### 3.3 汇报查看者

1. 只查看核心结论、版本变化和成本情况；
2. 不需要理解 ReportModel、FieldSchema 等内部技术信息；
3. 在需要时查看典型改善和退化案例。

## 4. 报告信息架构

报告采用“主报告 + Query 候选人明细 + 数据质量附录”三层结构。

### 4.1 推荐页面顺序

1. 报告标题与操作区；
2. 执行摘要；
3. 按检索条件的核心指标；
4. 版本变化与人物配对，仅对比报告展示；
5. Query 与全部候选人工作台；
6. 模块与字段质量；
7. 成本、检索时长与 PDL；
8. 参考线与建议，仅实际配置后展示；
9. 数据质量、风险和技术信息附录。

### 4.2 信息优先级

| 层级 | 内容 | 展示原则 |
|---|---|---|
| P0 | 核心结论、检索成功率、命中准确率、命中完整度、非命中完整度 | 首屏直接展示 |
| P1 | Query 条件差异、版本变化、人物配对、全部候选人 | 主报告展示 |
| P2 | 模块返回、字段质量、成本、耗时、PDL、置信度 | 主报告下半部分展示 |
| P3 | 数据处理错误、字段未接入、规则版本、ReportModel、Raw 入口 | 页面底部或折叠展示 |

## 5. 报告标题与操作区

### 5.1 默认展示

1. 评测名称；
2. 报告类型：单次报告或版本对比报告；
3. 当前版本；
4. 基准版本，仅对比报告展示；
5. 实际执行的 Query 条件；
6. 报告生成时间；
7. 导出静态 HTML；
8. 导出 Excel，功能可用时展示；
9. 报告信息入口。

### 5.2 报告信息折叠区

以下技术信息移入“报告信息”，不在首屏平铺：

- report_id；
- evaluation_id；
- process_id；
- ReportModel 版本；
- metrics 版本；
- processing 版本；
- FieldSchema 版本；
- 数据来源；
- 评估阶段；
- 报告生成状态。

### 5.3 状态显示规则

1. 正常状态不显示 `READY`；
2. `REVIEWED` 转换为“已确认”；
3. `NOT_CONNECTED` 转换为“字段暂未接入”；
4. `NOT_CONFIGURED` 不直接展示；对应可选模块应隐藏；
5. 只有异常、退化、冲突和阻断状态使用醒目颜色。

## 6. 执行摘要

### 6.1 第一排核心指标

首屏固定展示以下四项：

| 指标 | 业务含义 | 展示要求 |
|---|---|---|
| 检索成功率 | 命中基准人物的 Query 占正式 Query 的比例 | 百分比 + 成功 Query 数/正式 Query 数 |
| 命中准确率 | 主命中候选人与基准人物启用字段的准确程度 | 百分比 + 正确分/有效比较分母 |
| 命中完整度 | 主命中候选人已返回资料的完整程度 | 百分比 + 已返回字段数/启用字段数 |
| 非命中完整度 | 非命中及疑似候选人自身的资料完整程度 | 百分比 + 已返回字段数/可计算字段数 |

### 6.2 第二排辅助指标

1. Query 总数；
2. 有候选人 Query 数；
3. 无候选人 Query 数；
4. 执行失败 Query 数；
5. 返回候选人总数；
6. 有主要 HIT 的 Query 数；
7. 已确认无 HIT 的 Query 数；
8. 待身份归类 Query 数；
9. Candidate Detail 成功/失败数。

### 6.3 一句话结论

系统根据已有确定性指标生成结构化摘要，不使用 LLM：

```text
本次共执行 10 个 Query，全部返回候选人，其中 8 个命中基准人物；
检索成功率为 80.00%，命中准确率为 49.86%，命中完整度为 27.27%。
```

对比报告增加变化描述：

```text
相较基准版本，检索成功率提升 5.00 个百分点，命中准确率下降 2.30 个百分点。
```

如果某项指标不可用，该项不参与结论，不将缺失值描述成 0。

## 7. 按 Query 条件展示核心指标

### 7.1 分组规则

按实际存在的 `query_stage` 展示，例如：

- FULL_NAME；
- FULL_NAME_SOCIAL。

首版未实现或本次未执行的 Query 条件不展示空表。

### 7.2 每个条件展示内容

1. Query 数；
2. 有结果率/无结果率；
3. 检索成功率；
4. 命中完整度；
5. 命中准确率；
6. 非命中完整度；
7. 平均候选人数；
8. 执行失败数；
9. 平均成本、平均耗时和 PDL 调用率，仅字段已接入时展示。

### 7.3 格式规则

1. 百分比保留两位小数；
2. 同时展示分子和分母；
3. 变化使用“百分点”，不使用相对增长率代替；
4. 原始 `0.3863636` 必须格式化为 `38.64%`；
5. 无数据展示 `—` 或“不适用”，不得展示成 `0%`；
6. 章节标题应表达结论，不只写指标名称。

## 8. 版本对比与人物配对

### 8.1 展示条件

仅当报告类型为版本对比，并存在有效基准 Process 时展示。

单次报告不显示：

- 持续命中；
- 新增命中；
- 退化未命中；
- 持续未命中；
- 优化前后变化；
- 空的版本配对表。

### 8.2 汇总指标

按 Query 条件展示：

1. 持续命中；
2. 新增命中；
3. 退化未命中；
4. 持续未命中；
5. 检索成功率变化；
6. 命中准确率变化；
7. 命中完整度变化；
8. 非命中完整度变化；
9. 成本、耗时和 PDL 变化，仅字段可用时展示。

### 8.3 重点案例

展示：

1. 改善最明显的 3 至 5 个 Query；
2. 全部退化未命中 Query；
3. 持续命中但准确率明显下降的 Query；
4. 持续未命中的典型 Query。

每个案例必须能进入对应 Query 的全部候选人明细。

## 9. Query 与全部候选人工作台

### 9.1 核心要求

1. 报告必须包含本次正式 Query 的完整列表；
2. 每个 Query 必须展示接口实际返回并成功入库的全部候选人；
3. 候选人列表不得只展示前 5 名、主命中人物或异常案例；
4. Candidate Detail 失败的候选人仍需显示，并标记详情获取失败；
5. Query 候选人数必须与该 Query 的 Candidate 入库数量一致。

### 9.2 Query 卡片

每个 Query 使用可展开卡片，默认展示：

- query_id/input_id；
- person_id；
- 查询人物名称；
- query_stage；
- 执行状态；
- 有/无候选人；
- 候选人数量；
- 是否命中基准人物；
- 主命中候选人；
- 查询成本、耗时和 PDL，仅字段已接入时展示。

建议示例：

```text
case-001 · Stephanie McMahon · FULL_NAME
有结果 · 返回 5 人 · 命中 1 人 · 检索成功
```

### 9.3 候选人列表

展开 Query 后展示：

| 字段 | 说明 |
|---|---|
| 排名 | Candidate Rank |
| 候选人 | 显示姓名 + candidate_id |
| 身份结论 | HIT、NON_HIT、SUSPECTED、UNCLASSIFIED |
| Rank Score | ListTaskCandidates 返回的 rank_score |
| Candidate Confidence | Summary Confidence Level |
| 命中完整度 | 仅 HIT 展示 |
| 命中准确率 | 仅 HIT 展示 |
| 非命中完整度 | NON_HIT、SUSPECTED 展示 |
| 身份依据 | Social 一致、Social 冲突、照片相似度等 |
| 详情状态 | Candidate Detail 成功或失败 |
| 操作 | 展开字段、查看候选人详情、查看 Raw |

### 9.4 指标显示规则

| 候选人状态 | 命中完整度 | 命中准确率 | 非命中完整度 |
|---|---:|---:|---:|
| HIT | 展示 | 展示 | 不适用 |
| NON_HIT | 不适用 | 不适用 | 展示 |
| SUSPECTED | 不适用 | 不适用 | 展示 |
| UNCLASSIFIED | 不适用 | 不适用 | 根据现有指标规则决定；无正式结果时显示待处理 |
| Candidate Detail 失败 | 不适用 | 不适用 | 不适用 |

不适用必须显示为 `—` 或“不适用”，不得显示为 `0%`。

### 9.5 Query 筛选

首版支持：

1. 按 query_stage 筛选；
2. 按检索成功/未成功筛选；
3. 只看执行失败；
4. 只看无候选人；
5. 只看疑似候选人；
6. 只看待身份归类；
7. 只看存在 Social 冲突；
8. 按人物名称、person_id、query_id、candidate_id 搜索。

### 9.6 列表加载方式

1. Web 报告不使用服务端分页，也不要求用户手动切换页码；
2. ReportModel 快照保存本次报告的全部 Query 和候选人；
3. 页面首次打开时优先渲染执行摘要、核心指标和首段 Query；
4. 其余 Query 在用户向下浏览时由前端分段加载；
5. 前端分段加载只影响渲染性能，不改变候选人总数、排序、筛选结果和指标口径；
6. 搜索或筛选必须作用于报告快照中的全部 Query 和候选人，不能只搜索当前已渲染的部分；
7. 页面需要显示“已展示数量 / 总数量”，并提供加载状态；
8. 分段加载失败时允许重新加载当前分段，不得要求重新生成报告。

## 10. 候选人下钻

### 10.1 一级下钻：模块摘要

候选人展开后按以下模块展示：

- Insights；
- Photos；
- Profile；
- Social；
- Summary。

每个模块显示：

1. 模块状态；
2. 模块是否有真实数据；
3. 模块完整度；
4. 启用字段数；
5. 有值字段数；
6. 正确、错误、不适用字段数；
7. 展开字段明细入口。

### 10.2 二级下钻：字段比较

对启用基准对比的字段展示：

| 字段 | 基准人物值 | 检索候选值 | 比较结果 | 相似度/得分 | 说明 |
|---|---|---|---|---:|---|

要求：

1. 缺失值与处理错误必须区分；
2. 未启用基准对比的字段可以展示，但不显示准确度评分；
3. 长文本、列表、URL 和 JSON 使用适合的数据格式展示；
4. 数组和对象不得压缩成不可读的单行文本；
5. 可从字段明细进入完整候选人详情和 Raw JSON。

### 10.3 三级下钻：证据与 Raw

Evidence 的展示范围以生成该报告时冻结的字段配置为准。只有已经在字段配置中登记、启用且从当前 Process 数据中成功提取的 Evidence 字段才进入报告快照，不在报告代码中维护另一份固定 Evidence 清单。

在字段配置和实际数据均可用的前提下展示：

- Social 匹配链接和冲突链接；
- Photos 匹配照片、相似度和来源；
- 各模块 Evidence；
- candidate_evidence_raw；
- Candidate Detail 原始响应。

规则如下：

1. 字段配置关闭的 Evidence 不展示、不计为缺失，也不产生错误；
2. 字段配置已启用但接口未返回的 Evidence 按既有缺失策略处理；
3. 字段配置已启用但提取失败的 Evidence 记录为真实处理错误；
4. 报告仅消费字段配置快照中的 Evidence 结果，不重新从 Raw 中硬编码提取；
5. 未接入 Evidence 时，只在数据质量附录说明，不在每个候选人位置重复显示大段错误。

## 11. 模块与字段质量

### 11.1 模块级

展示五个业务模块：

- 有数据 Candidate 数；
- 空数据 Candidate 数；
- unknown Candidate 数；
- 真实有数据率；
- 模块完整度；
- 与基准人物比较的准确度，仅存在有效比较时展示。

### 11.2 字段级

字段明细放入可展开区域或附录，不在首屏平铺全部字段。

至少支持：

1. 字段返回率；
2. 字段完整度；
3. 字段准确度；
4. 有值、空值、错误、不适用数量；
5. 从字段统计下钻到对应 Query 和候选人。

### 11.3 Social 专项

在数据可用时展示：

- Social 平台分布；
- 匹配 Link 数；
- 冲突 Link 数；
- 无可比较 Link 数；
- 同平台冲突候选人；
- Social 判定依据明细。

### 11.4 Photos 专项

在数据可用时展示：

- 有照片候选人数；
- 无照片候选人数；
- 照片相似度分布；
- 相似度大于等于 80% 的候选人数；
- 匹配照片数量；
- 照片来源。

没有基准照片时必须明确显示“不具备照片比较条件”，不得按照片缺失判定错误。

## 12. 成本、检索时长与 PDL

### 12.1 展示条件

某项正式字段至少存在一个有效值时，才展示对应指标。

如果所有相关字段均未接入：

1. 主报告不展示空的成本表；
2. 页面底部的数据质量附录显示“成本与 PDL 字段暂未接入”；
3. 缺失值不得按 0 参与统计。

### 12.2 指标

按 Query 条件和版本展示：

- LLM 总成本；
- 第三方调用总成本；
- 总成本；
- 平均每次 Query 成本；
- 每次成功命中的平均成本；
- 平均检索时长；
- 最长检索时长；
- PDL 调用次数与调用率。

## 13. 参考线与建议

### 13.1 展示条件

同时满足以下条件时才展示：

1. 报告关联了有效参考线方案；
2. 参考线方案至少配置一个指标；
3. 至少有一个参考线指标具备可判断的实际值。

### 13.2 未配置时的行为

未选择或未有效配置参考线时：

1. 不显示“参考线方案：未选择”；
2. 不显示“参考线与建议”章节；
3. 不显示“已配置 0 项”；
4. 不显示 `NOT_CONFIGURED`；
5. 不生成上线建议或“暂不能判断”占位文案。

### 13.3 已配置时的内容

- 参考线名称；
- 指标；
- 方向；
- 目标值；
- 实际值；
- 是否达到；
- 判断依据；
- 结构化建议。

未选择建议配置时，仅展示参考线判断，不生成建议段落。

## 14. 风险、错误与技术附录

### 14.1 页面底部内容

1. 字段未接入；
2. 字段配置冲突；
3. 数据处理错误；
4. Candidate Detail 请求失败；
5. unknown 数据；
6. 指标不可用原因；
7. 评测口径说明；
8. 报告模型与规则版本；
9. Raw 数据和处理过程入口。

### 14.2 顶部警告条件

只有下列问题允许在页面顶部显示紧凑警告：

- 报告生成失败；
- 全部 Query 执行失败；
- 正式 Query 数为 0；
- 身份归类结果完全不可用；
- 核心指标因处理错误无法计算。

普通字段未接入、部分模块为空、成本字段缺失等问题不得取代执行摘要，只在相关章节或附录说明。

## 15. 视觉与交互要求

### 15.1 视觉层级

1. 核心 KPI 使用大号数字和简短说明；
2. 页面主体保持统一内容宽度和卡片间距；
3. 绿色只表示提升或命中；
4. 红色只表示退化、冲突或失败；
5. 黄色表示疑似或需要关注；
6. 灰色表示无变化、不适用或辅助信息；
7. 不使用颜色作为唯一状态判断方式，同时提供文字标签。

### 15.2 表格

1. 长表格使用固定表头；
2. 百分比统一格式化；
3. 支持筛选和搜索；
4. 长文本折叠，按需展开；
5. URL 显示平台或简短标题，完整地址可复制；
6. JSON 使用格式化、缩进和等宽字体展示；
7. 移动端允许横向滚动，不压缩到单字换行。

### 15.3 图表

首版仅在能明显提升理解时使用简单图表：

- 核心指标版本变化；
- 人物配对分类；
- Confidence 分布；
- 照片相似度分布。

图表标题直接表达结论，例如：

```text
FULL_NAME 检索成功率较基准版本提升 5.00 个百分点
```

不为了视觉效果添加无法下钻或不能辅助判断的图表。

## 16. 报告类型适配

### 16.1 单次报告

展示：

- 执行摘要；
- Query 条件指标；
- Query 与全部候选人；
- 模块与字段质量；
- 成本与耗时，数据可用时；
- 参考线与建议，已配置时；
- 数据质量附录。

不展示版本配对和变化。

### 16.2 版本对比报告

在单次报告内容基础上增加：

- 基准版本与候选版本；
- 同条件指标变化；
- 持续命中、新增命中、退化未命中、持续未命中；
- 人物级配对；
- 成本和耗时变化，数据可用时。

### 16.3 静态 HTML 报告

1. 与 Web 报告使用相同 ReportModel 数据；
2. 章节顺序和指标口径一致；
3. 不依赖 JavaScript 的核心数据必须可直接阅读；
4. Query 和候选人明细允许使用可展开的 HTML；
5. 不可访问的内部链接需显示可识别的 ID，不生成失效操作按钮；
6. 全部 Query 和全部候选人的指标摘要必须保存在静态 HTML 中，不截断候选人；
7. 执行摘要、核心指标、Query 标题和候选人指标摘要直接输出为 HTML，确保禁用 JavaScript 时仍可阅读；
8. 模块、字段和 Evidence 详情默认折叠，可从报告快照中的紧凑数据结构按需渲染；
9. 同一字段值或 Evidence 不在多个章节中重复嵌入，页面通过引用关系复用同一份快照数据；
10. Candidate Detail 完整 Raw 不嵌入静态 HTML，只保留 candidate_id、raw_id 和可用的 Web 详情入口；
11. 空模块、未启用字段、未配置参考线和未接入的可选数据不写入静态 HTML；
12. 静态 HTML 体积控制不得删除 Query、候选人身份结论及其核心指标；优先通过默认折叠、避免 Raw 和去除重复数据控制体积。

## 17. 数据与兼容要求

1. 本次优化优先复用已有 ReportModel、Process、Query、Candidate、Field Comparison 和 Raw 数据；

3. 历史报告仍可继续打开；

11. Web 和静态 HTML 均以报告快照为正式数据源，打开报告时不通过 `report_id` 临时拼装 Query 与候选人数据；
12. 报告快照不重复保存 Candidate Detail 完整 Raw，只保存 Raw 记录引用，避免无意义的数据膨胀。

## 19. 验收场景

### 19.1 核心指标

1. 打开报告时，首屏无需滚动即可看到四个核心指标；
2. 每个百分比可看到分子和分母；
3. 不再在核心指标后显示 `READY`；
4. 无数据指标显示“不适用”或 `—`，不显示为 0。

### 19.2 Query 和候选人

1. 一个 Query 返回 5 个候选人时，展开后必须展示 5 条候选人记录；
2. 一个 Query 返回 15 个候选人时，展开后必须展示 15 条候选人记录；
3. HIT 候选人展示命中完整度和准确率；
4. NON_HIT 候选人不展示准确率，展示非命中完整度；
5. SUSPECTED 候选人明确标记疑似，并按非命中口径展示完整度；
6. Candidate Detail 失败的候选人仍在列表中，并显示失败原因；
7. 候选人可以进入模块、字段、证据和 Raw 明细；
8. Web 报告不出现分页器，Query 随页面浏览前端分段加载；
9. 搜索第一个未渲染分段中的 candidate_id 时，仍能返回正确候选人；
10. 前端显示的 Query 数和候选人数最终与报告快照总数一致。

### 19.3 条件展示

1. 未选择参考线时，报告中不存在参考线章节和 `NOT_CONFIGURED`；
2. 未配置建议时，不显示建议内容；
3. 单次报告不显示版本配对；
4. 只有 FULL_NAME 数据时，不显示空的 FULL_NAME_SOCIAL 表格；
5. 成本字段全部未接入时，不显示空成本主表；
6. 普通字段未接入只在附录说明，不出现在执行摘要之前。

### 19.4 指标核对

1. 检索成功 Query 数与 Query 明细中的成功数量一致；
2. 候选人总数与所有 Query 下的候选人记录数一致；
3. 命中、非命中、疑似和待归类数量能够与候选人明细核对；
4. 命中完整度和准确率只使用主命中候选人及启用字段；
5. 非命中完整度只使用非命中和疑似候选人；
6. 执行失败不进入有结果率和无结果率分母；
7. 缺失成本、耗时和 PDL 不按 0 统计。

### 19.5 兼容

1. 现有历史报告仍可访问；
2. 新生成 Web 报告和静态 HTML 报告核心数据一致；
3. 报告优化不触发新的检索接口请求；
4. 报告优化不覆盖 Raw、Candidate、Process 和历史报告快照；
5. 系统不提供历史报告重生成新版快照的操作；
6. 新版报告关闭 JavaScript 后仍可阅读核心指标、全部 Query 和全部候选人指标摘要；
7. 静态 HTML 不嵌入 Candidate Detail 完整 Raw；
8. Evidence 的展示结果与报告关联的 FieldSchema 快照一致。

## 21. 已确认的开发约束

### 21.1 ReportModel 版本

1. 新版 ReportModel 必须具有独立于旧版的版本标识；
2. 版本值默认由系统在开发/发布时自动写入，也允许开发在发布新版模型时显式指定；
3. 版本值不是报告创建页面的用户输入项；
4. 同一套数据结构和口径使用稳定版本值，只有快照结构或业务语义变化时才升级版本；
5. 每份报告快照必须保存实际使用的 ReportModel 版本，便于后续审计。

### 21.2 报告快照

Query 与全部候选人数据由报告快照直接保存，不通过 `report_id` 在报告打开时临时查询和拼装。

报告快照至少保存：

- 全部 Query；
- 每个 Query 的全部候选人；
- 候选人排名、身份结论和核心指标；
- Query 和候选人统计分子、分母；
- 模块摘要；
- 字段比较结果；
- 当前 FieldSchema 已启用并成功处理的 Evidence；
- Candidate、Raw 和 Process 的引用 ID。

### 21.3 历史报告

1. 本期不处理历史报告的新版重生成；
2. 不提供“将历史报告升级为新版快照”的入口；
3. 历史报告继续按旧模型展示；
4. 新版报告能力从本功能上线后新生成的报告开始生效。

### 21.4 Web 加载方式

1. Query 与候选人列表使用前端分段加载；
2. 不使用分页器；
3. 筛选、搜索和总数统计面向完整报告快照；
4. 分段加载不得影响排序、统计口径和导出结果。

### 21.5 静态 HTML 体积控制

采用“核心摘要直接输出、详细数据按需展开、Raw 不重复嵌入”的方式：

1. 全部 Query 和全部候选人的身份结论与核心指标直接保留；
2. 模块、字段和 Evidence 默认折叠；
3. 重复字段数据只在快照中保存一份；
4. Candidate Detail 完整 Raw 不写入 HTML；
5. 未配置、未启用和空的可选章节不输出；
6. 优先保证数据完整性，不通过截断候选人数量控制文件体积。

### 21.6 Evidence 范围

1. Evidence 的正式范围以报告关联的 FieldSchema 快照为准；
2. 报告只展示字段配置已登记并启用的 Evidence；
3. 字段配置关闭的 Evidence 不视为缺失；
4. 已启用但接口未返回与提取失败必须继续按现有缺失/错误口径区分；
5. 后续接口新增 Evidence 字段时，通过字段配置扩展，不修改报告固定字段清单。
