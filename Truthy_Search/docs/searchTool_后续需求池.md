# searchTool 后续需求池

## 1. 文档说明

本文档用于保存未进入 `searchTool v1.3 MVP` 的需求。

需求池中的事项不属于 v1.3 MVP 验收范围。进入开发前需要重新确认业务价值、接口条件、优先级和验收标准。

状态说明：

- `待确认`：依赖产品、后端或真实数据确认；
- `待规划`：需求方向明确，但未排期；
- `条件满足后启动`：已有明确前置条件；
- `暂缓`：当前收益不足以进入近期版本。

## 2. 高优先级候选需求

### 2.1 `FULL_NAME_PHOTO` 照片检索

| 项目 | 内容 |
| --- | --- |
| 状态 | 条件满足后启动 |
| 目标 | 支持全名 + 照片 URL 的检索和评估 |
| 暂不进入 MVP 原因 | 需要新增 PUT 等接口请求，输入格式和响应行为尚未确认 |

启动前需要确认：

1. 照片输入是 URL、文件、base64 还是上传后的资源 ID；
2. PUT 接口地址、方法、请求头、请求体和响应结构；
3. 照片上传与 CreateIntentTask 的关联方式；
4. 上传失败、超时和重试规则；
5. 输入照片 URL 是否会在结果中原样回显；
6. `photos_identity_match_rate` 的来源、范围和含义；
7. 80% 命中阈值是否继续适用；
8. 照片数据的保存、访问和脱敏要求。

预期能力：

- Query 支持 `FULL_NAME_PHOTO`；
- Web 支持照片输入；
- 采集流程增加必要接口步骤；
- 报告支持照片条件横向比较；
- 无优化前数据时明确标记“新增条件，无历史基线”。

## 5. 数据获取与任务执行

### 5.1 候选人分页

当前 ListTaskCandidates 的分页字段只是预留。

后端明确以下内容后再实现：

- `page_token` 返回路径；
- 下一页请求方式；
- 结束条件；
- page size 上限；
- 排名跨页规则；
- 分页失败后的恢复方式。

### 5.2 并发执行

当前 searchTool 按输入顺序逐条执行。

只有在数据规模和运行时间证明有必要时，再评估：

- Query 级并发；
- 并发数配置；
- 限流；
- 重试；
- 并发任务的成本和可追溯性。

### 5.3 复杂任务编排

后续可考虑：

- 定时运行；
- 每日冒烟；
- 每周基础集；
- 发布前完整回归；
- 失败自动重试；
- 运行暂停和恢复。

## 6. 分析与报告增强

### 6.1 长期趋势

- 按版本和日期查看核心指标趋势；
- 按检索条件、难度和标签分组；
- 识别长期改善和波动；
- 保存正式基线。

### 6.2 发布门禁

- 配置最低成功率和准确率；
- 配置最大退化人数；
- 配置成本增长上限；
- 自动给出通过、阻塞或待复核状态；
- 门禁结论必须可下钻。

### 6.3 通知

- 运行完成通知；
- 运行失败通知；
- 出现退化通知；
- 报告生成通知；
- 后续根据平台能力选择通知渠道。

### 6.4 结果一致性

同一条件重复运行后，可增加：

- 候选人集合一致性；
- 命中状态一致性；
- 排名波动；
- 字段值变化；
- 外部数据源波动说明。

### 6.5 排名指标

后续根据实际返回数量增加：

- 命中候选人排名；
- Top 1 / Top 3 / Top 5 / Top K；
- MRR；
- 排名改善与退化。

### 6.6 错误类型与根因

- 命中其他同名人物；
- 错误 Social Link；
- 信息过期；
- 多人信息混合；
- 数据源缺失；
- 候选人排序问题；
- Pipeline 失败。

## 7. 自动化核验

以下能力风险和成本较高，暂不进入近期版本：

- 自动访问公开网页核验事实；
- AI 自动拆分 Insights 事实点；
- AI 自动判断字段正确性；
- AI 自动生成最终上线结论；
- 自动将多个证据映射到具体字段。

启用前必须明确：

- 人工复核保底机制；
- 错误结论责任；
- 外部访问合规；
- 成本；
- 结果可解释性。

## 8. 数据与导出增强

### 8.1 历史 Excel 双向同步

v1.3 MVP 只保证导入和导出，不保证任意历史 Excel 修改后无损回写。

后续如有需要，可定义：

- 固定模板版本；
- 行唯一键；
- 可回写字段；
- 冲突处理；
- 导入审计。

### 8.2 静态报告访问控制

v1.3 MVP 允许静态 HTML 包含人物级案例并作为受控文件使用。

多用户或对外分享时再增加：

- 人物信息脱敏；
- 报告有效期；
- 下载水印；
- 访问口令；
- 禁止导出字段；
- 操作审计。

### 8.3 数据保留与归档

后续确认：

- 原始结果保留周期；
- 报告保留周期；
- 数据删除流程；
- 冷数据归档；
- 敏感人物数据销毁；
- 测试平台统一存储策略。

## 9. 需求池维护规则

1. 新需求先记录背景、目标、价值和前置条件。
2. 未确认接口或数据口径的需求不能直接进入开发。
3. 进入版本前需要从需求池迁移到对应 PRD。
4. 已迁移需求在本文件中标记目标版本。
5. 不因“以后可能需要”提前增加 MVP 复杂度。
