# 优化后全名检索与全名+Link检索对比报告说明

## 1. 测试背景

本次测试使用同一批 100 名普通职业人士，对比优化后 V1 版本下两种检索方式：

- 仅使用人物全名检索：`NAME_V1`
- 使用人物全名及已知 Link 线索检索：`NAME+Link_V1`

对应报告：

- 全名+Link 运行报告：`report_fbebdc8982cb4464874d90dabadc84c2`
- 全名与全名+Link 对比报告：`report_17c02599dcff48e89f32c04e17e50c76`

两组运行使用相同系统版本和字段 Schema，人物样本也完全一致。区别在于第二组新增了 Link 线索，因此本报告衡量的是“新增已知 Link 对检索能力的增益”，不属于完全相同查询条件下的版本回归测试。

正式对比报告将 100 个 Link 查询标记为新增线索条件，`paired_count` 为 0。本文除使用报告中的总体指标外，还按照相同 `person_id` 对两组结果进行了探索性对齐，用于观察同一人物在两种检索方式下的结果迁移。该迁移分析用于产品决策参考，不替代同条件回归结论。

---

## 2. 核心结论

本次对比表明，增加 Link 线索后，系统的检索方式由“基于姓名的宽泛搜索”转向“基于姓名和已知链接的定向身份识别”。在总成本仅小幅增加、候选规模基本不变的情况下，目标人物命中率、第一名命中率、单位命中成本和检索耗时均获得明显改善。

### 2.1 Link 带来了最明显的目标人物召回提升

仅使用全名时，100 人中成功命中 53 人；增加 Link 后成功命中 90 人，目标人物命中率从 `53%` 提升至 `90%`，增加 37 个命中，相对提升约 `69.81%`。

在返回候选人的查询中：

- 仅全名有 89 个查询返回候选人，其中 53 个包含目标人物。
- 全名+Link 有 90 个查询返回候选人，这 90 个查询全部包含目标人物。
- 有候选人条件下的命中率由 `59.55%` 提升至 `100%`。

这说明 Link 的主要价值不是让更多查询“随便返回一些人”，而是显著提高返回候选人中包含正确目标人物的概率。

### 2.2 正确人物更容易排在第一位

新增 Link 后，第一名命中数量由 38 个增加至 80 个，第一名命中率从 `71.70%` 提升至 `88.89%`。

平均命中排名由 `1.38` 改善至 `1.13`，90 个命中人物全部进入前三名。

这意味着 Link 不仅提高了召回覆盖，还显著增强了身份定位确定性。用户在绝大多数情况下只需查看第一位候选人，不再需要在多个同名人物中反复筛选。

### 2.3 候选规模基本不变，但有效候选比例大幅提高

新增 Link 后，候选人总数仅从 236 人增加至 246 人，增幅约 `4.24%`；但目标命中数从 53 个增加至 90 个，增幅约 `69.81%`。

每获得一个目标命中所需的候选人数：

- 仅全名：`236 ÷ 53 ≈ 4.45 人`
- 全名+Link：`246 ÷ 90 ≈ 2.73 人`

单位命中所需候选人数下降约 `38.64%`。

因此，Link 没有造成候选池明显膨胀，而是提高了候选人的有效性。系统以基本相同的候选处理规模，获得了更多正确人物。

### 2.4 总成本小幅增加，但单位命中成本明显下降

100 人检索总成本由 `$57.37` 增加至 `$61.00`，增加约 `$3.63`，增幅为 `6.33%`。

但同期目标命中数由 53 个增加至 90 个，因此每获得一个目标命中的平均成本由：

- 仅全名：约 `$1.08`
- 全名+Link：约 `$0.68`

单位命中成本下降约 `37.38%`。

因此，不能只看总成本增加了 3.63 美元。更重要的是，系统用约 6.33% 的额外成本换来了 69.81% 的命中数量增长，单位检索产出明显提高。从成本收益角度看，新增 Link 线索具有较高价值。

### 2.5 检索耗时不升反降

平均检索耗时由 `15.12 秒` 下降至 `11.42 秒`，减少约 `3.70 秒`，降幅为 `24.47%`。

原因是全名检索主要依赖 PDL Search、LLM、Wiki 和社交平台的广泛搜索；全名+Link 则优先使用 PDL Person Identify 进行定向识别，减少了多数据源探索调用。

这说明新增 Link 不仅提升了命中率，还缩短了检索路径，使系统更快地锁定目标人物。

### 2.6 Link 提升的是身份识别能力，不是资料提取能力

命中信息准确度在两组中均约为 `57.77%`，基本没有变化；命中资料完整度由 `44.50%` 小幅下降至 `43.15%`。

因此，本次 Link 带来的核心提升是：

> 更快、更低单位成本、更确定地定位到目标人物。

但它没有同步解决以下问题：

- 人物 Profile 资料是否完整。
- 工作、教育、地点等字段是否准确。
- 头像是否能够稳定获取。
- Photos 和 Insights 是否能够提供更多身份验证证据。

换句话说，Link 显著提升了“找对人”的能力，但“拿全资料”和“验证资料”的能力仍需单独优化。

### 2.7 当前最优方向是 Link 优先、全名兜底

按人物进行探索性对齐后：

- 50 人两种方式均命中。
- 40 人只有增加 Link 后才命中。
- 3 人仅全名命中，Link 检索返回 0 个候选人。
- 7 人两种方式均未命中。

两种方式的命中并集为 93 人。因此，如果 Link 检索无结果时自动回退全名检索，历史结果显示潜在命中上限可达到 `93%`。

综合来看：

> 全名+Link 应作为存在可靠 Link 线索时的首选检索方式；当 Link 无法识别或返回 0 个候选人时，再自动回退全名检索。该策略可以同时利用 Link 的高命中、高排序和低单位成本优势，并降低 Link 失效造成的漏召回风险。

### 3.1 核心指标简要判断

从核心指标看，增加 Link 后的提升主要集中在三个方面：

1. **检索能力提升最明显**

   目标人物命中率增加 37 个百分点，有候选人情况下的命中率达到 100%，第一名命中率提高至 88.89%。

2. **成本和时间效率同步改善**

   总成本只增加 6.33%，但单位命中成本下降 37.38%，平均检索耗时下降 24.47%。

3. **资料质量没有同步提升**

   命中信息准确度基本不变，命中资料完整度略有下降，说明 Link 解决了身份定位问题，但没有解决资料提取和字段质量问题。

因此，核心指标支持以下判断：

> 全名+Link 在目标人物召回、第一名排序、单位命中成本和检索耗时方面均明显优于仅全名检索；其主要短板不是找不到人，而是找到人后仍缺少足够完整、准确的 Profile、Photos、Insights 和头像证据。

## 4. Link 对检索命中的实际增益

虽然正式对比报告将 100 个 Link 查询标记为“新增线索条件”，不提供同条件回归迁移结论，但按照同一人物 ID 进行探索性对齐后，结果如下：

| 人物检索结果 | 人数 |
|---|---:|
| 全名和全名+Link 均命中 | 50 |
| 全名未命中、Link 新增命中 | 40 |
| 全名命中、Link 未命中 | 3 |
| 两种方式均未命中 | 7 |
| 合计 | 100 |

全名+Link 检索新增 40 个命中，但丢失了 3 个仅全名检索可以命中的人物，最终净增加 37 个命中。

```text
仅全名命中：53 人
全名+Link 新增命中：40 人
全名+Link 丢失原命中：3 人
最终命中：90 人
```

新增 Link 后，目标命中数相对增长约：

```text
(90 - 53) ÷ 53 = 69.81%
```

即目标人物检索能力相对提升约 69.81%。

## 5. 三个 Link 退化人物

有 3 个人物在仅全名检索时能够命中，但加入 Link 后没有返回候选人：

| Case | 人物 | 仅全名候选数 | 全名+Link 候选数 |
|---|---|---:|---:|
| case-029 | Shea-Lynn Fernald | 1 | 0 |
| case-069 | Michaela Myers | 3 | 0 |
| case-100 | Tim Shattuck | 3 | 0 |

这 3 个 Case 不是因为候选人身份判定错误，而是 Link 检索直接返回了 0 个候选人。

可能原因包括：

- Link 已经过期或页面不可访问。
- Link 格式或平台未被识别。
- Link 对应的页面无法被 PDL Identify 识别。
- 全名与 Link 组合后的查询条件过严。
- Link 归属正确，但第三方数据源尚未收录。

这说明 Link 检索虽然命中效率高，但对 Link 有效性和第三方平台覆盖存在依赖。

## 6. 推荐采用“Link 优先、全名兜底”

从两组历史结果看：

- 全名+Link 命中 90 人。
- 其中有 3 人只能通过全名命中。
- 两种方式的命中并集为 93 人。

因此，可以考虑以下检索流程：

```text
存在可用 Link
    ↓
先执行全名+Link 定向识别
    ↓
返回候选人 ──→ 使用 Link 检索结果
    ↓ 无候选人
自动回退仅全名检索
```

按照本次历史数据估算，如果 Link 检索无结果时自动回退全名检索，理论上可以保留 90 个 Link 命中，并找回 3 个全名独有命中，使测试集命中上限达到：

```text
90 + 3 = 93 人
```

即潜在目标命中率为 `93%`。

该结果是根据两次历史运行的命中并集计算出的组合上限，仍需通过一次真实的“Link 优先、全名兜底”运行验证。但该策略只需对 10 个 Link 无结果 Case 执行全名回退，额外调用范围有限，具有较好的成本收益比。

## 9. 字段准确度与完整度

Link 显著提升了人物命中能力，但没有同步提高命中人物的资料质量：

- 命中信息准确度：`57.77% → 57.77%`，基本不变。
- 命中资料完整度：`44.50% → 43.15%`，下降 1.35 个百分点。

这说明 Link 解决的是“这是谁、能否找到这个人”，并没有直接改善“这个人的资料是否完整”。

各模块整体字段完整度如下：

| 模块 | 仅全名 | 全名+Link | 变化 |
|---|---:|---:|---:|
| Insights | 10.17% | 9.76% | -0.41 个百分点 |

| Profile | 75.25% | 63.90% | -11.35 个百分点 |

其中，命中候选人的 Social 完整度保持在 80%，Summary 完整度基本不变；Profile 命中完整度由 78.89% 下降至 74.89%。

整体字段完整度下降的一部分原因是 Link 检索减少了非必要的广泛资料搜索，返回结果更聚焦于人物识别，但附带资料相对较少。

仍需关注：

- Photos 模块在两种模式下均为 0%。
- 命中候选人的 Insights 返回率仍为 0%。
- Link 没有明显提升工作、教育、地点等资料字段的准确度。

## 11. 风险与口径说明

### 11.1 查询条件不同

全名+Link 增加了新的身份线索，不能将两组差异解释为同条件下的算法回归。本文描述的是 Link 线索带来的增量价值。

### 11.2 Link 质量依赖

Link 可能存在失效、格式不支持、页面不可访问或第三方数据源未收录等问题。3 个全名独有命中均在 Link 模式下返回 0 个候选人，说明必须设计回退机制。

### 11.3 有候选人条件下命中率

全名+Link 的条件命中率为 100%，表示本次测试中只要返回候选人就存在被规则确认的目标人物。该指标仍依赖当前基准数据、Link 质量和身份判定规则，不应直接外推到未知质量的外部 Link。

### 11.4 资料质量与身份命中是不同能力

目标人物命中率提高不等于字段资料更完整或更准确。Profile、Photos、Insights 和头像仍需独立评估和优化。

---

## 12. 综合结论

新增 Link 线索后，系统的目标人物命中率从 53% 提升至 90%，且候选数量只增加 4.24%、总成本只增加 6.33%、平均耗时下降 24.47%。这是一次非常明显的检索效率提升。

全名+Link 的主要价值是：

- 将宽泛人物搜索转化为定向身份识别。
- 目标人物命中率提高 37 个百分点。
- 40 个全名未命中的人物通过 Link 新增命中。
- 第一名命中率提高至 88.89%。
- 每个目标命中的平均成本下降 37.38%。
- 非命中候选人与基准人物的相似度下降，干扰候选更容易区分。

当前主要问题是：

- Link 无结果时会丢失部分仅全名可命中的人物。
- 命中资料完整度没有随命中率同步提升。
- Profile 和 Social 附带资料有所减少。
- 头像单人获取率没有提高。
- Photos 和命中人物 Insights 仍然缺失。

综合建议是采用“Link 优先识别、无结果时全名兜底”的混合策略。按照当前两次运行的命中并集，该策略在本测试集上的潜在命中上限为 93%，同时只需对 10 个 Link 无结果 Case 执行回退，预计能够在控制成本的情况下进一步提高检索覆盖率。

下一阶段建议重点验证：

1. 对 10 个 Link 无结果 Case 自动回退全名检索后的真实命中率、成本和耗时。
2. 3 个全名命中但 Link 无结果 Case 的 Link 有效性和 PDL Identify 失败原因。
3. 在保持 90% 以上命中率的前提下，提高 Profile、头像、Photos 和 Insights 的资料返回能力。
4. 对外部未知质量 Link 建立格式校验、可访问性检测和失效回退机制。
