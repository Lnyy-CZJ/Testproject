## 1. 背景

当前脑图工作台虽然已经具备节点展示、部分编辑、拖动、表格同步和版本发布能力，但实现仍以“保护标准测试资产结构”为优先：

- 节点点击、双击、拖动和删除前存在多层节点类型判断；
- 只有部分叶子节点能直接编辑，分组节点、结构节点和根节点存在不同限制；
- 测试用例的前置条件、测试步骤和预期结果被投影为“结构分组 + 多个明细节点”，节点数量过多；
- 当前平面 JSON 既承担正式业务数据，又承担脑图编辑中间状态，导致无法自然保存暂时不规范的结构；
- 为防止生成或发布收到错误数据，前端提前阻止了大量操作，造成脑图不具备常见脑图工具的基本手感。

用户实际期望是：脑图首先是一个可自由操作的编辑器。用户可以选择、修改、增加、删除、移动和重组节点；格式、层级或业务字段有问题时，系统负责及时提示，但不应通过“点不了、改不了、拖不了”的方式保护数据。

本期需要从产品模型上解决该矛盾，而不是继续针对单个事件补丁修复。

## 2. 市场产品参考与设计结论

### 2.1 参考能力

主流脑图产品形成了稳定的基础交互习惯：

- 单击选择节点；
- 双击或快捷键进入原位编辑；
- `Enter` 新增同级节点，`Tab` 新增子节点；
- 拖动节点调整顺序或重新指定父节点；
- `Delete` 删除节点及分支；
- 方向键在节点间导航；
- 画布可以平移、缩放、适应内容和回到中心；
- 操作完成后再通过布局、校验或整理能力处理结构问题。

参考资料：

- [Miro Mind Map 官方帮助](https://help.miro.com/hc/en-us/articles/360017730753-Mind-map)
- [XMind Topic Editing 官方指南](https://xmind.com/user-guide/topic-editing-new)

### 2.2 本产品设计结论

本产品不再把“阻止用户产生不规范数据”作为脑图交互层的主要职责，改为：

```text
自由编辑
→ 实时校验与问题标记
→ 显式保存草稿
→ 风险确认
→ 继续生成或发布版本
```

基本原则：

1. 所有可见节点均可单击选择。
2. 所有业务节点均可双击原位编辑。
3. 暂时错误的文本、字段或层级允许存在于草稿。
4. 错误必须可见、可定位、可解释，但业务质量错误不禁止保存。
5. 测试点继续生成时允许用户带质量风险确认；测试用例发布只以对象数组、安全序列化和 XLSX 可转换为硬条件。
6. 脑图编辑草稿和正式测试资产 JSON 分层保存，避免自由编辑与标准结构相互牵制。

## 3. 产品目标

### 3.1 核心目标

- 将测试点和测试用例脑图改造成符合通用脑图使用习惯的编辑器。
- 取消以节点类型为由造成的点击、原位编辑和选择定位差异。
- 支持用户先自由调整内容和层级，再通过校验面板处理问题。
- 简化测试用例脑图，避免前置条件、步骤和预期结果产生大量结构节点。
- 保持现有草稿 CAS、不可变确认版本、AI 建议、JSON/XLSX 发布和任务所有权能力。
- 通过统一交互内核一次解决节点事件问题，避免继续按页面、节点类型和按钮逐项修补。

### 3.2 成功指标

| 指标 | 目标 |
|---|---:|
| 所有业务节点单击选择成功率 | 100% |
| 所有业务节点双击进入编辑成功率 | 100% |
| 节点选择后进入安全可视区成功率 | 100% |
| 脑图、表格、详情面板当前草稿一致率 | 100% |
| 暂时不规范草稿保存成功率 | 100%（未触及硬限制） |
| 500 个可见节点交互 P95 | ≤ 100ms |
| 因前端类型守卫导致的无反馈操作 | 0 |
| 发布版本与对应确认 JSON 内容一致率 | 100% |

## 4. 范围

### 4.1 本期范围

- 测试点脑图自由选择、编辑、新增、删除、复制、移动和重组；
- 测试用例脑图自由选择、编辑、新增、删除、复制、移动和重组；
- 根节点、分组节点、叶子节点和用例内容节点使用一致的选择及编辑方式；
- 测试用例内容节点重新设计；
- 脑图草稿、标准业务 JSON 和确认版本的数据分层；
- 实时校验、错误标记、错误定位和风险确认；
- 表格、详情、脑图共享同一当前草稿；
- 已发布任务继续编辑和发布新版本；

- 图片、附件、富文本、Markdown 和外部链接节点；
- 移动端脑图编辑；
- 自动保存；
- 修改 API 测试智能体；
- 修改原功能智能体 Prompt、CLI 和历史 `output/`；
- 新增测试资产业务数据库表。

## 5. 用户与使用场景

### 5.1 主要用户

- 测试工程师：整理 AI 生成结果、补充场景、调整结构并发布用例。
- 测试负责人：检查覆盖、快速调整模块划分并发布评审版本。
- 管理员：在获得跨用户查看权限时排查任务问题。
- 只读用户：查看脑图、版本、问题和产物，但不能修改。

### 5.2 核心场景

1. 用户双击任意模块、功能、场景、测试点或用例节点直接修改文字。
2. 用户拖动节点重新组织结构，即使暂时造成字段缺失也可以先保存。
3. 用户点击错误标记，自动定位节点并继续修改。
4. 用户把多条测试步骤作为一个节点整体查看和编辑。
5. 用户在脑图、表格或详情面板修改同一数据，其他视图立即同步。
6. 用户保留错误或未覆盖项，确认风险后继续生成或发布新版本。
7. 用户打开已发布任务，基于当前版本继续修改并发布 v2、v3。

## 6. 产品原则

### 6.1 交互优先

- 单击、双击、拖动、键盘和右键菜单必须与通用脑图习惯一致。
- 操作失败必须给出明确原因，禁止无反馈。
- 不允许同一行为同时存在两套互相竞争的事件实现。

### 6.2 自由编辑、延迟约束

- 编辑阶段允许不完整、不规范和暂时错误的数据。
- 校验在每次编辑后增量执行，并在保存时由服务端完整执行。
- 业务质量错误只提示，不阻止保存。
- 继续生成、确认或发布前展示风险摘要，由用户明确确认后继续。

### 6.3 数据不丢失

- 所有编辑命令必须可撤销、重做。
- CAS 冲突时保留本地内容并允许下载本地副本。
- 原稿、草稿、AI 建议、确认版本和发布产物必须隔离。
- 不能表示为标准字段的临时结构仍必须保存在脑图草稿中。

### 6.4 安全边界不放松

自由编辑不等于绕过：

- 身份认证；
- CSRF；
- RBAC 和任务所有权；
- 路径 containment；
- 文件大小和节点数量上限；
- XSS、公式注入和危险字段过滤；
- revision/SHA 冲突；
- 正在运行任务的状态互斥。

## 7. 信息架构

工作台保持三个主 Tab：

```text
脑图｜表格｜版本
```

- 脑图：默认入口，提供自由结构编辑。
- 表格：结构化字段查看和编辑，适合批量核对。
- 版本：查看原稿、草稿、确认版本和发布版本差异。

右侧详情面板显示当前节点的完整字段。脑图节点负责结构和高频文本，详情面板负责复杂字段与精确编辑。

## 8. 统一脑图基础交互

### 8.1 节点选择

- 所有可见节点均可单击选择，包括中心根节点、分组节点、叶子节点和用例内容节点。
- 单击后必须立即显示统一选中态、面包屑和详情。
- 节点超出画布安全区域时自动平滑移动到可视区；已完整可见时不移动画布。
- 表格行、搜索结果、错误项和版本差异点击后复用同一个定位方法。
- `Ctrl/Command + 单击`用于多选；再次单击取消选择。

### 8.2 原位编辑

- 双击任意业务节点进入原位编辑。
- 选中节点后按 `F2` 或 `Space`进入编辑。
- `Enter`提交；`Shift + Enter`换行；`Escape`取消；失焦提交。
- 空文本、重复 ID、非法优先级等允许提交到草稿，但节点立即显示问题标记。
- 同一时间只允许一个原位编辑器。
- 原位编辑、详情编辑和表格编辑调用同一个领域命令。

### 8.3 新增

- `Tab`新增子节点；`Enter`新增同级节点。
- 节点右侧“＋”默认新增子节点。
- 右键菜单提供新增子节点和新增同级节点。
- 新节点自动进入编辑状态并滚动到可视区域。
- 新节点使用临时稳定 ID；业务 ID 可为空并由校验提示。

### 8.4 删除

- `Delete/Backspace`或右键菜单删除节点。
- 删除分组时显示受影响后代数量。
- 删除操作完成后选择相邻节点。
- 删除作为一个原子命令进入撤销历史。
- 中心根节点可修改，也可删除。删除前必须强确认，删除后清空当前草稿的业务节点并自动重建一个空白可编辑根；操作可撤销。
- 根节点删除不影响模型原稿、历史确认版本、已发布产物和任务记录。

### 8.5 拖动与重组

- 节点可拖动改变同级顺序或父节点。
- 拖动时展示影子、插入线和目标高亮。
- 合法标准结构使用正常落点样式。
- 会造成非标准结构的落点仍允许放置，但使用警告样式，并在放置后生成结构问题。
- 仅会形成循环引用、超过节点上限或跨任务的数据移动必须拒绝。
- 放置后保持选中并定位到新位置。

### 8.6 画布

- 空白区域拖动平移画布。
- 滚轮或工具栏缩放，步长固定且比例显示准确。
- 支持适应画布、回到中心、聚焦分支、全部展开、全部收起。
- 展开、缩放、位置和焦点属于 UI 状态，不写入正式业务 JSON。

### 8.7 键盘

| 快捷键 | 行为 |
|---|---|
| `Tab` | 新增子节点 |
| `Enter` | 新增同级节点 |
| `F2` / `Space` | 编辑节点 |
| `Delete` / `Backspace` | 删除节点 |
| `Ctrl/Command + C/V` | 复制/粘贴 |
| `Ctrl/Command + Z` | 撤销 |
| `Ctrl/Command + Shift + Z` | 重做 |
| 方向键 | 切换节点 |
| `Escape` | 退出编辑、清除菜单或取消选择 |
| `0` | 适应画布 |
| `1` | 回到中心 |

输入框、文本域和表格编辑器获得焦点时，不响应画布快捷键。

## 9. 测试点脑图

### 9.1 推荐标准结构

```text
任务根
└── 模块
    └── 功能
        └── 场景
            └── 测试点
```

### 9.2 节点编辑

- 根节点：修改本次 Review 的显示标题，不改变任务 ID。
- 模块节点：修改模块名称，并同步更新其后代测试点的标准字段。
- 功能节点：修改功能名称，并同步更新其后代测试点。
- 场景节点：修改场景名称，并同步更新其后代测试点。
- 测试点节点：修改测试点正文。
- 风险等级、ID 和扩展字段通过详情或表格修改。

### 9.3 非标准结构

用户可暂时把测试点放到模块下、把功能放到场景下或形成缺少中间层级的结构。系统应：

1. 保存脑图草稿结构；
2. 在节点和问题面板标记“层级不规范”；
3. 对可推导字段进行最佳努力映射；
4. 无法推导的标准字段保留为空；
5. 不自动创建隐藏分组纠正用户操作；
6. 提供“一键整理为推荐结构”，但必须由用户主动执行。

## 10. 测试用例脑图

### 10.1 推荐标准结构

```text
任务根
└── 模块
    └── 功能
        └── 已确认测试点
            └── 测试用例
                ├── 前置内容节点（最多一个）
                ├── 步骤内容节点（最多一个）
                ├── 预期内容节点（最多一个）
                └── 测试数据内容节点（最多一个）
```

### 10.2 用例节点显示

- 每条用例由一个主节点表示。
- 主节点第一行显示用例名称，第二行以紧凑标签显示 `case_id`和优先级。
- 不在用例节点下创建“前置条件”“测试步骤”“预期结果”等纯结构分组节点。
- 不把每一条前置条件或每一个测试步骤拆成独立节点。

### 10.3 四个内容节点

每条用例最多直接拥有四个内容节点：

1. 前置内容节点：展示该用例全部前置条件，以换行分隔；
2. 步骤内容节点：展示该用例全部测试步骤，以编号和换行分隔；所有步骤作为一个节点整体编辑；
3. 预期内容节点：展示完整预期结果。
4. 测试数据内容节点：展示稳定 JSON 或原始文本。

显示要求：

- 节点正文直接展示业务内容，不再额外增加一层结构标题节点；
- 通过小型图标或浅色短标签区分“前置”“步骤”“预期”，标签不占用新的树层级；
- 内容为空时仍显示一个“点击补充”的占位节点；
- 双击内容节点编辑完整多行正文；
- `Shift + Enter`换行，普通 `Enter`提交；
- 步骤保存时按行转换为 `test_steps`数组，展示时自动编号；
- 前置内容按行转换为 `preconditions`数组；
- 预期内容保存为 `expected_result`字符串。
- 测试数据若能解析为 JSON 则保存为对象或数组；否则保存原始字符串并产生质量提示。

### 10.4 其他用例字段

- `test_data`可在脑图、右侧详情和表格中编辑，三处共享同一草稿和撤销历史。
- `actual_result`继续只读。
- 模块、功能、场景、测试点引用可通过拖动或详情面板修改。
- 用例可以拖到其他测试点下，系统同步更新 `test_point_id`及可推导的模块、功能、场景字段。
- 测试点分组名称可以编辑；无法匹配已确认测试点时保留草稿并显示引用错误，不阻止保存。

## 11. 数据模型与持久化

### 11.1 分层原则

为同时支持自由编辑和标准生成，本期将数据分为两层：

```text
脑图编辑草稿（允许非标准结构）
            ↓ 编译/校验
标准测试点或测试用例 JSON（允许业务字段错误）
            ↓ 确认
不可变确认版本
            ↓ 生成/发布
测试用例 JSON/XLSX 产物
```

### 11.2 脑图草稿

在现有 Review 草稿信封中增加版本化 `mindmap`字段，至少包含：

```json
{
  "schema_version": 2,
  "revision": 3,
  "content_sha256": "...",
  "rows": [],
  "mindmap": {
    "root": {
      "node_id": "root_xxx",
      "node_type": "root",
      "text": "登录功能测试"
    },
    "nodes": [
      {
        "node_id": "node_xxx",
        "node_type": "module",
        "parent_id": "root_xxx",
        "order": 0,
        "binding_id": null,
        "text": "登录"
      }
    ]
  }
}
```

约束：

- `node_id`是稳定 UI 标识，不等同于业务 `case_id/test_point_id`；
- `binding_id`连接节点与标准业务行；
- `rows`仍是下游生成和发布使用的权威业务数据；
- `mindmap`保存用户当前结构以及无法立即映射为标准字段的中间状态；
- 同一 CAS 同时保护 `rows`和 `mindmap`，禁止分别保存造成不一致；
- 旧 revision 1 草稿读取时自动投影为 schema version 2，不批量改写历史文件；
- 正式确认版本同时保存标准 JSON 和结构快照，版本不可变。

### 11.3 编译规则

- 每次领域命令后在浏览器内增量生成标准行和校验问题；
- 保存时服务端从脑图草稿重新编译并校验，服务端结果为最终依据；
- 标准层级按祖先节点生成模块、功能、场景和引用字段；
- 缺少祖先时对应字段为空并产生问题；
- 重复分组、空分组和孤立分组保留在脑图草稿，但不伪造业务叶子；
- 发布 JSON 中不写入浏览器坐标、缩放、折叠或选择状态。

---

## 12. 校验与风险模型

### 12.1 质量问题：提示但不阻止草稿保存

以下问题允许保存。测试点需要用户确认质量风险后继续生成；测试用例在满足对象数组和安全转换条件时不因质量问题阻止发布：

- 标准字段为空；
- ID 为空或重复；
- 模块、功能、场景层级不规范；
- 测试点或用例引用不存在；
- 优先级或风险等级不在推荐枚举；
- 用例步骤为空；
- 用例格式不规范；
- 测试点未覆盖；
- 重复测试点或重复用例；
- 用例缺少前置条件或预期结果；
- 存在孤立分组或空分组。

### 12.2 技术与安全问题：必须阻止

- 未登录、无权限、越权或 CSRF 失败；
- revision/SHA 冲突；
- 文件或任务已过期；
- 超过配置的字节数、字符数或节点数；
- 路径穿越、符号链接或伪造 Artifact；
- NUL、危险内部字段或不能安全序列化的数据；
- XSS、HTML、脚本、公式注入；
- 形成树结构循环；
- 任务处于 `pending/running`等不允许编辑的状态；
- 发布文件无法原子生成或持久化失败。

### 12.3 问题展示

- 节点右上角显示错误或警告数量，不只依赖颜色；
- 顶部展示总问题数、未覆盖数和风险摘要；
- 问题面板按“结构、字段、引用、覆盖、重复”分组；
- 点击问题自动切换到脑图、展开父链、选中并定位节点；
- 原位编辑过程中问题可实时变化；
- 保存成功不代表没有问题，Toast 必须区分“已保存”和“校验通过”。

## 13. 保存、继续与发布

### 13.1 保存草稿

- 所有未触及硬限制的草稿均可保存。
- 保存同时提交树结构、标准行、revision 和 SHA。
- 保存成功显示 3 秒 Toast，并保留问题摘要。
- 正文及结构均未变化时不增加 revision。

### 13.2 测试点继续生成用例

- 点击“确认并继续”时展示错误、警告和未覆盖摘要。
- 用户明确勾选“我了解风险，仍然继续”后允许确认测试点版本并重新进入 FIFO。
- Runner 只读取该次不可变确认版本。
- 结构或字段问题可能降低生成质量，必须记录到任务时间线和审计，但不能偷偷修改用户数据。
- 无法解析的 JSON 语法、非测试点顶层数组、无法安全序列化、NUL、危险内部字段、容量、CAS、权限、CSRF、状态和队列问题仍硬阻止。

### 13.3 测试用例发布

- 质量错误、警告和未覆盖不阻止发布。
- 发布最低格式为“顶层 JSON 对象数组”；非对象数组元素以 `CASE_ITEM_NOT_OBJECT` 拒绝。
- 字段缺失、类型异常、ID 重复、引用不存在、未覆盖、非法优先级、未知扩展字段及 `test_data` 非对象都仅作质量提示。
- 只有序列化、容量、嵌套深度、NUL、危险内部字段、权限、CAS 或原子发布失败才阻止。
- 每个不同内容 SHA 生成新的不可变版本 vN。
- 相同 SHA 重复提交复用已有版本。
- 已发布任务继续保持可编辑，并可发布 v2、v3。
- JSON/XLSX必须从同一个确认 JSON 确定性生成。
- 历史版本永久保持只读并可下载，直至保留策略到期。

---

## 14. 表格与详情面板

- 表格继续允许编辑，与脑图共用一份草稿和撤销历史。
- 表格编辑后脑图立即更新；脑图编辑后表格立即更新。
- 表格不展示脑图专用空分组，但必须在问题摘要中说明。
- 用例前置条件、步骤和预期结果使用宽列和多行编辑。
- 详情面板展示所有标准字段、扩展字段和当前节点路径。
- 切换原稿或历史确认版本时，脑图、表格和详情均进入只读状态。

---

## 15. AI 辅助 Review

- AI 建议仍只产生 add/replace 建议，不能自动覆盖草稿。
- 应用建议后生成正常领域命令，可撤销、重做。
- AI 新增内容进入当前选中节点或范围；无法形成推荐结构时允许加入草稿并提示。
- AI 建议不得修改根标题、实际结果、内部节点 ID、确认版本或历史版本。
- AI 不读取 Secret、日志、其他任务和历史 `output/`。
- 应用 AI 建议后仍需显式保存和人工确认。

---

## 16. 状态、权限和审计

### 16.1 可编辑状态

- `waiting_review`：测试点可编辑；
- `waiting_case_review`：测试用例可编辑；
- `succeeded/case_review_published`：测试用例可继续编辑并发布新版本；
- `pending/running`：当前执行资源只读；
- 原稿和历史确认版本：只读。

### 16.2 权限

- 查看：`tool.result.view`；
- 编辑、保存、继续、发布、AI：`tool.execute`；
- 取消 AI 或运行任务：`task.cancel`；
- 管理员跨创建者查看：`task.view.all`；
- 越权和不存在统一返回 404。

### 16.3 审计

记录：

- 节点批量删除、结构重组和一键整理；
- 草稿 revision/SHA、节点数、标准行数和问题数量；
- 带风险继续或发布时的错误、警告、未覆盖数量；
- 确认版本、发布版本和产物 SHA；
- AI 操作、模型与 Prompt 哈希。

审计不得记录完整业务正文、Prompt 全文、Secret、绝对路径或浏览器坐标。

## 17. 接口影响

优先扩展现有 Review 接口，不新增逐节点保存接口：

- 测试点：`GET review`、`PUT review-draft`、`POST resume`；
- 测试用例：`GET case-review`、`PUT case-review-draft`、`POST case-review/confirm`；
- AI、版本、下载和 Artifact 接口保持路径不变。

请求和响应增加：

```json
{
  "draft_schema_version": 2,
  "rows": [],
  "mindmap": {
    "root_title": "...",
    "nodes": []
  },
  "validation": {
    "errors": [],
    "warnings": [],
    "hard_blockers": []
  }
}
```

兼容要求：

- 不传 `mindmap`的旧客户端继续按标准行保存；
- 旧草稿可按 rows 自动构建推荐结构；
- multipart JSON 上传/继续流程至少保留一个发布周期；
- 不新增节点级 HTTP 请求和自动保存请求。

## 18. 性能与容量

- 单任务最多 5,000 条测试点、2,000 条测试用例，沿用既有服务端限制；
- 同时可见节点默认不超过 500；超限时自动折叠，不删除数据；
- 测试用例三个内容节点默认随用例折叠；
- 选中用例后展开其内容节点；
- 500 条搜索或筛选 ≤ 300ms；
- 最大数据服务端编译与校验 ≤ 2s；
- 撤销历史最多 50 步或 20MiB；
- 页面销毁和重新渲染不得累积事件监听器。

---

## 19. 可访问性与视觉反馈

- 所有节点支持键盘选择和编辑；
- 选中、错误、警告、拖动目标必须同时使用文字/图标和颜色；
- 原位编辑器具有可见焦点和可访问名称；
- 200%缩放时主操作不重叠；
- `prefers-reduced-motion`关闭非必要动画；
- 长内容节点支持自动换行，编辑时展示完整正文；
- 1280px及以上桌面端为本期验收范围。

---

## 20. 异常与恢复

- 浏览器刷新后从最近保存草稿恢复，未保存内容由离开确认保护；
- 双标签 CAS 冲突时不得覆盖服务端或丢失本地数据；
- 草稿树损坏但 rows 完整时，回退为推荐结构并提示恢复事件；
- rows 损坏但树结构完整时，尝试重新编译；失败则提供脑图草稿下载；
- 保存文件、确认版本和发布产物均使用临时文件、fsync 和原子替换/创建；
- 已发布版本不得覆盖；
- 服务重启不改变 Review 草稿和发布版本。

## 21. 验收标准

### 21.1 基础交互

- 根、模块、功能、场景、测试点、测试点分组、用例及四个内容节点均可单击选择。
- 所有业务节点均可双击、F2或Space原位编辑。
- 单击定位、表格定位、搜索定位和问题定位行为一致。
- 空白拖动画布与节点拖动不冲突。
- 删除、复制、粘贴、撤销和重做在测试点及用例脑图均可用。

### 21.2 自由结构

- 可保存字段缺失、重复 ID、非法等级和非推荐层级草稿。
- 非推荐结构具有可见问题标记，且可通过问题面板定位。
- 一键整理必须预览影响并可撤销。
- 循环结构、越权和超限操作仍被拒绝。

### 21.3 测试用例显示

- 每条用例只有一个主节点。
- 前置条件全部内容使用一个直接子节点。
- 测试步骤全部内容使用一个直接子节点，不按步骤拆成多个节点。
- 预期结果全部内容使用一个直接子节点。
- 测试数据全部内容使用一个直接子节点，并可在脑图原位编辑。
- 不出现额外的“前置条件/测试步骤/预期结果”结构分组层。
- 四个内容节点可原位编辑并正确回写数组、对象或字符串字段。

### 21.4 保存与发布

- 业务质量错误不阻止保存。
- 用户确认风险后可继续生成或发布。
- 已发布任务可以修改并发布 v2、v3。
- 同一内容幂等复用版本，历史版本保持只读可下载。
- JSON/XLSX同源且内容可追溯到确认版本。

### 21.5 安全与回归

- 认证、CSRF、RBAC、所有权、IDOR和CAS测试通过。
- Prompt、Secret、绝对路径和内部异常不回显。
- 测试点 Review、用例 Review、AI、原CLI和API智能体回归通过。
- API智能体继续保持真实执行关闭、数据库写入关闭和目标列表为空。
- 历史 `output/`不被读取、迁移、覆盖或删除。

## 23. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 自由结构无法完整映射标准字段 | 生成质量下降 | 保存树结构；最佳努力编译；风险确认；提供一键整理 |
| 旧草稿兼容 | 历史任务打不开 | 读取时投影，不批量改写；旧接口继续接受 rows |
| 节点过多 | 页面卡顿 | 折叠、筛选、500可见节点限制、内容节点懒展开 |
| 事件再次冲突 | 点击或双击失效 | 单一事件拥有者、真实浏览器指针测试、禁止重复编辑实现 |
| 带错误发布造成低质量产物 | 下游使用风险 | 风险摘要、明确确认、版本审计、历史版本可回退 |
| 多版本产物增多 | 存储增长 | 继续使用既有保留策略和版本索引，不覆盖历史版本 |

## 24. 发布与回滚

- 不新增独立功能开关或配置迁移，新行为直接替换现有脑图工作台行为；
- 各环境随应用版本发布生效，不通过 dev/prod 功能开关分流；
- 生产环境实际部署仍需后续单独授权；
- 回滚通过恢复上一版功能智能体镜像，不删除新版草稿和历史文件；
- 回滚不得删除 schema version 2 草稿、确认版本、产物或审计；
- 不改变 API 智能体配置和安全默认值。

## 26. 完成定义

本 PRD 对应功能完成必须同时满足：

- 用户不再遇到“节点能看但点不了、改不了、删不了”的节点类型差异；

- 测试用例步骤不再拆成多个节点；

- 自由脑图草稿、标准 JSON、确认版本和发布产物职责清晰且可恢复；
- 自动化、真实浏览器、权限、安全、性能和历史数据保护全部通过验收。
