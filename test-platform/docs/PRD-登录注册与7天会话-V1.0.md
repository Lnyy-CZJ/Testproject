## 1. 文档摘要

本次改造面向测试开发平台的账号入口，完成以下三项产品调整：

1. 正式交付未登录用户可见、可用、可验收的自助注册功能；
2. 将新设和修改密码的长度规则统一为 6–18 位，不再要求大小写字母、数字或特殊字符组合；
3. 将浏览器登录会话的固定有效期调整为 7 天。除主动退出、会话撤销、用户停用、密码安全操作等事件外，用户在第 7 天到期前不需要重新登录。

平台当前采用服务端 Session，而不是 JWT。浏览器持有 HttpOnly 的 `tp_session` Cookie，服务端数据库只保存 Token 哈希，并支持注销和会话撤销。因此，本文所称“Token 7 天”统一解释为“浏览器服务端 Session 的绝对有效期为 7 天”，不新增 JWT、Refresh Token 或本地 Token 存储。

## 2. 背景与现状

### 2.1 用户侧现状

当前用户感知为平台只有登录入口，缺少可稳定使用的注册能力。新用户无法独立完成账号创建，必须依赖管理员或已有初始化流程。

### 2.2 代码基线

仓库当前代码已存在基础注册链路：

- 前端已有 `/register` 路由、注册表单和登录页注册链接；
- 后端已有 `POST /api/v1/auth/register`；
- 注册成功后会创建 `active` 的 `tester` 用户并直接建立登录会话；
- 后端已有注册角色隔离与基础测试。

因此，本期不是重新设计一套账号系统，而是把已有基础能力按统一规则完善、验证并正式交付。若现网仍没有注册入口，发布前必须核对部署版本、前端静态资源和网关路由是否与当前代码基线一致。

### 2.3 当前规则与目标差距

| 项目 | 当前实现 | 本期目标 |
|---|---|---|
| 注册密码 | 12–256 位 | 6–18 位 |
| 修改密码 | 12–256 位 | 6–18 位 |
| 首次管理员密码 | 12–256 位 | 6–18 位 |
| 登录输入 | 必填，后端允许 1–256 位 | 必填；兼容验证存量密码 |
| Session 空闲有效期 | 8 小时 | 不得导致 7 天内提前退出 |
| Session 绝对有效期 | 24 小时 | 7 天（168 小时） |
| 注册成功行为 | 自动登录并进入工作台 | 保持不变并正式验收 |
| 会话存储 | HttpOnly Cookie + 服务端 Session | 保持不变 |

## 3. 产品目标与成功标准

### 3.1 产品目标

#### G1：新用户可独立完成注册

未登录用户能从登录页进入注册页，创建测试人员账号，并在成功后直接进入工作台。

#### G2：密码规则简单且一致

所有新设置的密码只校验长度 6–18 位，不增加大写字母、数字、特殊字符或字符种类组合要求。

#### G3：登录状态稳定保持 7 天

用户登录或注册成功后，在没有安全事件的情况下，刷新页面、关闭并重新打开浏览器、跨日使用均保持登录，直到登录时间满 7 天。

#### G4：保留现有安全与权限边界

继续使用 Argon2id 密码哈希、服务端可撤销 Session、HttpOnly Cookie、CSRF 双提交、登录限流、固定角色与审计机制，不因延长会话或开放注册降低现有权限边界。

### 3.2 可衡量成功标准

- 登录页存在清晰的“创建测试人员账号”入口，且 `/register` 可直接访问和刷新；
- 合法用户可完成注册，注册结果固定为 `active tester`，不允许选择角色或项目；
- 5 位密码不能用于新账号或改密，6 位与 18 位可以，19 位不可以；
- 新会话的绝对过期时间为创建时间加 168 小时；
- 在第 7 天到期前，用户不会因为原有 8 小时空闲规则被要求重新登录；
- 到期后下一次页面恢复或 API 请求进入登录页，并提示登录状态已失效；
- 主动退出、会话撤销、账号停用等安全操作仍可在 7 天内提前终止会话；
- 前后端自动化测试、登录注册端到端测试及相关回归测试全部通过。

## 4. 范围与边界

### 4.1 本期包含

1. 登录页注册入口与登录表单细节；
2. 注册页面、注册表单、提交状态和错误提示；
3. 自助注册 API 契约与注册后自动登录；
4. 密码长度规则调整；
5. 7 天服务端 Session 与 Cookie 生命周期；
6. 会话到期后的前端跳转和提示；
7. 登录、注册、密码、会话相关文档和自动化测试；
8. 注册、登录和会话安全审计。

### 4.2 本期不包含

- 邮箱、手机号及验证码注册；
- 邮箱验证或实名认证；
- 忘记密码、自助找回密码；
- 第三方账号、企业 SSO 或扫码登录；
- JWT、Refresh Token 或“记住我”开关；
- 用户在注册时选择角色、项目或工具权限；
- 注册审批流、邀请码页面或管理员审核页；`invite` 模式未实现时必须失败关闭，不能退化为开放注册；
- 对现有用户、角色和项目模型进行重构。

## 5. 用户与核心场景

### 5.1 未注册用户

用户访问平台登录页，点击“创建测试人员账号”，填写用户名、显示名称、密码和确认密码。注册成功后自动进入工作台，无需再次登录。

### 5.2 已注册用户

用户输入用户名和密码登录。登录成功后，平台保持 7 天登录状态；用户在其他页面被引导到登录页时，登录成功后回到原站内地址。

### 5.3 会话到期用户

用户在第 7 天到期后打开平台或继续操作，平台判定 Session 无效，跳转登录页并提示“登录状态已过期，请重新登录”。重新登录后恢复正常使用。

### 5.4 安全事件用户

用户主动退出、管理员撤销会话、账号被停用或发生既有密码安全操作时，会话可以在 7 天前失效。此类失效属于安全策略，不视为违反“7 天免登录”。

## 6. 已锁定产品决策

1. 注册入口对未登录用户可见；
2. 注册字段固定为用户名、显示名称、密码和确认密码；
3. 确认密码只在前端校验，不发送给后端；
4. 注册用户固定为 `tester`、`active`、无项目、无额外工具授权；
5. 注册成功立即建立会话并进入工作台；
6. 新设置或修改的密码必须为 6–18 位；
7. 密码不要求大小写、数字或特殊字符组合；
8. 密码不得自动去除首尾空格，用户输入内容按原值参与哈希与校验；
9. 浏览器认证继续使用服务端 Session Cookie，不改为 JWT；
10. 每次新登录或注册创建一个固定 7 天的会话；
11. 活跃操作不会把绝对过期时间延长到第 7 天之后；
12. 不提供“记住我”选项，所有普通浏览器会话统一使用 7 天规则；
13. 登录限流、CSRF、会话撤销、账号停用和审计规则保持有效；
14. 页面关闭、浏览器重启和普通刷新不会主动清除会话。
15. 本期正式交付 `registration_mode=open`，同时保留 `disabled` 关闭能力；`invite` 在邀请码链路另行交付前按 `disabled` 处理；
16. 新注册用户只有一个有效全局角色 `tester`；兼容响应可暂时保留 `roles=["tester"]`，但不得产生多角色、旧角色授权并集或可选角色字段。

## 7. 功能需求

### FR-1：登录页面

1. 页面提供“用户名”和“密码”两个必填字段；
2. 用户名输入使用浏览器 `autocomplete="username"`；
3. 密码输入使用浏览器 `autocomplete="current-password"`；
4. 页面提供清晰的“登录”主按钮和“创建测试人员账号”次入口；
5. 提交期间按钮显示“正在验证…”并禁止重复提交；
6. 登录成功后优先跳转到合法的站内 `next` 地址，否则进入首页；
7. `next` 不得接受协议地址或 `//` 开头的外部跳转；
8. 用户名或密码错误统一提示“用户名或密码错误”，不得区分账号不存在、密码错误或账号状态；
9. 触发登录锁定时提示“登录尝试过多，请稍后再试”，不展示内部限流计数；
10. 登录成功后不得把密码、Session Token 或 CSRF Token写入 `localStorage`、`sessionStorage` 或页面日志。

### FR-2：注册页面

1. 页面标题为“创建测试人员账号”；
2. 页面说明注册账号默认用于测试工作，不展示角色和项目选择；
3. 注册模式行为：
   - `open`：登录页显示注册入口，注册页和注册 API 可用；
   - `disabled`：登录页隐藏注册入口，直达注册页显示“暂未开放注册”，注册 API 返回 503 `REGISTRATION_UNAVAILABLE`；
   - `invite`：本期没有邀请码链路，必须与 `disabled` 一样失败关闭并记录安全事件，不得自动按 `open` 处理；
4. 表单字段为：
   - 用户名：必填，沿用现有 3–128 位规则；
   - 显示名称：必填，沿用现有 1–128 位规则，去除首尾空格后不得为空；
   - 密码：必填，6–18 位；
   - 确认密码：必填，必须与密码完全一致；
5. 表单不得提交 `role`、`platform_role`、`role_ids`、`project_ids`、`tool_ids`、`status` 等权限字段；
6. 服务端继续拒绝所有未知字段，不得静默忽略；
7. 用户名规范化规则保持为去除首尾空格后转小写，并按规范化结果全局唯一；
8. 提交期间按钮显示“正在创建…”并禁止重复提交；
9. 注册失败时保留用户名和显示名称，清空密码与确认密码；所有字段均不得写入持久化存储、日志或埋点；
10. 注册成功返回 HTTP 201，创建登录会话并直接进入首页；
11. 注册完成后由前端继续请求 `GET /api/v1/tools`，目录只返回该用户当前可访问的公共工具；注册响应本身不嵌入工具列表；
12. 注册成功写入 `auth.register` 审计事件，审计不得包含密码或原始 Token；
13. 规范化用户名重复时不得返回可用于确认账号存在的明确信息；统一返回 409 `REGISTRATION_UNAVAILABLE` 和安全提示。

### FR-3：密码规则

1. 注册、用户修改密码、首次管理员初始化、管理员创建用户、管理员重置密码以及首次强制改密时，新密码统一为 6–18 位；
2. 长度由服务端共享校验作为最终判定，前端使用相同边界提前提示；不得在多个入口分别维护不一致的常量；
3. 长度按 Unicode code point 计数，不按 UTF-8 字节数计数；前端计数规则必须与服务端一致；
4. 不设置大写字母、小写字母、数字、特殊字符或字符种类组合要求；
5. 不自动 trim 密码；空格若由用户主动输入，计入密码长度；
6. 继续使用现有 Argon2id 哈希，不保存或回显明文密码；
7. 登录接口只负责验证用户提交的凭据，不以新密码策略提前拒绝存量密码。该兼容规则避免旧密码超过 18 位的账号在发布后被直接锁定；
8. 存量用户下一次主动修改密码或被管理员重置密码时，必须使用 6–18 位新规则；
9. 管理员生成的临时密码必须落在 6–18 位内；`must_change_password` 用户首次改密也必须执行同一规则；
10. 所有密码错误响应不得包含密码原文、哈希、长度或内部校验参数。

### FR-4：7 天会话

1. 新登录或注册成功后创建服务端 Session；
2. Session 绝对有效期固定为 168 小时；
3. Cookie `max_age` 与 Session 绝对有效期一致；
4. 原有 8 小时空闲过期规则不得导致用户在 7 天内提前退出；本期有效行为等价于空闲有效期和绝对有效期均为 168 小时；
5. Session 的绝对过期时间在创建时确定，后续访问不得滚动延长到 168 小时之外；
6. `/auth/me` 继续返回当前会话的绝对过期时间；
7. 浏览器只保存 `tp_session` HttpOnly Cookie 和 `tp_csrf` Cookie，不新增本地 Token；
8. 服务端数据库继续只保存 Session Token 和 CSRF Token 的哈希；
9. 到期 Session 的任何受保护请求返回 401；
10. 前端收到认证失效后清空内存认证态，跳转登录页，并保留安全的站内返回地址；
11. 登录页对会话到期场景显示一次“登录状态已过期，请重新登录”；
12. 到期后必须重新输入用户名和密码，不提供静默刷新或 Refresh Token。

### FR-5：会话提前失效

以下情况允许 Session 在 7 天前失效：

1. 用户主动退出登录；
2. 用户在账号与会话页面撤销指定会话；
3. 管理员撤销用户会话；
4. 用户被停用；
5. 发生现有密码修改、密码重置或其他明确要求撤销会话的安全操作；
6. Session 数据异常、Token 校验失败、CSRF 校验失败或平台安全策略拒绝。

主动退出必须持久化撤销当前 Session，并清除 `tp_session` 与 `tp_csrf` Cookie。不能只清理前端状态。

### FR-6：会话恢复与路由保护

1. 页面首次加载时调用 `/auth/me` 恢复认证状态；
2. 有效会话直接进入目标页面，不显示登录页闪烁；
3. 未登录访问受保护页面时跳转 `/login?next=<原站内地址>`；
4. 登录后返回原站内地址；
5. 无效、撤销或过期会话不得访问任意受保护页面、工具入口或 API；
6. `must_change_password=true` 的既有安全流程保持不变。

### FR-7：注册防滥用与登录安全

1. 保留现有登录失败限流：15 分钟内失败 5 次后锁定 15 分钟；
2. 注册提交按来源 IP、规范化用户名以及可信设备信号分别计数：任一维度 15 分钟内达到 5 次后，第 6 次起返回 429 `REGISTRATION_RATE_LIMITED` 并锁定 15 分钟；
3. 设备信号仅在可信网关能够提供时参与；无法取得时继续使用 IP 与规范化用户名，不能跳过限流；
4. 全局 15 分钟内达到 100 次注册提交时触发 15 分钟熔断，期间返回 503 `REGISTRATION_UNAVAILABLE`，并向运维告警；阈值允许按部署环境收紧，但不得关闭全部保护；
5. 注册限流与熔断同时统计成功和失败提交，不能通过反复更换无效字段绕过；
6. 注册防滥用不得允许客户端选择角色、项目或工具权限；
7. 注册、登录成功与失败均记录不含敏感数据的安全事件；字段校验失败、重复用户名、未知字段、限流和熔断均有可区分的内部事件类型，但对外不泄露账号状态和内部阈值；
8. 注册账号使用公共高成本工具时，仍受每用户配额、成本预算和真实执行安全门禁限制；
9. 生产 Cookie 在 HTTPS 部署下必须启用 `Secure`，并保持 `HttpOnly` 与 `SameSite=Lax`；若现网仍为已接受风险的 HTTP 部署，本期不把 `Secure=true` 作为阻断条件，但必须在发布审批中重新确认 7 天窗口带来的传输风险；
10. 写请求继续使用 `tp_csrf` 与 `X-CSRF-Token` 双提交校验。

## 8. 页面与交互要求

### 8.1 登录页

- 保持现有平台品牌、运行环境标识和双栏布局；
- 注册入口位于登录按钮下方，文案为“创建测试人员账号”；
- 登录错误紧邻密码区域展示，并使用可访问的 `role="alert"` 或等价语义；
- Enter 可提交表单；请求进行中不得重复发送。

### 8.2 注册页

- 复用登录页整体视觉和平台品牌；
- 页面提供“返回登录”入口；
- 密码字段旁显示“6–18 位，不限制字符组合”；
- 当密码少于 6 位、超过 18 位或两次输入不一致时，在提交前给出字段级提示；
- 服务端错误使用统一错误区域展示，不暴露堆栈、数据库信息、限流阈值或账号状态；
- 任意注册失败后清空密码和确认密码，保留可修正的用户名与显示名称；
- 注册成功不显示中间成功页，直接进入工作台。

### 8.3 会话失效提示

- Session 到期或失效后跳转登录页；
- 仅展示一次非阻塞提示，避免每个并发 401 重复弹出；
- 用户重新登录后，若原地址仍为合法站内地址，则返回原地址。

## 9. 接口与数据要求

### 9.1 注册接口

```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "username": "new.tester",
  "display_name": "新测试人员",
  "password": "123456"
}
```

成功：

- HTTP 201；
- 响应为现有 `MeResponse`；
- 设置 `tp_session` 和 `tp_csrf` Cookie；
- `role` 固定为 `tester`；兼容字段如保留，仅允许 `roles=["tester"]`；
- 不写入旧多角色关联或任何项目、额外工具授权；
- 不返回原始 Session Token、CSRF Token、密码或密码哈希。

### 9.2 登录接口

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "new.tester",
  "password": "123456"
}
```

成功：

- HTTP 200；
- 响应为现有 `MeResponse`；
- 设置有效期为 7 天的认证 Cookie；
- 更新用户最后登录时间。

### 9.3 当前用户与会话

- `GET /api/v1/auth/me` 返回用户、角色、权限和 `session_expires_at`；
- `GET /api/v1/auth/sessions` 继续展示当前用户有效会话及绝对过期时间；
- `POST /api/v1/auth/logout` 撤销当前会话；
- `DELETE /api/v1/auth/sessions/{session_id}` 撤销指定会话。

### 9.4 错误语义

| 场景 | HTTP | 稳定语义 | 用户提示 |
|---|---:|---|---|
| 用户名或密码错误 | 401 | `INVALID_CREDENTIALS` | 用户名或密码错误 |
| 登录尝试过多 | 423 | `ACCOUNT_LOCKED` | 登录尝试过多，请稍后再试 |
| Session 无效或到期 | 401 | `AUTH_REQUIRED` | 登录状态已失效，请重新登录 |
| 注册字段不合法 | 422 | 参数校验错误 | 请检查注册信息 |
| 用户名不可用 | 409 | `REGISTRATION_UNAVAILABLE` | 暂时无法创建账号，请更换信息或稍后重试 |
| 注册频率过高 | 429 | `REGISTRATION_RATE_LIMITED` | 操作过于频繁，请稍后重试 |
| 注册关闭或熔断 | 503 | `REGISTRATION_UNAVAILABLE` | 暂未开放注册，请稍后重试 |
| 未知或提权字段 | 422 | 参数校验错误 | 注册信息不合法 |
| CSRF 失败 | 403 | `CSRF_INVALID` | 页面状态已失效，请刷新后重试 |

## 10. 兼容性与迁移

### 10.1 存量密码

密码哈希无法反推出原始长度，发布时不能可靠识别哪些存量账号使用了 18 位以上密码。因此：

- 新注册、新建账号、修改密码和重置密码立即执行 6–18 位规则；
- 登录验证保持对存量密码的兼容，不在鉴权前按新长度拒绝；
- 存量用户下一次改密时切换到新规则；
- 不进行批量密码失效或数据库密码迁移。

### 10.2 存量 Session

Session 的绝对过期时间已写入数据库。发布后：

- 新创建的 Session 使用 7 天有效期；
- 发布前已创建的 Session 保持原过期时间，不批量延长；
- 存量 Session 到期并重新登录后自动获得 7 天会话；
- 不修改数据库表结构，不批量改写现有 Session 记录。

### 10.3 文档一致性

发布时必须同步：

- `README.md` 的 Session 默认值；
- `docs/接口文档.md` 的公开注册接口、密码长度和会话说明；
- 上游账号 PRD 中“当前没有自助注册接口”的过时现状描述；
- 前端提示、后端 `schemas/auth.py`、共享密码校验、`Settings` 默认值、`.env` 示例、部署配置和测试样例。

## 13. 发布与回滚

### 13.1 发布前检查

1. 确认现网前端版本是否包含 `/register` 路由和注册入口；
2. 确认网关允许匿名访问 `/api/v1/auth/register`；
3. 确认前端、API 和后台任务使用同一套 Session 配置；
4. 确认生产 Cookie 的 HTTPS 与 `Secure` 策略；
   - 若继续使用 HTTP，发布审批必须明确接受 7 天 Cookie 的传输风险；
   - 若要求 `Secure=true`，则 HTTPS、反向代理证书和转发协议配置属于发布前置条件；
5. 确认注册限流、审计和公共工具配额生效；
6. 完成自动化测试和浏览器端到端验收。

### 13.2 发布顺序

1. 先发布后端密码规则、Session 配置和兼容接口；
2. 再发布前端表单、提示和会话失效处理；
3. 最后开放并验证注册入口；
4. 观察注册失败率、登录失败率、401 数量和 Session 撤销行为。

### 13.3 回滚要求

- 回滚不得删除已注册用户；
- 已签发的 7 天 Session 不会因仅回滚配置自动缩短；若安全原因要求立即缩短，必须显式撤销或更新相关 Session；
- 紧急批量撤销 Session 必须由具备权限的管理员执行、记录审计，并通过受保护接口确认撤销生效；
- 回滚前端时不得留下可点击但后端不可用的注册入口；
- 密码规则回滚不得使已按 6–11 位新规则创建的账号无法登录。

## 14. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 现网版本与仓库基线不一致 | 用户仍看不到注册入口 | 发布前核对前端产物、路由和 API 版本 |
| 7 天 Cookie 被窃取后的窗口更长 | 账号冒用风险上升 | 强制 HTTPS/Secure、保留撤销、停用、改密和会话管理 |
| 只修改绝对有效期，遗漏空闲有效期 | 用户 8 小时后仍被退出 | 同步调整空闲策略，测试 T+6 天 23 小时 |
| 前后端密码规则不一致 | 页面通过但接口失败 | 服务端为权威，所有入口共享同一 6–18 位规则 |
| 存量长密码被前端拦截 | 老用户无法登录 | 登录验证保留存量兼容，只收紧新设密码 |
| 开放注册被批量滥用 | 账号与外部 API 成本上升 | 注册限流、全局熔断、每用户配额和执行安全门禁 |
| 回滚后 6–11 位账号失效 | 新用户无法登录 | 登录接口不得按旧 12 位下限拒绝已存在密码 |

## 15. 待产品确认项

当前评审稿采用以下推荐口径：

> 6–18 位规则约束“新设置的密码”；登录接口继续兼容存量密码长度。这样既满足新规则，也不会让已经使用 19 位以上密码的账号在发布当天被锁定。

若产品要求登录输入框也必须硬性拒绝 6–18 位之外的输入，则需要在开发前明确接受存量长密码账号无法继续登录，或另行制定全量密码重置方案。
