## 1. 文档目的

本 PRD 定义功能测试智能体从“任务详情中嵌入表格编辑器”升级为“完整测试生成工作台”的产品需求，重点解决以下问题：

1. 当前创建任务、查看生成进度、Review 测试点、Review 测试用例和下载产物的体验较分散，缺少完整测试平台的连续工作流；
2. 测试点和测试用例层级关系在二维表格中不直观，大量模块、功能、场景和用例难以快速扫描；
3. 用户需要在 Web 中直接修改测试点和测试用例，但不希望再直接操作 JSON；
4. 用户希望脑图成为唯一主要编辑入口，同时保留表格作为清晰、稳定的只读检查视图；
5. 改进必须复用现有 JSON 权威数据、草稿 CAS、确认版本、AI 建议、权限、队列和产物发布能力，不能复制第二套任务或 Review 系统。

本 PRD 是交互与产品流程升级，不改变功能智能体的 Prompt 语义、测试生成算法和 API 智能体安全边界。

## 2. 设计判断与参考界面结论

### 2.1 设计判断

目标用户是测试工程师、测试开发和研发负责人；主要任务是创建生成任务、跟踪生成状态、检查层级覆盖、修改测试资产并发布最终产物。本产品是桌面高信息密度工程工作台，不是营销页面。

### 2.2 参考界面的可取之处

从参考截图中提取并采用以下产品模式：

1. **任务是一等对象**：先进入任务列表，再创建、查看、重跑或进入具体任务；
2. **生成过程和结果共用一个工作台**：生成时展示阶段与状态，生成完成后在原位置切换为脑图，不让用户重新寻找入口；
3. **任务头部持续显示上下文**：任务标题、状态、用例数量、当前版本和主要操作稳定存在；
4. **脑图是唯一主要编辑入口**：保存、增删、移动、标记和 AI 操作均围绕脑图展开；
5. **表格作为只读校对视图**：表格适合完整字段扫描，但不承担编辑，避免脑图和表格同时写入导致冲突；
6. **明确的版本感**：用户能知道当前查看的是模型原稿、草稿还是确认版本；
7. **任务创建集中完成**：标题、文档和生成方式在一个弹窗中提交。

### 2.3 不直接照搬的内容

以下内容不从参考界面直接复制：

- 不引入未经定义的“质量 75/B”等评分；本平台使用可解释的错误、警告和覆盖率；
- 不显示无法准确计算的虚假百分比；LLM 阶段使用确定性阶段状态或不确定进度；
- 不提供当前运行时不支持的“暂停”语义；MVP 只保留取消任务；
- 不扩展为 docx、PDF、XLSX 等未批准的需求文档类型；继续遵守现有 `.md/.txt` 和文件大小限制；
- 不复制参考平台的色彩、图标和品牌；继续使用测试平台现有 Apple-inspired 设计 token；
- 不允许脑图与表格同时编辑；表格明确只读。

### 2.4 参考界面可见风险及本产品修正

| 参考界面可见风险 | 本产品要求 |
|---|---|
| 脑图节点密集，长文本容易重叠 | 自动折行、节点摘要、选中后详情面板、最大可见节点保护 |
| 低对比度灰色文字和细小控件 | 满足 WCAG AA，对主要操作保持清晰文字标签和足够点击区域 |
| 状态主要依赖颜色 | 状态必须同时显示文字、图标或形状 |
| 生成百分比可能缺乏可验证依据 | 只展示真实阶段和已完成数量，不伪造 LLM 精确进度 |
| 表格单元格文本过长、扫描困难 | 固定表头、合理列宽、截断后详情查看、分页和筛选 |
| 脑图工具栏操作较多 | 按“编辑、视图、校验、AI”分组，低频操作收入更多菜单 |

## 3. 产品目标与成功标准

### 3.1 总体目标

建立一个具有完整测试平台感的功能测试生成工作台，使用户在单一任务上下文中完成：

```text
新建任务
→ 观察需求解析与测试点生成阶段
→ 脑图 Review 测试点
→ 确认并生成测试用例
→ 脑图 Review 测试用例
→ 确认并发布 JSON/XLSX
```

### 3.2 成功标准

- 普通用户完成主流程时不需要下载或手工编辑 JSON；
- 测试点和测试用例均可在脑图中完成新增、修改、复制、移动和删除；
- 脑图修改实时同步到旁边的只读表格预览，但只有显式保存后才写入服务端；
- 表格不包含可编辑输入控件，不产生第二份浏览器编辑状态；
- 用户在所有阶段都能看到任务状态、当前版本、未保存状态和下一步操作；
- 正式生成或发布仍只读取不可变确认版本；
- AI 仍只产生建议，应用建议后也必须由用户显式保存和确认；
- 现有 Review API、JSON 文件协议、CAS、权限、FIFO 和产物发布保持兼容；
- 回退新工作台后，现有表格 Review 和 JSON 高级流程仍可使用。

### 3.3 建议量化指标

上线后按不记录业务正文的方式统计：

| 指标 | 目标 |
|---|---:|
| 使用 Web 完成 Review 的任务占比 | ≥ 90% |
| 主流程中下载再上传 JSON 的任务占比 | ≤ 10% |
| 从进入 Review 到首次有效保存的中位时长 | 较现有流程下降 ≥ 25% |
| 因不知道下一步而退出任务详情的比例 | ≤ 5% |
| 草稿保存成功率 | ≥ 99.5% |
| 确认发布幂等成功率 | 100% |
| 脑图与只读表格内容一致率 | 100% |
| 因切换视图导致的未保存数据丢失 | 0 |

## 4. 用户与核心场景

### 4.1 目标用户

- **测试工程师**：创建任务、调整测试点和用例、发布最终产物；
- **测试开发**：检查结构、覆盖、版本和模型信息，处理复杂 Review；
- **测试负责人**：查看任务结果、覆盖缺口和确认版本；
- **平台管理员**：跨用户查看、排障、取消任务和配置功能开关；
- **只读用户**：查看任务、脑图、只读表格和已发布产物，不可修改。

### 4.2 核心用户故事

1. 作为测试工程师，我希望从任务列表点击“新建生成任务”，上传需求并立即看到任务进入队列；
2. 作为测试工程师，我希望在同一个页面看到需求解析、测试点生成和用例生成的实际阶段（log中其实已经有各个步骤阶段的打印了）；
3. 作为测试工程师，我希望通过脑图理解模块、功能、场景、测试点和用例之间的层级关系；
4. 作为测试工程师，我希望直接修改脑图节点，并让只读表格立即反映当前未保存内容；
5. 作为测试工程师，我希望拖动或使用键盘移动节点时，系统明确告诉我哪些业务字段会改变；
6. 作为测试工程师，我希望使用 AI 补充或改写当前节点/子树，但 AI 不能自动覆盖我的草稿；
7. 作为测试负责人，我希望切换原稿、草稿和确认版本，并准确知道当前查看的版本；
8. 作为只读用户，我希望可以展开脑图和查看表格，但所有写操作都不可见或禁用；
9. 作为管理员，我希望继续遵守所有权和跨用户查看权限，不因脑图前端而绕过服务端校验。

## 6. 产品原则与关键决策

### 6.1 JSON 仍是唯一权威格式

脑图不是新的业务数据格式。页面加载时将现有 JSON 投影为树，保存时将树规范化回现有 JSON。只读表格直接读取同一份浏览器内规范化数据。

```text
服务端 Review JSON
        ↓
浏览器规范化数据模型
   ↙            ↘
脑图编辑视图      只读表格视图
        ↓
现有 PUT 草稿 API
```

不允许形成“脑图数据、表格数据、JSON 数据”三份独立状态。

### 6.2 脑图是唯一编辑入口

- 修改节点文本可以使用节点内快捷编辑或右侧详情面板；
- 复杂字段只能在选中节点详情面板编辑；
- 表格没有输入框、下拉框、拖拽或批量修改能力；
- JSON 上传只作为高级兼容入口，导入后必须回到脑图检查；
- 所有编辑最终仍通过服务端 Review Schema 校验。

### 6.3 显式保存，不自动保存

沿用现有评审决策：脑图修改只存在浏览器内，用户点击“保存脑图”才写入草稿。切换脑图/表格不会保存；离开存在未保存内容的页面必须提示。

### 6.4 层级移动必须有明确业务语义

脑图不是任意图编辑器。拖拽、移动和新增只能遵守固定层级。移动导致批量字段变化时，必须在操作前显示影响数量和字段摘要。

### 6.5 只读表格展示当前视图数据

表格默认展示当前浏览器内数据，包括尚未保存的脑图修改，并显示“未保存预览”标识。用户可切换查看服务端已保存草稿，但不能在表格中修改。

### 6.6 AI 只产生建议

AI 建议以临时节点或差异面板呈现，默认不选中。用户应用建议后仅改变浏览器内数据，仍需“保存脑图”和后续确认。

### 6.7 不伪造生成进度

- 已知阶段使用“等待中、执行中、已完成、失败”；
- 可计数阶段可展示“已生成 N 条”；
- LLM 调用中不展示虚假的线性百分比；
- 若后端没有真实进度数据，使用不确定进度条和当前阶段文案。

### 6.8 复用现有 Review 事务和状态机

本期只新增 UI 投影与任务工作台，不改变以下约束：

- 草稿使用 `revision + sha256` CAS；
- 确认版本不可变；
- 相同 SHA 确认幂等；
- 测试点确认继续重新进入 FIFO；
- AI Review 与正式生成共享 FIFO；
- 正式用例生成只读取确认测试点版本；
- 最终 JSON/XLSX 只从确认用例版本发布。

## 7. 总体信息架构

### 7.1 一级页面

```text
功能测试智能体
├── 任务列表
├── 新建任务弹窗
└── 任务工作台
    ├── 生成进度
    ├── 测试点 Review
    │   ├── 脑图（编辑）
    │   └── 表格（只读）
    ├── 测试用例 Review
    │   ├── 脑图（编辑）
    │   └── 表格（只读）
    ├── AI 建议面板
    ├── 产物与版本
    └── 日志与技术信息
```

### 7.2 推荐路由

```text
/functional-test-agent/tasks
/functional-test-agent/tasks/{task_id}
/functional-test-agent/tasks/{task_id}?stage=test-points&view=mindmap
/functional-test-agent/tasks/{task_id}?stage=test-cases&view=mindmap
```

`stage` 和 `view` 只决定页面展示，不允许绕过服务端任务状态。无权访问与不存在任务继续统一返回 404。

### 7.3 工作台稳定布局

工作台由五个稳定区域构成：

1. **任务头部**：返回、标题、状态、任务 ID 摘要、数量、版本、模型、主要操作；
2. **阶段导航**：需求解析、测试点生成、测试点 Review、用例生成、用例 Review、已发布；
3. **工作区标签**：脑图、表格、产物、日志；
4. **主要内容区**：生成状态、脑图画布或只读表格；
5. **底部/悬浮操作区**：保存脑图、确认继续/确认发布，位置保持稳定。

任务状态变化不能造成主操作在页面不同位置跳动。

## 8. 任务列表需求

### 8.1 页面目标

任务列表是功能测试智能体的默认入口，必须让用户快速判断“有哪些任务、当前状态、生成了什么、下一步能做什么”。

### 8.2 顶部区域

- 页面标题：“功能测试用例生成”；
- 右上角唯一主按钮：“新建生成任务”；
- 可折叠“使用说明”，默认收起；
- 搜索框支持标题、任务 ID、文件名；
- 状态筛选：全部、排队中、生成中、待测试点 Review、待用例 Review、已完成、失败、已取消；
- 时间筛选：最近 7 天、30 天、全部；
- 查询按钮与清除筛选。

### 8.3 列表字段

| 字段 | 说明 |
|---|---|
| 任务 ID | 显示短 ID，支持复制完整 ID |
| 标题 | 用户填写的任务标题 |
| 需求文档 | 安全文件名，过期时显示“已过期” |
| 当前阶段/状态 | 文本 + 图标，不只用颜色 |
| 测试点数 | 未生成时显示 `—` |
| 用例数 | 未生成时显示 `—` |
| 校验/覆盖 | 错误数、警告数或覆盖摘要，不显示黑盒质量分 |
| 发起人 | 普通用户只看到自己的任务 |
| 使用模型 | 展示记录的模型版本 |
| 版本 | 最近确认版本，如 `TP v2 / TC v1` |
| 创建时间 | 使用平台统一时区与格式 |
| 操作 | 查看；符合条件时显示取消、复制重跑 |

### 8.4 行为要求

- 点击行或“查看”进入任务工作台；
- “复制重跑”只复制标题和安全的普通配置，不复制旧任务草稿、Secret 或历史文件路径；
- `running/pending` 可按权限取消；
- MVP 不提供删除任务；
- 空态提供“新建生成任务”；
- 错误态提供重试加载，不把 API 异常详情直接展示给用户；
- 默认按 `created_at` 倒序，分页由服务端完成。

## 9. 新建任务弹窗

### 9.1 字段

| 字段 | 必填 | 规则 |
|---|---:|---|
| 标题 | 是 | 1～100 字符；默认可取文件名但允许修改 |
| 需求文档 | 是 | `.md/.txt`；沿用单文件 5 MiB、UTF-8 和字符数限制 |
| 操作模式 | 是 | 默认“完整流程”；可选择生成测试点、直接生成用例等现有 operation |
| 补充说明 | 否 | 沿用当前说明字符限制；必须实际传给现有 Runner |

模型、Prompt、队列上限和覆盖矩阵等由已发布平台配置决定，普通用户不在弹窗中切换生产环境或 Secret。

### 9.2 交互

- 支持点击选择和拖放文件；
- 拖放区域显示支持类型、大小和 UTF-8 要求；
- 文件校验失败在对应字段下显示可操作原因；
- 提交期间禁用重复提交；
- 成功创建返回任务工作台，不停留在列表；
- 队列满时保留用户填写内容，显示当前等待上限和稍后重试；
- 弹窗关闭前若已填写内容必须确认。

### 9.3 明确不提供

- 不让普通用户选择并发数；
- 不让普通用户选择 dev/prod；
- 不在本期增加“模型卡”；
- 不因参考界面而扩展文件类型或大小。

## 10. 生成工作台与任务状态

### 10.1 生成中布局

当任务为 `pending/running` 时：

- 左侧或顶部阶段栏展示当前阶段；
- 主区域展示当前状态、已完成数量和下一阶段；
- 脑图标签可以展示空态：“生成完成后可在此 Review”；
- 日志摘要只展示脱敏业务阶段，不展示 Prompt、Secret、绝对路径和 traceback；
- 右上角仅提供“取消任务”，不提供暂停；
- 任务完成一个阶段后原地刷新，不跳转到新的详情页。

### 10.2 阶段定义

| 阶段 | 典型状态 | 页面表现 |
|---|---|---|
| 等待执行 | `pending` | 显示队列位置（可准确计算时） |
| 读取需求 | `running/reading_requirement` | 不确定进度 |
| 需求拆解 | `running/decomposing_requirement` | 显示已处理片段数（后端可提供时） |
| 生成测试点 | `running/generating_test_points` | 显示已生成条数（后端可提供时） |
| 测试点 Review | `waiting_review` | 默认打开测试点脑图 |
| 生成用例 | `running/generating_test_cases` | 展示批次或已生成条数（后端可提供时） |
| 用例 Review | `waiting_case_review` | 默认打开用例脑图 |
| 已发布 | `succeeded` | 默认打开确认版本与下载操作 |
| 失败/取消 | `failed/cancelled` | 显示稳定错误摘要和可用恢复操作 |

### 10.3 状态刷新

- 复用现有短轮询；不引入 WebSocket/SSE；
- 页面不可见时降低轮询频率；
- 状态变更后使用 `aria-live` 文本提示；
- 网络断开时保留当前页面并显示“状态可能已过期”；
- 恢复网络后先重新读取任务状态，再允许写操作。

## 11. 测试点脑图数据映射

### 11.1 固定层级

```text
任务根节点（只读）
└── 模块 module
    └── 功能 feature
        └── 场景 scenario
            └── 测试点 test_point
```

测试点叶子附加显示：

- `id`；
- `risk_level`；
- 错误/警告；
- 新增、修改或删除状态；
- AI 建议状态。

### 11.2 聚合与展开

- 相同模块、功能、场景在脑图中聚合为一个父节点；
- 聚合只影响展示，不改变平面 JSON 条目；
- 重命名父节点相当于批量修改全部后代对应字段；
- 删除父节点相当于删除全部后代测试点，必须显示数量并确认；
- 复制父节点会生成对应后代的新测试点 ID，并立即触发重复校验提示；
- 空父节点不允许保存；删除最后一个子节点后自动删除空父节点。

### 11.3 允许的层级操作

| 当前节点 | 可新增子节点 | 可移动到 | 说明 |
|---|---|---|---|
| 根 | 模块 | 不可移动 | 根节点只读 |
| 模块 | 功能 | 根下 | 更新后代 `module` |
| 功能 | 场景 | 任一模块下 | 更新后代 `module/feature` |
| 场景 | 测试点 | 任一功能下 | 更新后代上下文 |
| 测试点 | 无 | 任一场景下 | 更新该条目的上下文字段 |

不允许跨越层级，例如把测试点直接移动到模块下。

## 12. 测试用例脑图数据映射

### 12.1 固定层级

```text
任务根节点（只读）
└── 模块 module
    └── 功能 feature
        └── 测试点 test_point_id（来自已确认测试点）
            └── 测试用例 case
```

用例节点摘要显示：

- `case_id`；
- `case_name`；
- `priority`；
- 步骤数量；
- 错误/警告；
- 新增、修改或删除状态。

前置条件、步骤、测试数据、预期结果和扩展字段不全部展开为脑图子节点，避免画布失控；选中用例后在详情面板编辑。

### 12.2 测试点节点约束

- 测试点节点来自不可变确认测试点版本；
- 不允许在用例 Review 中新增、重命名或删除测试点节点；
- 无用例的测试点仍显示，并标记“未覆盖”；
- 把用例移动到另一测试点节点时，更新 `test_point_id`；
- `module/feature/scenario` 按目标测试点上下文同步更新；
- 移动前展示字段变化摘要；
- 所有确认测试点至少有一条有效用例，否则阻塞发布。

### 12.3 用例详情面板

选中用例节点后提供：

- Case ID；
- 来源 Test Point ID（可选择）；
- 模块、功能、场景（由来源测试点派生时显示说明）；
- 用例名称；
- 优先级；
- 前置条件列表；
- 测试步骤列表；
- 测试数据：结构化 JSON/纯文本；
- 预期结果；
- `actual_result` 只读；
- 扩展字段只读摘要。

步骤支持新增、删除、上移、下移和多行粘贴；不得只提供拖拽排序。

## 13. 脑图工作区详细需求

### 13.1 默认视图

- 进入 `waiting_review` 默认打开测试点脑图；
- 进入 `waiting_case_review` 默认打开测试用例脑图；
- 已完成任务默认打开最近确认版本的脑图只读视图；
- 初次打开自动定位根节点并适配画布；
- 默认折叠深层节点，避免一次渲染全部数据。

### 13.2 顶部摘要

显示：

- 当前资源：测试点/测试用例；
- 当前来源：模型原稿/草稿/确认版本；
- revision、SHA 短值和保存时间；
- 总数、新增、修改、删除；
- 错误和警告；
- 用例 Review 增加覆盖数量；
- 未保存状态。

### 13.3 工具栏

工具栏按以下分组：

**编辑**

- 新增子节点；
- 新增同级节点；
- 复制；
- 删除；
- 撤销/重做；
- 备注/详情。

**状态与质量**

- 风险/优先级；
- 只看错误；
- 只看警告；
- 只看已修改；
- 只看未覆盖（用例）。

**视图**

- 全部展开；
- 全部折叠；
- 放大、缩小、适配画布；
- 搜索；
- 主题仅沿用平台浅色/深色，不提供任意主题颜色。

**AI**

- AI 补充当前范围；
- AI 改写选中节点；
- 按说明生成。

保存与确认不混在工具栏中，固定放在稳定的主操作区。

### 13.4 节点编辑

- 双击节点或按 `Enter` 进入快捷文本编辑；
- `Escape` 取消本次快捷编辑；
- `Tab/Shift+Tab` 在可编辑字段之间移动；
- 节点复杂字段通过详情面板编辑；
- 保存前保留用户输入大小写，仅执行现有规范化；
- 节点文本使用纯文本渲染，不能解释 HTML；
- 长文本在节点中显示摘要，悬停或详情面板查看完整内容。

### 13.5 移动节点

支持鼠标拖拽和键盘“移动到……”操作。

移动时：

1. 只高亮合法目标；
2. 非法层级不能放置，并说明原因；
3. 批量影响超过 1 条时显示确认；
4. 移动后立即运行客户端校验；
5. 只修改浏览器内数据，不自动保存；
6. 只读用户不能拖动节点。

### 13.6 删除与撤销

- 删除单个叶子节点可直接执行，并提供撤销；
- 删除父节点或超过 1 条数据必须确认数量和影响；
- 浏览器内保留最多 50 步撤销/重做；
- 撤销历史不跨刷新持久化；
- 成功保存后保留当前会话撤销历史，但明确标记保存点；
- 重载服务端版本后清空撤销历史。

### 13.7 搜索与定位

- 搜索测试点 ID、Case ID、模块、功能、场景、名称和正文；
- 结果显示数量与上一个/下一个；
- 定位结果时自动展开祖先节点；
- 清除搜索后恢复用户原折叠状态；
- 从错误摘要或只读表格点击条目可切回脑图并定位节点。

### 13.8 大数据保护

- 数据总量沿用测试点 5,000 条、测试用例 2,000 条限制；
- 页面不能一次创建全部展开节点；
- 同时可见节点建议不超过 500 个；
- 用户尝试展开超过上限时提示先筛选或折叠，不静默截断数据；
- 脑图只渲染已展开分支；
- 表格只渲染当前页；
- 切换视图不重新复制完整业务对象。

## 14. 只读表格需求

### 14.1 产品定位

表格用于核对字段、筛选、排序和快速扫描，不是编辑器。标签名称必须为“表格 · 只读”，并在表格顶部显示说明：“如需修改，请返回脑图”。

### 14.2 数据一致性

- 表格和脑图读取同一浏览器内规范化对象；
- 脑图修改后表格立即更新；
- 未保存时显示“未保存预览”；
- 用户可选择查看“当前预览”或“已保存草稿”；
- 表格与脑图的数量、错误、警告和覆盖摘要必须一致；
- 切换标签不触发保存和服务端写请求。

### 14.3 测试点表格列

| 列 | 说明 |
|---|---|
| ID | 测试点 ID |
| 模块 | module |
| 功能 | feature |
| 场景 | scenario |
| 测试点 | test_point |
| 风险 | risk_level |
| 状态 | 新增、修改、错误、警告等 |

### 14.4 测试用例表格列

| 列 | 说明 |
|---|---|
| Case ID | 用例 ID |
| Test Point ID | 来源测试点 |
| 模块/功能 | 业务上下文 |
| 用例名称 | case_name |
| 优先级 | priority |
| 前置条件 | 只读多行摘要 |
| 步骤 | 编号展示 |
| 测试数据 | 安全文本摘要 |
| 预期结果 | expected_result |
| 状态 | 新增、修改、错误、警告 |

### 14.5 表格行为

- 支持关键字、模块、功能、风险/优先级、错误、警告、修改状态筛选；
- 支持固定表头；
- 测试点每页 50/100/200；
- 测试用例每页 25/50/100；
- 允许复制单元格文本，不允许粘贴修改；
- 点击行的“在脑图定位”切回脑图并选中对应节点；
- 所有字段使用文本或安全格式化内容，不渲染用户 HTML；
- 表格中不出现输入框、`contenteditable`、下拉编辑或拖拽手柄。

## 15. 版本、草稿与确认

### 15.1 版本选择器

任务头部版本选择器支持：

- 模型原稿；
- 当前草稿 revision；
- 已确认版本 `vN`；
- 已发布最终版本。

只有当前草稿可编辑。原稿、确认版本和已发布版本均为只读。切换版本前存在未保存修改时必须确认。

### 15.2 保存脑图

“保存脑图”实际调用现有草稿保存接口：

1. 浏览器将树规范化为现有平面 JSON；
2. 携带当前 `revision + sha256`；
3. 服务端执行完整 Schema、大小、重复、引用和覆盖校验；
4. 原子覆盖草稿文件；
5. 返回新 revision、SHA、保存时间和校验结果；
6. 页面更新保存点但不进入队列、不确认版本。

草稿允许存在业务错误，但页面必须显示“不可确认”。

### 15.3 CAS 冲突

发生冲突时：

- 不覆盖服务端草稿；
- 不丢弃浏览器内脑图；
- 禁止继续保存直到用户选择处理方式；
- 提供“下载本地 JSON”“重新加载服务端版本”；
- 本期不提供自动合并或三方合并。

### 15.4 测试点确认继续

沿用现有流程：

```text
waiting_review
→ 创建/复用不可变确认测试点版本
→ pending（重新进入 FIFO）
→ running/generating_test_cases
```

队列满时确认文件和草稿保留，任务仍为 `waiting_review`。

### 15.5 测试用例确认发布

沿用现有流程：

```text
waiting_case_review
→ 创建/复用不可变确认用例版本
→ 同源发布 JSON/XLSX
→ succeeded
```

确认不重新调用 LLM。JSON 或 XLSX 任一发布失败时不得登记半成品，不得把任务标记成功。

## 16. 校验、覆盖和错误定位

### 16.1 规则来源

所有阻塞错误和警告继续使用现有测试点 Review、测试用例 Review 服务端规则。本期不新定义一套脑图专用业务校验。

### 16.2 脑图表达

- 节点右侧显示错误/警告数量；
- 有问题的折叠父节点显示后代问题汇总；
- 点击问题自动展开祖先并定位具体节点；
- 错误使用图标、文字和边框，不只使用红色；
- 画布顶部显示错误、警告、未覆盖总数；
- 确认时再次执行服务端完整校验。

### 16.3 用例覆盖

用例脑图中：

- 已覆盖测试点显示用例数量；
- 未覆盖测试点显示明确标记；
- 点击“未覆盖”筛选只保留相关分支；
- 测试点无有效用例时阻塞最终发布；
- 删除或移动用例后实时重新计算浏览器端覆盖摘要；
- 服务端覆盖结果为最终依据。

### 16.4 修改摘要

持续显示相对模型原稿的：

- 新增；
- 修改；
- 删除；
- 未修改；
- 风险/优先级变化；
- 引用变化；
- 错误、警告和覆盖缺口。

本期不要求逐字符全树差异和版本合并。

## 17. AI 辅助 Review 在脑图中的交互

### 17.1 支持操作

沿用现有三种操作：

1. `supplement`：补充当前任务或当前合法子树；
2. `rewrite_selected`：改写选中的测试点或用例；
3. `generate_from_instruction`：根据说明生成新增建议。

### 17.2 作用域

- 未选择节点时作用于整个已保存草稿；
- 选择模块/功能/场景时，作用于对应后代测试点；
- 选择测试点时，可补充该范围测试点，或在用例阶段补充对应测试用例；
- 选择用例时，只允许改写选中用例；
- 超过现有选择和上下文上限时整体拒绝，不静默截断。

### 17.3 发起条件

- 必须先保存当前脑图；
- AI 请求绑定已保存的 revision/SHA；
- 存在未保存修改时，页面提示先保存，不自动代替用户保存；
- 继续使用现有 `review_ai/case_review_ai` execution kind 和共享 FIFO；
- AI 关闭时人工脑图 Review 不受影响。

### 17.4 建议展示

- 新增建议以虚线临时节点显示；
- 替换建议在右侧差异面板展示原值和建议值；
- 建议默认不选中；
- 用户可逐条或按合法子树选择应用；
- 应用建议只改变浏览器内数据；
- 草稿 revision 已变化时建议标记“基准已过期”，禁止直接应用；
- 不展示模型原始响应、Prompt 全文或内部异常。

### 17.5 AI 失败与取消

- 排队和运行状态在任务头部及 AI 面板显示；
- 取消 AI 需要 `task.cancel`；
- AI 失败、取消、超时和重启中断都返回原 Review 状态；
- 失败不能清空脑图草稿、原稿、确认版本和 artifact registry；
- 用户可以继续人工编辑、保存和确认。

## 18. HTTP API 与兼容策略

### 18.1 原则

脑图视图优先复用现有 API，不为树形结构新增第二套写接口。树与平面 JSON 的转换在前端完成，服务端仍只接受现有权威 Schema。

### 18.2 复用接口

测试点 Review：

```text
GET  /api/v1/tasks/{id}/review
PUT  /api/v1/tasks/{id}/review-draft
POST /api/v1/tasks/{id}/review-draft/import
GET  /api/v1/tasks/{id}/review/download
POST /api/v1/tasks/{id}/resume
POST /api/v1/tasks/{id}/review-ai
GET  /api/v1/tasks/{id}/review-ai
POST /api/v1/tasks/{id}/review-ai/cancel
```

测试用例 Review：

```text
GET  /api/v1/tasks/{id}/case-review
PUT  /api/v1/tasks/{id}/case-review-draft
POST /api/v1/tasks/{id}/case-review-draft/import
GET  /api/v1/tasks/{id}/case-review/download
POST /api/v1/tasks/{id}/case-review/confirm
POST /api/v1/tasks/{id}/case-review-ai
GET  /api/v1/tasks/{id}/case-review-ai
POST /api/v1/tasks/{id}/case-review-ai/cancel
```

任务创建、列表、详情、日志、取消和 artifact 接口继续复用现有 `/api/v1/tasks` 协议。

### 18.3 最小响应扩展

详细设计阶段允许在现有任务详情或 Review 响应中增加以下白名单字段：

```json
{
  "ui_capabilities": {
    "workbench_v2": true,
    "mindmap_edit": true,
    "table_readonly": true
  },
  "progress": {
    "stage": "generating_test_points",
    "completed_items": 12,
    "total_items": null
  }
}
```

`progress` 只能来源于真实 Runner 状态；未知总数必须为 `null`，不能推算虚假百分比。

### 18.4 错误响应

沿用稳定错误结构，只允许返回：

- `code`；
- 中文 `message`；
- `request_id`；
- 白名单化 revision、SHA、容量、字段和节点 ID；
- 不返回正文、绝对路径、Prompt、Secret、traceback 或异常对象。

## 19. 文件、数据库与配置

### 19.1 文件协议

不新增脑图权威文件。继续使用：

```text
input/review-draft.json
input/review-test-points-vN.json
input/review-ai/suggestions-vN.json
input/case-review-draft.json
input/review-test-cases-vN.json
input/case-review-ai/suggestions-vN.json
published/test-cases/vN/test-cases.json

```

折叠状态、缩放和当前选中节点属于用户界面偏好，可保存在浏览器 `localStorage`，键必须包含环境、用户和任务 ID；不得作为业务事实，也不得影响服务端保存内容。

### 19.2 数据库

- 不新增测试点、用例或脑图业务表；
- 不把节点坐标、连线或画布状态写入平台数据库；
- 平台数据库只增加必要的配置定义；
- 审计继续使用现有审计能力，不记录节点正文。

### 19.3 功能开关

建议新增一个统一开关：

```text
FUNCTIONAL_WORKBENCH_V2_ENABLED=false
```

行为：

- `false`：回退现有任务详情和结构化 Review 工作台；
- `true`：启用任务列表升级、统一工作台和脑图主编辑入口；
- 测试点脑图编辑仍受 `ONLINE_REVIEW_ENABLED` 控制；
- 测试点 AI 仍受 `REVIEW_AI_ENABLED` 控制；
- 用例脑图编辑仍受 `ONLINE_CASE_REVIEW_ENABLED` 控制；
- 用例 AI 仍受 `CASE_REVIEW_AI_ENABLED` 控制。

建议新增配置迁移接在当前 `20260814_0012` 之后；具体 revision 由开发设计基于实际 Alembic head 确认。dev 验收后开启，prod 首次发布保持关闭。

## 20. 权限、安全与审计

### 20.1 权限

| 行为 | 权限与条件 |
|---|---|
| 查看任务、脑图、表格 | `tool.result.view` + 所有权，或 `task.view.all` |
| 创建任务 | `tool.execute` |
| 编辑脑图、保存、导入、确认 | `tool.execute` + 所有权 |
| 发起 AI | `tool.execute` + 所有权 |
| 取消任务或 AI | `task.cancel` + 所有权，或管理员规则 |
| 跨用户查看 | `task.view.all` |

越权和不存在任务统一返回 404。前端隐藏按钮不能替代服务端权限校验。

### 20.2 写请求安全

- 所有写请求执行可信身份、CSRF、RBAC、所有权和状态检查；
- 节点正文使用文本渲染，禁止 `innerHTML` 注入；
- JSON 使用安全解析，不使用 `eval`、`Function` 或动态脚本；
- 下载只接受固定资源和版本枚举，不接受客户端路径；
- 脑图移动和删除必须在服务端保存时重新验证引用和覆盖；
- localStorage 不存 Prompt、Secret、需求正文或完整草稿；
- 普通用户页面只展示模型、Prompt SHA、Release 和应用版本。

### 20.3 审计事件

建议增加或复用：

```text
functional_task.created
functional_task.cancelled
test_point_mindmap.draft_saved
test_point_mindmap.confirmed
test_case_mindmap.draft_saved
test_case_mindmap.confirmed
mindmap_ai.requested
mindmap_ai.cancelled
mindmap_ai.suggestion_applied
```

审计只记录任务 ID、用户、资源类型、revision、SHA、数量、操作类型、模型、Prompt SHA、结果和稳定错误码，不记录测试正文或 Secret。

## 21. 视觉与交互规范

### 21.1 总体基调

- 面向桌面工程师，默认视口宽度 ≥ 1280px；
- 页面背景、文字、强调色、圆角和阴影沿用现有平台 token；
- 主体使用白色/近白背景、中性色文字和系统蓝强调；
- 避免紫色渐变、发光、卡片墙和大面积毛玻璃；
- 卡片只用于真实分组，工作台主体优先使用分隔线和留白；
- 使用 8px 间距网格和系统字体栈。

### 21.2 层级与操作

信息顺序固定为：

```text
当前状态
→ 下一步操作
→ 错误/覆盖摘要
→ 脑图或表格内容
→ 产物、日志和技术细节
```

页面只能有一个主按钮：生成阶段为取消；测试点 Review 为“确认并生成用例”；用例 Review 为“确认并发布”。“保存脑图”为次主操作。

### 21.3 脑图视觉

- 根、分组、叶子和临时 AI 建议使用不同形状或边框，不只使用颜色；
- 连接线颜色克制，不能干扰文字；
- 节点宽度有上下限，长文本折行并显示摘要；
- 选中节点、键盘焦点和拖拽目标必须可区分；
- 错误和警告标记位置稳定；
- 缩放后文字不得小于可读下限；
- 不使用 emoji 作为业务图标。

### 21.4 只读表格视觉

- 标签直接标注“只读”；
- 固定表头，正文保持可扫描行高；
- 长文本截断但可查看完整内容；
- 行状态用文字和图标表达；
- 表格不伪装成可编辑控件。

## 23. 非功能需求

### 23.1 性能

| 场景 | 目标 |
|---|---:|
| 100 条测试点/用例首次可交互 | ≤ 2 秒 |
| 500 条数据搜索/筛选反馈 | ≤ 300 毫秒 |
| 500 个可见脑图节点平移/缩放反馈 | P95 ≤ 100 毫秒 |
| 5,000 测试点树构建 | ≤ 2 秒，不一次展开全部 |
| 2,000 用例树构建 | ≤ 2 秒，不一次展开全部 |
| 脑图切换只读表格 | ≤ 300 毫秒 |
| 服务端完整校验 | 沿用现有 ≤ 2 秒目标 |

不得为达到指标而静默丢弃节点、截断业务数据或降低服务端校验。

### 23.2 可靠性

- 脑图与表格必须基于同一内存对象；
- 保存失败不清空浏览器内修改；
- 页面刷新后从服务端草稿恢复；
- 网络恢复后必须重新校验 revision；
- 确认与发布继续使用原子写入和幂等键；
- 浏览器崩溃不会破坏已保存草稿；
- 服务重启恢复行为沿用现有任务运行时；
- 功能工作台异常不能影响 API 智能体。

### 23.3 兼容性

- 桌面 Chrome、Edge、Safari 当前支持版本；
- 1280×800、1440×900、1920×1080 验收；
- 不要求移动端；
- 功能开关关闭时完整回退当前界面；
- 旧任务可从现有 artifact 初始化脑图；
- 旧 JSON 上传/下载继续保留至少一个发布周期；
- 原 CLI 和历史 `output/` 不受影响。

### 23.4 可观测性

- 记录页面加载失败、树构建失败、保存冲突和确认失败的稳定错误码；
- 记录性能耗时和数量，不记录节点正文；
- 客户端异常上报必须脱敏任务内容；
- readiness 可返回工作台功能开关布尔值，不返回配置正文或 Secret。

## 24. 验收标准

### 24.1 任务列表与创建

- 用户能搜索和筛选任务；
- 列表明确区分排队、生成、两类 Review、完成、失败和取消；
- 新建任务弹窗完成标题、文档、操作和补充说明校验；
- 重复提交被阻止；
- 创建成功直接进入工作台；
- 队列满时输入不丢失；
- 只读用户不能创建任务。

### 24.2 生成过程

- 页面展示真实阶段，不展示虚假精确百分比；
- 状态变化在原工作台内更新；
- 取消遵守权限并终止任务；
- 失败显示稳定错误和可用恢复方式；
- 测试点完成后自动进入测试点脑图；
- 用例完成后自动进入用例脑图。

### 24.3 测试点脑图

- JSON 正确投影为模块/功能/场景/测试点层级；
- 可新增、编辑、复制、删除和合法移动节点；
- 父节点重命名和删除准确影响后代；
- 非法层级移动被阻止；
- 风险、错误、警告和修改状态清晰；
- 保存调用现有 CAS 草稿协议；
- 确认后重新进入 FIFO；
- 队列满时确认版本不重复且草稿不丢失。

### 24.4 测试用例脑图

- 已确认测试点准确投影为不可编辑测试点节点；
- 无用例测试点显示未覆盖；
- 可新增、编辑、复制、删除和移动用例；
- 移动用例准确更新引用和上下文；
- 详情面板可编辑条件、步骤、数据和预期；
- `actual_result` 只读；
- 覆盖缺口阻塞发布；
- 确认 JSON/XLSX 来自同一不可变版本。

### 24.5 只读表格

- 脑图修改后表格立即同步；
- 未保存数据有明确标识；
- 表格无任何编辑控件；
- 筛选、分页和长文本查看可用；
- 从表格可定位脑图节点；
- 切换标签不保存、不丢数据。

### 24.6 AI

- 三种 AI 操作可从脑图选择范围发起；
- 未保存脑图不能直接发起 AI；
- AI 建议默认不应用；
- 临时节点和替换差异可查看；
- 应用建议只改变浏览器内数据；
- 基准过期禁止应用；
- 失败、取消、超时和重启返回原 Review；
- AI 不执行测试步骤或访问真实目标。

### 24.7 并发与恢复

- 双标签保存冲突不覆盖、不丢本地数据；
- 同正文不增加 revision；
- 相同 SHA 确认不创建重复版本；
- 页面离开提示未保存修改；
- 网络断开和恢复后重新读取状态；
- 迟到 Runner 结果不覆盖新状态。

### 24.8 权限与安全

- 创建者可编辑；
- 其他普通用户统一 404；
- 管理员按 `task.view.all` 查看；
- 只读用户只能查看脑图和表格；
- 缺少 CSRF 的写请求失败；
- 节点文本不能形成 XSS；
- Prompt、Secret、路径和 traceback 不回显；
- API 智能体三个安全默认值不变。

### 24.9 浏览器验收

在 1280×800、1440×900 和 1920×1080 验收：

- 任务列表、创建弹窗、生成状态、失败和空态；
- 测试点脑图完整编辑流程；
- 测试用例脑图完整编辑流程；
- 脑图/只读表格切换；
- 版本切换和未保存确认；
- AI 排队、运行、取消、失败、建议、应用；
- CAS 冲突和本地副本；
- 键盘导航、焦点恢复、对话框和 reduced-motion；
- 200% 缩放和长文本；
- 最大数据量下的折叠、搜索、筛选和性能保护。

## 28. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 大量长文本导致脑图不可读 | 高 | 默认折叠、节点摘要、详情面板、搜索和可见节点限制 |
| 脑图库与现有原生 JS 不兼容 | 高 | 详细设计先做小型技术验证；不改变后端 JSON 协议 |
| 树与平面 JSON 转换丢字段 | 高 | 未识别字段挂在叶子对象并做往返测试 |
| 父节点操作误改大量数据 | 高 | 影响预览、数量确认、撤销/重做和显式保存 |
| 脑图与表格状态不一致 | 高 | 单一内存对象；表格只读；一致性自动化测试 |
| 双标签覆盖草稿 | 高 | 继续使用 revision/SHA CAS 和本地副本 |
| 脑图键盘可访问性不足 | 中高 | 语义化树导航、详情表单和非拖拽移动入口 |
| AI 建议混入正式数据 | 高 | 临时建议层、默认不选、显式应用、保存和确认 |
| 用户误认为生成百分比准确 | 中 | 只展示真实阶段和计数，未知总数不显示百分比 |
| 工作台升级影响现有用户 | 中 | 单一功能开关、dev 灰度、旧界面完整回退 |
| 第三方依赖带来供应链风险 | 中 | 许可证/锁文件/离线构建/依赖审计；无法满足则采用最小自研投影 |

## 30. 评审确认项

以下开发设计前确认项均已评审确认：

1. **脑图为唯一编辑入口，表格永久只读**：已确认；
2. **只读表格展示当前未保存预览，而非只展示服务端草稿**：已确认；
3. **测试点脑图固定为根→模块→功能→场景→测试点**：已确认；
4. **用例脑图固定为根→模块→功能→测试点→用例，复杂字段在详情面板编辑**：已确认；
5. **用例 Review 中测试点节点不可编辑，只能移动用例改变引用**：已确认；
6. **显式保存，不自动保存**：已确认；
7. **父节点重命名/删除视为批量操作，必须显示影响并可撤销**：已确认；
8. **浏览器内最多保留 50 步撤销/重做，不跨刷新持久化**：已确认；
9. **不保存自由坐标，只保存业务 JSON，布局自动计算**：已确认；
10. **同时可见节点上限 500，超过时要求折叠或筛选**：已确认；
11. **生成进度只展示真实阶段/计数，不展示推算百分比**：已确认；
12. **MVP 不提供暂停任务，只提供取消**：已确认；
13. **不引入版本合并；只支持版本查看和 CAS 冲突处理**：已确认；
14. **AI 建议以临时节点/差异面板展示，应用后仍需保存**：已确认；
15. **仅新增一个统一工作台 V2 功能开关**：已确认；
16. **脑图库由开发设计的技术验证决定，PRD 不锁定实现库**：已确认；
17. **MVP 不扩展上传类型、并发控制和模型选择**：已确认；
18. **prod 首次发布关闭，完成灰度后开启**：已确认。

## 31. 最终产品结论

本次改进不是在当前页面上再叠加一个“脑图组件”，而是把功能测试智能体整理为完整的任务型测试工作台：

- 任务列表负责管理和进入；
- 任务工作台负责展示真实生成过程；
- 脑图负责唯一编辑；
- 表格负责只读校对；
- 现有 Review 文件、版本和 CAS 负责可靠保存；
- AI 负责提供可选择建议；
- 确认版本负责驱动后续生成和最终发布。

该方案能够明显提升平台感和层级信息的可理解性，同时复用已完成的测试点/测试用例 Review 能力，避免引入第二套数据模型、任务状态机或业务数据库，具备明确的实现边界、验收标准和回滚路径。
