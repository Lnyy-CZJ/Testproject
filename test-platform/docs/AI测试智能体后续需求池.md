## 3. 当前已实现基线

### 3.1 两个智能体公共基线

- 两个独立服务、容器、URL、配置、Secret、Client Token、任务目录和产物目录；
- 持久化单槽位 FIFO、队列上限、取消、超时、重启恢复和原子文件发布；
- 身份、任务所有权、管理员查看、CSRF、RBAC、审计和脱敏；
- 模型、Prompt 哈希、配置 Release 和应用版本展示；
- dev/prod 配置和 Secret 隔离；
- API 数据库写入可选且默认关闭，文件生成不依赖数据库。

### 3.2 功能测试智能体

测试点 Review 已实现：

- 在线筛选、分页、增删改、复制、撤销、草稿 CAS 和不可变确认版本；
- JSON 导入/下载及原下载上传兼容入口；
- AI 补充、改写选中项、按说明生成建议；
- AI 建议不自动覆盖草稿，失败/取消/超时后返回 Review；
- 确认后重新参与 FIFO，再生成测试用例。

测试用例 Review 本轮新增实现：

- 用例生成后可进入 `waiting_case_review`；关闭开关时兼容原直接成功流程；
- 列表 + 详情工作台，用例增删复制、步骤/前置条件/测试数据编辑和覆盖摘要；
- 原稿、草稿、AI 建议、确认版本和最终产物隔离；
- revision/SHA CAS、JSON 导入下载、引用/覆盖/重复校验；
- AI 补充、改写选中用例、按说明生成建议，保持 ID、测试点引用和实际结果；
- AI 与正式任务、测试点 AI 共用单槽 FIFO；
- 确认时不再调用 LLM，从同一不可变 JSON 确定性生成最终 JSON/XLSX；
- XLSX 公式注入防护、幂等发布和半成品保护；
- 迁移 `20260814_0012` 增加独立配置，定义默认关闭，dev Release 显式开启，prod 不自动开启。

### 3.3 API 测试智能体

可信生成和 Review 主体已实现：

- OpenAPI 3.x、Swagger 2.0 确定性解析；非结构化文档 LLM 解析和质量硬门禁；
- 契约版本、人工 Review、基础用例、业务补充、覆盖矩阵和覆盖补齐；
- 用例 Review、可执行用例生成、依赖/脚本静态校验；
- 分阶段 Runner、阶段 attempt/version、失败重试和中间产物发布；
- 执行预览、确认 SHA、Run、报告、慢响应候选和本地缺陷草稿模型/API/UI。

本机 S2 真实执行试点已实现：

- API Web 不持有 Docker Socket；独立 Controller 是唯一容器创建者；
- 每个 Run 使用独立、短生命周期、非 root、只读根、清空 capability 的固定 Executor 镜像；
- Executor 有 CPU、内存、PID、临时目录、输出大小和超时限制；
- Egress Proxy 校验目标、scheme、host、port、path、Host Header、DNS 前后结果和重定向后的新请求；
- Executor 不获得模型、平台、KEK、数据库或 Controller Token；
- 结果、日志、报告和缺陷草稿分层脱敏；
- 本机 `local-platform-dev` 健康接口真实执行成功，metadata 负向请求被拒绝；
- 默认 Compose 不启动 S2 Profile，`API_EXECUTION_ENABLED=false`；prod 环境即使配置 true 也由代码固定关闭。

## 6. 重点方案

### 6.1 API 真实执行：从本机试点走向共享环境

已经完成的 Controller、Executor 和 Egress 不应推倒重做，下一步是补生产门禁：

1. **运行时边界**：优先改为 rootless Docker、隔离宿主或受控编排 API；如果继续使用 Docker Socket，必须完成专项渗透测试和宿主恢复演练。
2. **供应链**：固定镜像 digest，完成 CVE 扫描、签名验证、SBOM 和报告归档，高危漏洞不得放行。
3. **目标与凭据**：目标、环境、路径、方法和 Credential 分离审批；凭据只在单 Run 内短期注入并自动撤销。
4. **HTTPS**：实现受控 CONNECT 或平台代理 TLS，严格证书校验，不允许全局关闭验证。
5. **确认与权限**：确认 SHA 必须绑定用户选择的目标、用例版本、写请求、高风险项和脚本摘要；网关与工具服务双层校验权限。
6. **运维恢复**：演练取消竞态、Controller/Web 重启、孤儿容器、代理故障和 Secret 轮换。
7. **灰度**：先共享 dev，再 staging；每增加一个目标都重新审批。prod 保持代码级固定禁止，直到另一次生产安全评审明确修改该决策。

### 6.2 功能测试用例 Review：发布收口

当前不需要再建设第二套编辑器，应集中完成验收：

1. 用真实任务验证“测试点确认 → 用例生成 → `waiting_case_review` → 最终确认”；
2. 真实调用三类用例 AI，验证限流、超时、取消、失败和建议基准过期；
3. 用 100/500/2000 条用例测试加载、筛选、编辑、完整校验和 XLSX 发布；
4. 验证双标签页 CAS、引用失效、覆盖缺口、公式注入、发布中断和幂等重试；
5. 完成 1280×800、1440×900、键盘、焦点、非纯颜色状态和 reduced-motion 验收；
6. dev 先开启人工 Review，再独立开启 AI；prod 默认关闭，通过发布审批后创建新 Release。

不建议把全部文件永久保存到 PostgreSQL。推荐：

| 数据层 | 保存内容 | 介质 | 建议保留 |
|---|---|---|---|
| 任务摘要 | 状态、创建者、版本、统计、错误码、产物索引 | PostgreSQL | 180 天或归档后长期 |
| 热运行数据 | 输入、日志、Review 文件、Run、报告、产物 | 独立任务卷 | 90 天 |
| 长期资产 | 用户显式归档的稳定用例、报告和发布包 | 对象存储/资产库 | 生命周期策略控制 |

该方案仍可满足“需要时查看”，同时避免关系库膨胀、备份恢复变慢、二进制和敏感文件混入数据库。

### 6.4 功能执行与 API 执行不要共用模型

功能用例执行通常需要 UI/业务流程、环境数据和步骤级证据；API 执行使用 HTTP 契约和请求响应。两者可以复用 Run、权限、审计、脱敏和缺陷草稿概念，但不应复用同一个 Executor 或 CaseResult Schema。建议先定义公共运行摘要，再分别实现 API Runtime Adapter 和功能/UI Runtime Adapter。

## 8. 当前不应采取的捷径

- 把本机单目标试点描述为生产真实执行已经完成；
- 在 prod 或共享环境直接设置 `API_EXECUTION_ENABLED=true`；
- 使用宿主机 `subprocess` 执行生成脚本或 API 用例；
- 为支持 HTTPS 关闭证书校验，或扩大 CIDR/端口白名单；
- 让 AI 建议自动写入草稿、自动确认或删除人工用例；
- 为并发直接增加 Web worker，破坏单槽队列和配置隔离；
- 把正文、长日志、二进制输入和产物永久写入 PostgreSQL；
- 默认向项目成员共享任务；
- 未经人工确认自动提 Bug、提交 Git 或触发生产流水线；
- 未确认归属就迁移历史 `output/`；
- 让 dev 读取 prod Secret 或任务卷。

## 9. 进入详细设计前的确认项

每项需求进入排期前至少确认：

1. 业务负责人、目标用户、频率和量化收益；
2. 新权限、跨用户数据、网络访问及外部写入边界；
3. 数据保留、删除、审计、脱敏和合规要求；
4. dev/prod Secret、Token、目标、Credential 和网络隔离；
5. 状态机、失败语义、幂等、补偿和回滚；
6. 自动化、真实联调、浏览器、性能和安全验收；
7. 对 CLI、Prompt、LangGraph、Schema、旧任务和产物字段的兼容影响；
8. 是否需要安全、基础设施、数据或目标系统负责人审批。

## 10. 维护规则

- 状态统一使用：`候选`、`待评审`、`已批准`、`设计中`、`开发中`、`部分实现`、`已完成`、`已取消`；
- “有页面、接口或测试替身”不等于真实或生产能力完成；
- 已批准需求应另建 PRD/专项设计，并在本文件记录关联；
- 完成项保留编号和历史状态，不直接删除；
- 真实执行、生产环境、外部写入和跨用户共享必须独立评审；
- 每次两个智能体发生较大变化后，应重新以代码、配置、迁移、测试和真实运行证据更新本文件。
