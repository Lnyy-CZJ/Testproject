## 2. Web 平台化需求

### WEB-001 简易接口自动化 Web 平台

| 项目 | 内容 |
| --- | --- |
| 状态 | 待评估 |
| 优先级 | 待确定 |
| 目标版本 | 待确定 |
| 来源 | 现有 Python + pytest + requests + YAML 接口自动化项目演进 |

#### 需求目标

在保留现有自动化执行引擎能力的基础上，提供一个简易 Web 页面，让使用者可以管理接口、单接口用例、Flow、环境配置和执行记录，并从页面发起测试。

#### 候选能力

- 接口定义的新增、查看、编辑和删除。
- 单接口多用例的新增、查看、编辑和删除。
- 多接口 Flow 步骤编排和 Scenario 数据维护。
- 环境配置选择和运行时变量配置。
- 按接口、用例、Flow、标签和环境发起测试。
- 查看执行状态、请求日志、响应日志和断言结果。
- 查看历史执行记录和失败原因。
- YAML 导入、导出，继续兼容本地代码仓库使用方式。

#### 候选技术方向

- 后端：FastAPI。
- 页面：服务端模板配合轻量交互方案，避免首版引入复杂前后端分离架构。
- 数据存储：SQLite 起步，后续根据并发和部署需求评估其他数据库。
- 执行方式：Web 层提交任务，独立执行层调用现有核心执行能力。
- 数据模型：API、TestCase、Flow、FlowStep、Scenario、Environment、Execution。

以上技术方向仅作为后续评估输入，不代表已经确定实现方案。

#### 进入开发前的前置条件

1. V1.3 完成接口定义与测试用例拆分。
2. 单接口和 Flow 的核心加载、执行能力可以脱离具体 pytest 文件调用。
3. 明确单用户还是多用户、是否需要登录和权限。
4. 明确部署环境、并发执行数量和历史数据保留周期。
5. 明确 YAML 文件与数据库谁是主数据源，以及两者的同步规则。

#### 当前版本边界

该需求不属于 V1.3，不影响 V1.3 的设计、开发和验收。V1.3 只为后续平台化建立清晰的数据职责，不提前开发 Web、数据库或任务队列。
