## 二、详细测试用例

### T1: P2-1 仓库管理升级 (12 cases)

#### T1.1 ProjectRepo 新字段验证
- `T1.1.1` 创建仓库时 sourceType 必填（github/gitlab/gitea/custom）
- `T1.1.2` 创建仓库时 defaultBranch 默认值 "main"
- `T1.1.3` 创建仓库时 agentTypes 默认值 "backend,test"
- `T1.1.4` 更新仓库支持所有新字段（SourceType/CredentialID/AgentTypes/DefaultBranch）
- `T1.1.5` 同一项目内仓库URL唯一性校验

#### T1.2 RepoCredential CRUD (10 cases in credential_test.go)
- `T1.2.1` 创建凭证 → AES加密存储 + maskedValue 脱敏
- `T1.2.2` 查询凭证列表 → 按 userID 过滤
- `T1.2.3` 获取单个凭证 → 返回加密内容(不暴露明文)
- `T1.2.4` 更新凭证 → 支持部分字段更新
- `T1.2.5` 删除凭证 → 不存在返回 ErrCredentialNotFound
- `T1.2.6` 解密凭证内容 → 加密/解密一致性
- `T1.2.7` TouchLastUsed → 更新时间戳
- `T1.2.8` ValidateConnection → 4种provider均返回success
- `T1.2.9` EncryptDecrypt 往返正确性
- `T1.2.10` 凭证归属隔离（用户A看不到用户B的凭证）

### T2: P2-2 个人信息管理 (8 cases)

#### T2.1 Profile API
- `T2.1.1` GET /users/me 返回当前用户完整信息
- `T2.1.2` PUT /users/me 更新 nickname/avatar
- `T2.1.3` PUT /users/me 更新 agentTypes（逗号分隔字符串）
- `T2.1.4` PUT /users/me 空字段不覆盖已有值

### T3: P2-3 用户管理增强 (5 cases)

#### T3.1 管理员创建用户
- `T3.1.1` POST /users 创建用户（username/email/password必填）
- `T3.1.2` 密码自动 bcrypt 哈希存储
- `T3.1.3` 用户名/邮箱唯一性校验
- `T3.1.4` nickname 可选字段
- `T3.1.5` 最小密码长度6位校验

### T4: P3-1 简化权限模型 (10 cases)

#### T4.1 两级角色体系
- `T4.1.1` 平台角色: super_admin / admin / member (3个)
- `T4.1.2` 项目角色: project_admin / developer / tester / viewer (4个)
- `T4.1.3` SeedRBACData 创建全部7个角色
- `T4.1.4` admin 用户默认绑定 super_admin 角色
- `T4.1.5` 角色权限全量分配（每个角色拥有全部19种permission）

### T5: P3-2 通知偏好配置 (8 cases)

#### T5.1 NotificationPreference CRUD
- `T5.1.1` 首次获取 → 自动创建5条默认偏好
- `T5.1.2` 默认偏好: defect_status→in_app,email; assignment→in_app,email
- `T5.1.3` 单条更新偏好 channels
- `T5.1.4` 批量更新偏好
- `T5.1.5` IsEnabled 判断逻辑
- `T5.1.6` 用户偏好隔离

### T6: P1 回归测试 (10 cases)

#### T6.1 Organization 已移除
- `T6.1.1` Project 模型无 OrgID 字段
