# BugAgent v5.1 Development Plan

> Date: 2026-04-13
> Scope: 项目内信号接入中心 + 连接器生产化 + 分诊准确率 + AI 可信化 + 接口测试与页面联调专项

---

## 1. Delivery Strategy

本期按“先稳，再迁，再做深”的顺序推进：

1. `P0` 接口测试与页面联调专项
2. `P1` 项目内接入中心迁移
3. `P2` 连接器生产化
4. `P3` 分诊智能准确率
5. `P4` AI 处置可信化

说明：

1. `P0` 不是独立结束项，而是贯穿全程。
2. 不保留平台级接入页和平台级接入接口。
3. 每个阶段都必须带接口测试、页面联调和浏览器回归。

---

## 2. Ordered Worklist

### P0 接口测试与页面联调专项

目标：系统性收口“页面数据获取失败”。

任务：

1. 梳理项目主链路页面与依赖 API 的映射表。
2. 为核心 API 增加冒烟测试和契约校验。
3. 统一前端错误语义处理。
4. 为关键页面补加载态、空态、错误态、重试逻辑。
5. 形成联调问题台账并逐项关闭。

完成标准：

1. 核心页面不再频繁无反馈失败。
2. 页面失败时具备明确提示和恢复路径。

### P1 项目内信号接入中心迁移

目标：彻底删除平台级接入入口，统一到项目内。

任务：

1. 新增项目内信号接入页。
2. 删除平台级菜单和平台级页面路由。
3. 后端改造为项目级连接器接口。
4. 前端把当前页面复用能力拆到项目上下文组件。
5. 问题池与路由治理补跳转联动。
6. 删除历史联调脚本中的平台级接入路径引用。

完成标准：

1. 平台级接入入口彻底消失。
2. 项目内完成接入 CRUD/test/sync/records 全流程。

### P2 连接器生产化

目标：连接器真正可运维。

任务：

1. 增加健康状态与错误分类。
2. 增加同步记录与失败详情。
3. 增加手动重试与失败重放。
4. 补连接器配置诊断逻辑。
5. 补真实外部系统联调脚本与验收记录。
6. 收口“第三方失败误判为系统登录失效”类问题。

完成标准：

1. 接入失败可诊断、可重试。
2. 至少一条真实连接器链路完成闭环。

### P3 分诊智能准确率

目标：提升建议结果的可用性。

任务：

1. 强化重复识别与聚类策略。
2. 增加路由建议置信度。
3. 展示推荐依据。
4. 实现批量分诊动作。
5. 记录人工修正和建议采纳率。
6. 增加相关回归测试。

完成标准：

1. 批量分诊可用于真实问题池。
2. 建议可解释、可统计。

### P4 AI 处置可信化

目标：让 AI 进入生产可信状态。

任务：

1. 记录模型与 Prompt 版本。
2. 增加 AI 调用审计与结果观测。
3. 建立分析失败降级策略。
4. 增加多模型 fallback。
5. 增加风险摘要和修复前验证建议。
6. 增加 AI 成本、延迟、成功率指标。

完成标准：

1. AI 失败不会打断主流程。
2. AI 输出和调用链可复盘。

---

## 3. Suggested Engineering Split

### Backend

1. 接入中心项目级接口迁移
2. 连接器健康状态与同步任务能力
3. 分诊建议与采纳反馈能力
4. AI 审计、fallback 与观测能力
5. API 测试与错误语义统一

### Frontend

1. 项目内信号接入页
2. 平台级接入入口删除
3. 页面错误态/重试统一
4. 问题池建议增强与批量分诊
5. AI 结果可信化展示

### QA / Integration

1. 核心接口冒烟
2. 页面联调清单
3. 浏览器回归
4. 真实外部连接器验收记录

---

## 4. Exit Criteria

1. 平台级接入页与接口已删除。
2. 项目级接入中心可稳定使用。
3. 页面数据获取失败显著下降。
4. 至少 1 到 2 条真实外部接入链路完成验收。
5. 问题池分诊建议具备可解释性和批量能力。
6. AI 处置链路具备基本可信化与观测能力。
