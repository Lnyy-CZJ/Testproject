# BugAgent v4.0 (Phase 4) Development Plan

> Date: 2026-04-10  
> Scope: 平台全局凭证 + 通知治理 + 全局个人中心 + 平台配置 + 用户安全 + AI 目录治理

---

## 1. Delivery Strategy

本期按“先修复交互断点、再补底层数据模型、最后串联复杂治理逻辑”的顺序推进：

1. P0：通知按钮无响应修复与消息中心落地
2. P1：账户安全与全局个人中心改造
3. P2：平台全局凭证管理
4. P3：项目通知管理与个人 webhook
5. P4：平台配置页（SMTP）
6. P5：用户管理增强
7. P6：AI 目录治理升级与模型测试
8. P7：联调、回归、发布准备

## 3. Work Breakdown

## Phase P1: 全局个人中心与账户安全（2 天）

目标：移除独立 profile 页，统一为弹窗入口，并补齐密码能力。

任务：
1. 前端新增全局 `UserCenterModal` 组件：
   - 基本信息
   - AGENT 身份
   - 访问凭证
   - 通知设置
   - 安全设置
2. 替换 `MainLayout` / `ProjectLayout` 中“个人信息”跳转逻辑：
   - 从 `navigate('/profile')` 改为打开弹窗
3. 登录流程新增强制改密守卫：
   - 登录响应增加 `mustChangePassword`
   - 首次登录必须完成修改密码
4. 后端新增：
   - `PUT /users/me/password`
   - `users.must_change_password` 等字段
5. 兼容保留：
   - 旧 `/profile` 路由可临时保留一版，但前端不再使用

完成标准：
1. 任意页面可打开个人中心。
2. 被标记用户无法跳过改密流程。

## Phase P2: 平台全局凭证管理（2-3 天）

目标：建立平台凭证主表与项目授权关系。

任务：
1. 新增 migration：
   - `platform_credentials`
   - `platform_credential_projects`
2. 新增模型与服务：
   - 加密存储
   - 脱敏返回
   - `lastUsedAt`
   - 项目授权校验
3. 新增管理员接口：
   - 列表
   - 新增/编辑/删除
   - 测试连接
   - 项目授权更新
4. 前端新增平台凭证管理页。
5. 项目侧凭证选择器改造：
   - 同时展示平台凭证与个人凭证
   - 标识来源

完成标准：
1. 平台凭证可授权多个项目。
2. 项目内只能看到已授权的平台凭证。

## Phase P3: 通知中心与项目通知管理（3 天）

目标：消息中心可用，项目通知治理上线。

任务：
1. 前端通知中心组件：
   - 未读数
   - 列表分页
   - 单条/全部已读
   - 点击跳转
2. 新增项目“通知管理”页面：
   - webhook 地址列表
   - 规则配置表
3. 新增 migration：
   - `project_webhooks`
   - `project_notification_policies`
4. 后端新增：
   - 项目 webhook CRUD
   - webhook 测试接口
   - 项目通知规则读写接口
5. 通知服务改造：
   - 项目上限规则计算
   - 项目 webhook 单选下发

完成标准：
1. 通知按钮修复。
2. 项目通知规则和 webhook 可完整配置。

## Phase P4: 个人 webhook 与通知优先级合并（2 天）

目标：形成“项目上限 + 个人细化 + 个人 webhook 镜像”的完整通知链路。

任务：
1. 新增 `user_webhook_settings`。
2. 个人中心通知设置页新增：
   - 个人 webhook URL / secret / enabled
   - 测试发送
3. 通知服务改造：
   - 先计算项目允许通道
   - 再应用个人偏好
   - 站内消息成功写入后异步镜像到个人 webhook
4. 补充失败日志与不阻塞主流程机制。

完成标准：
1. 个人 webhook 发送失败不影响站内消息。
2. 同一条站内消息可成功镜像到个人 webhook。

## Phase P5: 平台配置页（SMTP）（1-2 天）

目标：将发件邮箱配置迁入数据库管理。

任务：
1. 新增 `platform_settings` 表或等价配置存储。
2. 后端新增：
   - 读取/保存 SMTP 配置
   - 测试邮件发送
3. 前端新增平台配置页：
   - SMTP 表单
   - 测试邮箱输入
   - 最近一次测试结果
4. 通知服务发送邮件改为优先读取数据库平台配置。

完成标准：
1. 平台管理员可完成 SMTP 配置和测试。
2. 邮件通道未配置时，系统行为明确且不阻塞其他通道。

## Phase P6: 用户管理增强（1-2 天）

目标：补齐项目归属筛选和管理员重置密码。

任务：
1. 用户列表接口支持 `projectId` 条件。
2. 前端用户管理页新增项目归属筛选器。
3. 后端新增管理员重置密码接口：
   - 生成临时密码
   - 设置 `must_change_password=true`
   - 记录重置人和时间
4. 前端新增“重置密码”操作和结果弹窗。

完成标准：
1. 用户可按项目归属筛选。
2. 重置密码结果一次性展示给管理员复制。

## Phase P7: AI 目录治理升级（2 天）

目标：数据库成为 AI 目录唯一来源，并改造后台展示。

任务：
1. 删除项目侧代码内置厂商/模型 fallback。
2. 新增 seed/migration：
   - OpenAI / Anthropic / 智谱 / DeepSeek / DashScope 等初始目录
3. 前端 AI 目录页改造：
   - 厂商列表
   - 展开显示模型列表
4. 新增模型可用性测试接口与前端操作：
   - 临时 API Key 输入
   - 成功/失败/耗时反馈
5. 项目 AI 配置页改造：
   - 只读数据库目录
   - 目录为空时明确提示初始化失败

完成标准：
1. 运行时无代码清单 fallback。
2. AI 目录树形展示与模型测试可用。

## Phase P8: 联调、回归、发布准备（2 天）

任务：
1. 后端：
   - handler/service 单测
   - 通知优先级合并逻辑测试
   - 密码重置与强制改密测试
2. 前端：
   - 个人中心弹窗交互
   - 通知中心
   - 平台凭证管理
   - 项目通知管理
   - AI 目录树形页
3. 浏览器 E2E：
   - 登录 -> 强制改密
   - 打开通知中心 -> 标记已读
   - 个人中心 -> 修改密码 / 个人 webhook
   - 平台凭证 -> 授权项目 -> 项目页可见
   - 项目通知管理 -> 规则保存
4. 回归：
   - 项目列表
   - 仓库管理
   - 云效导入
   - AI 配置保存

完成标准：
1. 本期新增链路具备自动化验证。
2. 核心旧链路无回归。

## 7. Risks And Mitigation

1. 通知规则三层合并复杂度高
   - 先固化优先级规则，再写单元测试覆盖所有组合。
2. 平台凭证与个人凭证并存后 UI 易混淆
   - 统一选择器显示来源标签与授权范围。
3. SMTP/ webhook 涉及敏感信息
   - 统一复用现有加密能力，避免明文日志。
4. 强制改密会影响现有登录流程
   - 单独增加登录后守卫和 E2E 覆盖。
5. 移除 AI 代码 fallback 有初始化风险
   - 必须提供 seed，并在后台缺少目录时给出明确告警。
