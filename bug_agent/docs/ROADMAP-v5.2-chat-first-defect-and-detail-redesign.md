# BugAgent v5.2 路线图

> Version: v5.2
> Date: 2026-04-13
> Status: Planning

---

## 1. 总体目标

`v5.2` 的目标是把缺陷域最核心的两段体验做顺：

1. 让缺陷创建从繁琐表单切换到 chat-first。
2. 让手工缺陷进入问题池统一治理模型。
3. 让缺陷详情页从长文本堆叠页重构为可阅读、可处理的工作台。

---

## 2. 迭代顺序

建议拆成 3 个 Sprint：

1. `Sprint 5.2-1` 对话式创建缺陷
2. `Sprint 5.2-2` 手动缺陷进入问题池
3. `Sprint 5.2-3` 缺陷详情页重构

---

## 3. Sprint 5.2-1

### 目标

1. 缺陷创建默认改成对话方式。
2. AI 生成结构化草稿并进入确认页。
3. 高级模式保留为次级入口。

### 交付

1. 对话创建入口
2. AI 草稿生成接口
3. 确认页
4. AI 失败降级最小草稿
5. 高级模式切换入口

### 验收

1. 用户可以通过自然语言完成缺陷草稿生成。
2. 用户确认前不会真正创建缺陷。
3. AI 失败时仍可继续提单。

---

## 4. Sprint 5.2-2

### 目标

1. 所有手动创建缺陷进入问题池。
2. 问题池、回归预防、质量情报覆盖手工来源。

### 交付

1. `manual_chat / manual_form` 来源扩展
2. defect -> signal -> cluster 自动建模
3. 问题池来源展示与跳转联动
4. 质量情报来源统计打通
5. 相似问题建议接入手工来源

### 验收

1. 手动缺陷创建后能在问题池中找到对应项。
2. 不会重复生成多个 signal。
3. 手工来源可进入质量统计。

---

## 5. Sprint 5.2-3

### 目标

1. 缺陷详情页结构重组。
2. Markdown 正确渲染。
3. 系统评论和 AI 内容从正文噪音中解耦。

### 交付

1. 顶部摘要区
2. 中部双栏布局
3. 评论时间线
4. GFM Markdown 渲染
5. 原始 JSON 折叠区
6. 修复任务卡简化

### 验收

1. 缺陷详情页能快速读懂核心结论。
2. Markdown 和代码块渲染正确。
3. 原始机器数据不再直接淹没正文。

---

## 6. 横向约束

所有 Sprint 都必须满足：

1. handler / service 自动化测试同步补齐
2. 缺陷创建与详情页浏览器回归同步扩展
3. 详情渲染需覆盖历史存量评论和系统消息
4. chat-first 与高级模式共用一套最终创建数据模型

---

## 7. 风险

1. AI 草稿结果波动会影响创建体验
2. 手工缺陷自动入问题池可能引入重复关联
3. 详情页历史数据格式不统一，渲染兼容有成本
4. 大幅改布局可能影响现有缺陷处理操作路径

---

## 8. 路线图结论

`v5.2` 成败的关键是：

1. 缺陷创建是否真正变简单
2. 手工缺陷是否真正进入统一治理体系
3. 缺陷详情页是否真正变得可阅读、可处理
