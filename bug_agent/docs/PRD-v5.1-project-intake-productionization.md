# BugAgent v5.1 PRD

> Version: v5.1
> Date: 2026-04-13
> Status: Draft
> Owner: Product + Engineering

---

## 1. Background

`v5.0` 已完成问题信号接入、问题池、路由治理、版本影响、回归预防和质量情报主干能力，但当前版本仍存在三类约束：

1. 信号接入入口仍在平台层，与项目内的问题池和路由治理链路割裂。
2. 连接器更偏“开发可用”，缺少生产级诊断、重试、健康状态与真实外部联调闭环。
3. 在实际体验中，页面数据获取失败频繁出现，说明接口契约和页面联调稳定性仍不足。

因此，`v5.1` 的目标不是继续增加外围模块，而是围绕以下方向推进：

1. 把信号接入中心完全迁入项目内。
2. 把真实连接器能力推进到生产可用。
3. 提高问题池分诊建议准确率和可解释性。
4. 强化 AI 处置的可信度、降级能力和可观测性。
5. 增加接口测试与页面联调专项，系统性收口页面数据获取失败问题。

---

## 2. Product Goals And Non-Goals

### 2.1 Goals

1. 删除平台级接入入口，将信号接入统一下沉到项目内。
2. 建立项目级连接器管理、测试、同步、诊断与同步记录闭环。
3. 完成连接器生产化能力：健康状态、错误分类、重试、失败记录与诊断。
4. 提高问题池的重复识别、聚类、路由建议与批量分诊能力。
5. 提升 AI 分析/修复链路的可信度，包括模型版本、失败降级、风险摘要和可观测指标。
6. 系统性治理“页面数据获取失败”，统一接口契约与错误态表现。

### 2.2 Non-Goals

1. 不保留平台级接入页或平台级接入兼容接口。
2. 不在本期交付平台级连接器模板库。
3. 不在本期交付外部系统双向回写。
4. 不在本期新增更多新渠道类型。
5. 不在本期自研 App 崩溃采集 SDK。
6. 不在本期做复杂自定义规则编排器。

---

## 3. Personas

1. 平台管理员：继续管理平台治理能力，但不再直接负责项目级连接器入口操作。
2. 项目管理员：在项目内管理信号接入、路由、问题池和质量闭环。
3. 分诊人员：处理问题池、执行批量分诊、校正建议结果。
4. 研发/测试成员：查看问题来源上下文、接收分诊和 AI 结果、进入正式缺陷处置。
5. 运维/质量负责人：关注接入健康、异常版本、问题趋势与 AI 处置指标。

---

## 4. Core Decisions

### 4.1 信号接入必须完全项目化

1. 信号接入入口只存在于项目内。
2. 项目就是连接器唯一归属，不再允许用户在平台页先选项目归属。
3. 问题池、路由治理、信号接入、回归预防、质量情报共享同一项目上下文。

### 4.2 不保留任何历史入口与历史接口

1. 删除前端平台级 `/integration-connectors` 页面。
2. 删除平台导航中的“信号接入”。
3. 删除后端平台级连接器接口，不做兼容保留。
4. 测试、文档和联调脚本同步迁移。

### 4.3 稳定性专项与功能开发并行推进

1. `接口测试 + 页面联调` 为本期强约束。
2. 新增功能若引入新的页面获取失败，不视为功能完成。
3. 每个 Sprint 都必须包含接口契约测试和浏览器联调验证。

## 5. User Stories

1. 作为项目管理员，我希望在项目内部直接配置 Bugly、钉钉、飞书、Webhook、阿里云日志连接器，而不是跳到平台页再选项目。
2. 作为项目管理员，我希望能清楚知道连接器为什么失败、是否还能重试、最近同步到了什么状态。
3. 作为分诊人员，我希望系统给出的归属、负责人、优先级和重复建议更可信，并告诉我推荐依据。
4. 作为研发或测试成员，我希望 AI 分析失败时不会打断主流程，而且能看到明确失败原因和降级结果。
5. 作为用户，我希望页面数据获取失败时能看到清晰错误、重试按钮和稳定的恢复路径，而不是白屏或静默失败。

## 6. Functional Requirements

### FR-1 项目内信号接入中心

1. 在项目侧边栏新增“信号接入”。
2. 页面路径为 `/projects/:projectId/integrations`。
3. 页面支持：
   - 列表当前项目全部连接器
   - 新增连接器
   - 编辑连接器
   - 删除连接器
   - 测试连接器
   - 手动同步
   - 查看同步记录
   - 查看最近错误与健康状态
4. 创建与编辑时不再让用户选择项目归属。
5. 平台级接入页与平台级路由全部删除。

验收标准：
1. 用户在项目内即可完成接入配置全流程。
2. 不再存在平台级接入入口。
3. 新连接器创建后立即归属于当前项目并在问题池链路中可见。

### FR-2 连接器生产化

1. 连接器需支持统一健康状态：
   - healthy
   - warning
   - failed
   - inactive
2. 连接器需支持最近同步记录：
   - 开始时间
   - 结束时间
   - 导入数量
   - 聚类数量
   - 错误摘要
3. 连接器错误需标准分类：
   - 配置缺失
   - 鉴权失败
   - 第三方限流
   - 超时/网络失败
   - 第三方接口异常
4. 连接器需支持手动重试。
5. 对失败同步记录需提供失败详情与排查指引。
6. 对真实外部连接器测试结果统一返回标准结构。

验收标准：
1. 用户能区分“当前登录失效”和“第三方连接器失败”。
2. 连接器失败后可重试且不会误伤系统登录态。
3. 至少一条真实外部链路在本期成功闭环。

### FR-3 分诊智能准确率提升

1. 重复识别增强：
   - 支持更稳定的 fingerprint 聚合
   - 支持相似问题建议
2. 路由建议增强：
   - 项目归属
   - 模块归属
   - 责任人
   - 严重级别
   - 优先级
3. 每条建议需展示“推荐依据”。
4. 支持批量分诊：
   - 批量指派
   - 批量忽略
   - 批量转缺陷
   - 批量调整优先级/严重级别
5. 记录人工修正结果和建议采纳率。

验收标准：
1. 分诊人员可批量处理高频问题。
2. 建议结果具备解释信息，不是黑盒。
3. 建议采纳率可统计。

### FR-4 AI 处置可信化

1. AI 分析/修复链路需记录：
   - 模型版本
   - Prompt 版本
   - 调用时间
   - 调用结果
2. AI 分析失败需支持降级：
   - 返回明确失败原因
   - 支持 fallback 策略
   - 不打断主业务状态机
3. AI 输出需增加：
   - 风险摘要
   - 修复前验证建议
4. 平台需提供基本观测指标：
   - 成本
   - 延迟
   - 成功率
   - 失败分类

验收标准：
1. AI 分析失败不会导致页面卡死或流程悬空。
2. AI 输出比当前版本更可解释。
3. AI 链路可复盘。

### FR-5 接口测试与页面联调专项

1. 核心主链路页面必须补齐：
   - 加载态
   - 空态
   - 错误态
   - 重试动作
2. 核心 API 需统一错误语义。
3. 新增页面和核心旧页面均纳入联调清单。
4. 对“页面数据获取失败”类问题建立回归集。

验收标准：
1. 核心页面不再频繁出现无反馈失败。
2. 页面失败时可重试、可恢复。
3. 联调问题数量显著下降。

## 7. Interaction Design Requirements

1. 项目内“信号接入”页风格与“问题池 / 路由治理 / 回归预防 / 质量情报”保持一致。
2. 连接器列表应突出：
   - 类型
   - 状态
   - 最近同步时间
   - 最近错误
   - 快捷操作
3. 问题池页在无数据时，应给出去“信号接入”配置的明确引导。
4. 所有数据加载失败页面都必须提供明确错误文案和重试按钮。
5. 建议类 UI 应明确“系统建议”和“人工最终结果”的区别。

## 9. Data Model Changes

1. 连接器模型延续现有 `project_id` 结构。
2. 可新增：
   - 连接器健康状态字段或派生聚合视图
   - 失败重试/死信记录表
   - 建议采纳反馈表
   - AI 调用审计扩展字段
3. 不新增任何平台级连接器归属模型。

---

## 10. Permission Design

1. 平台管理员：可查看全部项目接入状态，但不以平台页作为主操作入口。
2. 项目管理员：可管理本项目接入中心、路由治理和相关配置。
3. 分诊人员：可操作问题池，但不默认拥有接入配置权限。
4. 普通成员：默认无接入管理权限。

---

## 11. Non-Functional Requirements

1. 页面级：
   - 数据获取失败时必须有明确反馈和重试动作
2. 接口级：
   - 错误语义统一，不再混淆系统登录失效与第三方连接失败
3. 连接器级：
   - 外部连接器失败不能影响主业务系统可用性
4. AI 链路：
   - 分析失败必须可回退、可记录、可观察

---

## 12. Definition Of Done

1. 平台级接入页和平台级接入接口已删除。
2. 项目级接入中心已可用。
3. 至少 1 到 2 条真实连接器链路完成联调。
4. 问题池分诊建议具备解释性和批量操作。
5. AI 链路具备基础可信化与观测能力。
6. 核心接口测试、页面联调和浏览器回归通过。
