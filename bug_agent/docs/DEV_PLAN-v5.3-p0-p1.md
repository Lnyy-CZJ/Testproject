# BugAgent v5.3 开发迭代计划（P0 + P1）

> Date: 2026-04-18  
> Scope: 仅覆盖 `PRD-v5.3` 的 P0、P1事项  
> 目标: 先稳定与安全，再提效与智能

---

## 1. 迭代目标

在不重做现有主架构的前提下，完成四件必须落地的能力：

1. P0-1：统一全站搜索/筛选栏组件与样式行为，消除回归。
2. P0-2：Webhook 签名校验上线，补齐接入安全基线。
3. P1-1：智能推荐分配 v1（Top-N + 推荐理由）。
4. P1-2：AGENT 自动推荐 v1（类型/模块/历史匹配）。

---

## 2. 迭代拆分（6周，3个迭代）

### Iteration 5.3.1（Week 1-2）— UI 稳定性收敛（P0）

目标：彻底收敛搜索/筛选栏样式与交互回归。

任务：

1. 梳理所有列表页筛选栏入口（平台页 + 项目页）。
2. 统一输入规范（禁止页面私有 `Input.Search` 双层样式分叉）。
3. 所有页面统一 `PageFilterBar` 结构与间距规则。
4. 补齐高频页面视觉快照基线（缺陷、问题池、回归预防、用户管理、审计日志、项目列表）。
5. 增加发布前 UI 巡检清单（最小可执行脚本 + 手工检查点）。

完成标准：

1. 核心页面不再出现空白按钮、双边框、控件错位。
2. 组件复用率达到 100%（筛选栏场景）。

---

### Iteration 5.3.2（Week 3-4）— Webhook 安全基线（P0）

目标：所有 Webhook 入站请求具备可校验签名能力。

任务：

1. 连接器配置新增 Secret 字段（加密存储）。
2. 接收端支持 `X-Hub-Signature-256` HMAC-SHA256 校验。
3. 校验失败拒绝请求并记录审计日志。
4. 提供“测试模式”开关（非生产环境可关闭强校验）。
5. 增加联调用例（合法签名、非法签名、缺失签名、过期重放）。

完成标准：

1. 非法签名请求拦截率 100%。
2. 审计日志可追溯失败原因与来源。

---

### Iteration 5.3.3（Week 5-6）— 推荐提效（P1）

目标：让“分配谁、用哪个 AGENT”从手工判断升级为推荐辅助。

任务：

1. 智能推荐分配 v1：
   - 评分维度：缺陷类型匹配、历史处理成功率、当前负载。
   - 返回 Top-3 推荐对象与理由。
2. 指派界面支持“一键采纳推荐”。
3. AGENT 自动推荐 v1：
   - 基于缺陷类型、模块、历史命中给出推荐组合。
   - 支持手动覆盖。
4. 采纳反馈埋点：
   - 记录“是否采纳推荐”，用于后续优化。

完成标准：

1. 推荐可稳定返回并用于指派。
2. 分配平均耗时下降（目标 20%+）。
3. 推荐采纳率可观测。

---

## 3. 角色分工建议

### Backend

1. Webhook 签名校验链路（配置、校验、中间件、审计）。
2. 推荐分配与 AGENT 推荐服务实现。
3. 推荐反馈埋点与基础统计接口。

### Frontend

1. 全站筛选栏统一改造。
2. 指派界面推荐展示与一键采纳交互。
3. AGENT 推荐展示、手动覆盖与反馈上报。

### QA

1. UI 回归快照与关键链路冒烟。
2. Webhook 安全校验联调测试。
3. 推荐能力准确性与可用性验收。

---

## 4. 风险与缓解

1. 风险：全站样式改造影响面大。  
   缓解：先高频页面，逐页灰度合并。

2. 风险：推荐质量依赖历史数据。  
   缓解：先规则+统计混合，不做纯模型依赖。

3. 风险：接入方签名实现不一致。  
   缓解：提供验签调试工具与示例代码。

---

## 5. 交付出口（Exit Criteria）

1. P0 两项全部上线：筛选栏统一 + Webhook 验签。
2. P1 两项可用：推荐分配 + AGENT 推荐。
3. 对应自动化与冒烟用例通过，无 P0/P1 回归阻塞。
