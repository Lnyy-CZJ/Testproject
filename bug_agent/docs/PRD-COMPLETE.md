# BugAgent 上线前产品需求文档（PRD）

版本：v1.0 上线版  
文档状态：上线评审稿  
适用范围：对外产品说明、上线评审、研发测试验收、交付沟通  
整理日期：2026-05-25

## 1. 产品概述

BugAgent 是面向软件研发团队的智能缺陷管理与 AI 处置平台。平台围绕项目、迭代、仓库、缺陷和 AI Agent 构建统一工作台，帮助团队完成问题接入、缺陷分诊、AI 分析、修复跟进、PR 状态追踪和验证闭环。

上线版本重点解决以下问题：

1. 缺陷信息分散，项目、迭代、仓库、责任人和修复进度难以统一追踪。
2. 外部问题、测试反馈和线上异常需要人工整理后才能进入缺陷流程。
3. 缺陷分析依赖人工经验，定位成本高，重复问题难复用历史经验。
4. AI 修复、人工修复、PR 状态和验证结果之间缺少闭环。
5. 项目级 AI 能力、凭证、通知和 Agent 上下文需要统一治理。

## 2. 产品定位

BugAgent 的定位是“AI 驱动的缺陷处理工作台”，不是通用工单系统，也不是单纯的 AI 聊天工具。

产品核心价值：

1. 以项目为工作空间，统一管理迭代、仓库、缺陷、人员和通知。
2. 以缺陷生命周期为主线，串联创建、分析、修复、验证和关闭。
3. 以 AI Agent 为辅助能力，提供分析、总结、修复建议、上下文检索和经验复用。
4. 以问题池承接外部信号，实现正式缺陷之前的分诊和聚类。
5. 以可追溯记录保证上线后质量、成本、安全和处理效率可审计。

## 3. 目标用户

| 用户角色 | 使用目标 |
|---|---|
| 项目负责人 | 了解项目质量状态、缺陷处理进度、风险和资源分配 |
| 测试人员 | 快速创建缺陷、接入问题信号、分诊问题、验证修复结果 |
| 研发人员 | 获取缺陷上下文、AI 分析结论、修复建议和 PR 状态 |
| 平台管理员 | 管理用户、凭证、AI 模型、通知、安全策略和平台配置 |
| 质量负责人 | 追踪缺陷处理效率、重复问题、Token 成本和上线质量指标 |

## 4. 上线目标

### 4.1 核心目标

1. 完成项目、迭代、仓库、缺陷、评论、附件和通知的基础缺陷管理闭环。
2. 支持 AI 分析缺陷，并将分析结果沉淀到缺陷详情中。
3. 支持 AI 修复和人工修复两条路径，保证 AI 无法完成时仍可闭环处理。
4. 支持 PR 状态跟踪，PR 被拒绝后自动回退到待修复。
5. 支持问题池承接外部问题信号，并转化为正式缺陷。
6. 支持项目级凭证、AI 模型、通知和 Agent 能力配置。
7. 支持 Token 和成本统计，便于上线后运营和成本管控。
8. 支持状态变更、Webhook 签名失败、PR 拒绝等关键事件审计。

### 4.2 非目标

1. 不做通用工单、客服、CRM 或任务管理系统。
2. 不承诺 AI 自动完成所有缺陷修复，AI 输出必须允许人工确认和接管。
3. 不支持未授权仓库或凭证的代码访问。
4. 不在上线版本提供完整 IDE 能力。
5. 不将外部问题信号直接自动关闭或自动上线，关键动作保留人工确认。

## 5. 产品范围

### 5.1 上线范围

| 模块 | 上线内容 |
|---|---|
| 项目管理 | 项目、成员、迭代、仓库配置 |
| 缺陷管理 | 缺陷创建、列表、详情、状态流转、评论、附件 |
| 问题池 | 外部信号接入、问题分诊、转正式缺陷 |
| AI 分析 | 缺陷分析、报告生成、失败降级、进度展示 |
| 修复闭环 | AI 修复、人工修复、FixTask、PR URL 关联 |
| PR 生命周期 | PR 打开、合并、关闭、拒绝记录和状态回退 |
| Agent 能力 | 项目记忆、迭代记忆、MCP 服务、技能配置 |
| 通知 | 项目通知、个人通知偏好、Webhook、邮件 |
| 平台治理 | 用户、凭证、AI 模型、SMTP、强制改密、审计 |
| 运营统计 | Token 统计、费用估算、项目/迭代/缺陷维度汇总 |

### 5.2 暂不上线范围

1. 全自动上线发布。
2. 完整代码在线编辑器。
3. 跨企业多租户商业计费。
4. 不经人工确认的自动分诊、自动派单、自动关闭。
5. 非软件研发场景的泛工单模板。

## 6. 核心业务流程

### 6.1 缺陷创建流程

1. 用户进入项目。
2. 选择当前迭代和相关仓库。
3. 创建缺陷，填写标题、描述、类型、严重级别、优先级、附件等信息。
4. 系统生成缺陷编号。
5. 缺陷进入待分析状态。
6. 系统按项目通知策略通知相关人员。

### 6.2 对话式创建流程

1. 用户输入自然语言问题描述、日志、截图说明或复现步骤。
2. AI 生成结构化缺陷草稿。
3. 草稿包含标题、描述、严重级别、类型、标签和复现摘要。
4. 用户确认或编辑草稿。
5. 系统创建正式缺陷。

### 6.3 问题池分诊流程

1. 外部系统通过连接器上报问题信号。
2. 平台保存原始 payload 和接入记录。
3. 系统将信号归一化并进入问题池。
4. 系统识别疑似重复和问题簇。
5. AI 给出项目、责任人、严重级别、优先级和重复问题建议。
6. 分诊人员确认后转为正式缺陷。

### 6.4 AI 分析流程

1. 用户触发缺陷分析。
2. 系统提交分析任务并进入队列。
3. Agent 获取缺陷、项目、迭代、仓库、历史记忆和相关上下文。
4. Agent 执行分析并生成分析报告。
5. 前端实时展示分析进度。
6. 分析成功后缺陷进入待修复。
7. 分析失败时展示明确失败原因，缺陷主流程不被阻断。

### 6.5 修复流程

1. 缺陷进入待修复。
2. 用户选择 AI 修复或人工修复。
3. AI 修复时，系统使用隔离工作目录生成修复建议和变更。
4. 人工修复时，研发登记修复说明和 PR URL。
5. 修复完成后生成 FixTask。
6. 缺陷进入待验证。

### 6.6 PR 与验证流程

1. FixTask 关联 PR URL。
2. 系统接收 PR 状态变化。
3. PR 合并后，缺陷进入验证链路。
4. PR 被拒绝时，系统记录拒绝原因。
5. 缺陷自动回退到待修复。
6. 拒绝原因沉淀为 Agent 记忆，后续分析和修复可复用。
7. 测试验证通过后缺陷关闭。

## 7. 状态模型

| 状态 | 说明 |
|---|---|
| `pending_analysis` | 待分析 |
| `analyzing` | 分析中 |
| `pending_fix` | 待修复 |
| `manual_fixing` | 人工修复中 |
| `fixing` | AI 修复中 |
| `pending_verify` | 待验证 |
| `verified` | 验证通过 |
| `rejected` | 验证或 PR 被拒绝 |
| `closed` | 已关闭 |

状态要求：

1. 所有状态变更必须记录操作人、时间、来源和备注。
2. AI 分析失败不能导致缺陷卡死。
3. PR 被拒绝必须回退到 `pending_fix`。
4. 缺陷可重新回到 `pending_analysis` 触发完整分析。
5. 待验证状态下允许补充或修改 PR URL。

## 8. 功能需求

### FR-1 项目与迭代管理

需求说明：

1. 用户可创建、编辑、查看项目。
2. 项目下可维护成员、迭代、仓库和通知配置。
3. 用户进入项目后，后续操作默认使用当前项目上下文。
4. 项目内支持快速切换迭代。

验收标准：

1. 项目内创建缺陷、连接器、仓库时不需要重复选择项目。
2. 项目、迭代、仓库、缺陷的关联关系可追溯。
3. 项目切换后页面数据不串项目。

### FR-2 仓库管理

需求说明：

1. 支持手动添加仓库。
2. 支持仓库 URL 规范化去重。
3. 支持配置默认分支、来源类型和关联凭证。
4. 支持按 Agent 类型绑定可用仓库。
5. AI 修复时按缺陷隔离工作目录。

验收标准：

1. 同一项目内重复仓库不会重复创建。
2. 缺少仓库凭证时提示明确。
3. 并发修复不会互相覆盖文件。

### FR-3 缺陷管理

需求说明：

1. 支持缺陷创建、编辑、列表、详情和关闭。
2. 支持标题、描述、类型、严重级别、优先级、标签、责任人。
3. 支持评论、附件和状态历史。
4. 支持缺陷详情展示 AI 分析、修复任务和 PR 状态。
5. 支持筛选、搜索和排序。

验收标准：

1. 缺陷全生命周期可追溯。
2. 缺陷详情能完整展示当前处理进度。
3. 页面数据加载失败时展示错误和重试入口。

### FR-4 对话式缺陷创建

需求说明：

1. 用户可通过自然语言创建缺陷草稿。
2. AI 自动生成结构化标题、描述、类型、严重级别和标签。
3. 用户确认后再创建正式缺陷。

验收标准：

1. AI 草稿可编辑。
2. 用户不确认时不创建正式缺陷。
3. AI 失败时用户仍可手动创建缺陷。

### FR-5 问题池与外部信号

需求说明：

1. 支持连接器接入外部问题信号。
2. 支持保存原始 payload、幂等键和接入记录。
3. 支持问题池列表、详情和分诊。
4. 支持疑似重复识别和问题簇。
5. 支持转正式缺陷。

验收标准：

1. 外部信号进入问题池后可追溯来源。
2. 重复信号不会重复创建正式缺陷。
3. 转缺陷后保留问题池和缺陷关联。

### FR-6 连接器管理

需求说明：

1. 项目内可创建和管理连接器。
2. 连接器支持健康状态。
3. 连接器支持最近同步记录。
4. Webhook 连接器支持签名密钥。
5. 服务端校验 `X-Hub-Signature-256`。

验收标准：

1. 签名非法请求返回 401 或 403。
2. 签名失败记录审计日志。
3. 连接器异常时页面展示最近错误。

### FR-7 AI 分析

需求说明：

1. 用户可触发 AI 分析。
2. 系统展示分析进度。
3. 分析报告写入缺陷详情。
4. 分析过程使用项目、迭代、仓库和记忆上下文。
5. 分析失败时展示失败原因和降级结果。

验收标准：

1. AI 分析成功后生成报告。
2. AI 分析失败不阻断缺陷继续流转。
3. 用户可重新触发分析。

### FR-8 AI 修复与人工修复

需求说明：

1. 支持 AI 修复缺陷。
2. 支持人工修复路径。
3. 人工修复可登记修复说明和 PR URL。
4. 修复完成后生成 FixTask。
5. AI 修复和人工修复统一展示，但标明来源。

验收标准：

1. `pending_fix` 状态下可选择 AI 修复或人工修复。
2. 人工修复完成后生成 `FixTask(source=manual)`。
3. 放弃人工修复不会产生脏数据。

### FR-9 PR 生命周期

需求说明：

1. FixTask 支持 PR 状态。
2. 支持记录 PR 打开、合并、关闭、拒绝。
3. PR 被拒绝时记录拒绝原因。
4. PR 被拒绝后缺陷回退到待修复。
5. PR 拒绝原因进入 Agent 记忆。

验收标准：

1. PR 被拒绝的缺陷 100% 回退到 `pending_fix`。
2. PR 拒绝历史可追溯。
3. PR 状态变化能反映到缺陷详情。

### FR-10 Agent 记忆

需求说明：

1. 支持项目级记忆。
2. 支持迭代级记忆。
3. 支持用户手动录入记忆。
4. 支持从分析、修复和 PR 拒绝中提取记忆。
5. AI 分析和修复时可注入相关记忆。

验收标准：

1. 记忆可新增、编辑、删除和查看。
2. PR 拒绝原因可沉淀为避免策略。
3. AI 调用可使用项目和迭代上下文。

### FR-11 Agent 能力管理

需求说明：

1. 项目内可管理 MCP 服务。
2. 项目内可管理 Agent 技能。
3. 支持 MCP 服务连通性测试。
4. Agent 调度按项目配置动态构建能力。

验收标准：

1. 项目配置修改后 Agent 能力即时生效。
2. 无需修改服务配置文件完成常规能力变更。
3. MCP 连通性测试失败时提示明确。

### FR-12 凭证管理

需求说明：

1. 平台管理员可维护平台凭证。
2. 平台凭证可限制项目可见范围。
3. 用户可维护个人凭证。
4. 仓库可绑定凭证。
5. 凭证加密存储，接口返回脱敏。

验收标准：

1. 用户不能使用无权限凭证。
2. 凭证缺失时提示明确。
3. API 不返回明文密钥。

### FR-13 AI 模型配置

需求说明：

1. 支持维护 AI 厂商。
2. 支持维护 AI 模型。
3. 支持设置项目默认模型。
4. 支持模型可用性测试。
5. 支持密钥脱敏和加密。

验收标准：

1. 每个启用 AI 的项目至少有一个默认模型。
2. 模型不可用时不可静默失败。
3. 前后端模型来源一致。

### FR-14 通知管理

需求说明：

1. 支持项目通知配置。
2. 支持邮件和 Webhook。
3. 支持个人通知偏好。
4. 个人偏好不得突破项目允许范围。
5. Webhook 推送失败不影响主流程。

验收标准：

1. 项目管理员可配置通知通道。
2. 通知失败有记录。
3. 未配置 Webhook 目标时不发送 Webhook。

### FR-15 用户与安全

需求说明：

1. 支持用户管理。
2. 支持个人信息维护。
3. 支持强制修改密码。
4. 支持用户角色和项目权限。
5. 支持审计关键安全事件。

验收标准：

1. `must_change_password=true` 用户登录后必须改密。
2. 用户权限按项目角色生效。
3. 安全事件可追溯。

### FR-16 实时进度推送

需求说明：

1. 使用 SSE 推送分析进度。
2. 使用 SSE 推送修复进度。
3. 使用 SSE 推送缺陷状态变化。

验收标准：

1. 前端能实时看到分析和修复进度。
2. 推送断开后页面可重新建立连接。
3. 推送失败不影响主流程状态写入。

### FR-17 Token 与成本统计

需求说明：

1. 记录 AI 调用 Prompt Token、Completion Token 和总 Token。
2. 记录 AI 厂商、模型、耗时、费用估算、Fallback 标记。
3. 支持缺陷、迭代、项目维度统计。
4. 支持分析和修复分组统计。

验收标准：

1. 99% 以上 AI 调用有 Token 记录。
2. 单个缺陷可查看 Token 明细和汇总。
3. 项目负责人可查看项目成本趋势。

### FR-18 任务调度与取消

需求说明：

1. AI 分析任务进入队列。
2. 队列支持优先级和任务去重。
3. 系统控制并发执行数量。
4. 用户可取消分析任务。
5. 中断任务保留已产生记录。

验收标准：

1. 重复触发不会创建重复执行任务。
2. 用户取消后任务及时停止。
3. 队列状态可查询。

## 9. 数据与审计要求

### 9.1 必须保留的数据

1. 缺陷基础信息。
2. 缺陷状态变更记录。
3. AI 分析报告。
4. 修复任务记录。
5. PR 状态和拒绝记录。
6. 问题信号原始 payload。
7. 连接器同步记录。
8. Token 和费用记录。
9. 凭证使用范围。
10. 安全和审计事件。

### 9.2 审计事件

必须审计：

1. Webhook 签名失败。
2. 凭证新增、编辑、删除。
3. 用户强制改密。
4. PR 被拒绝。
5. AI 任务取消。
6. Agent 高风险工具操作。

## 10. 非功能需求

### 10.1 安全

1. 凭证加密存储。
2. API 返回密钥必须脱敏。
3. Webhook 必须支持签名校验。
4. 项目凭证必须隔离可见范围。
5. Agent 高风险操作必须可审计。

### 10.2 可靠性

1. AI 失败不阻断主流程。
2. 通知失败不阻断主流程。
3. 外部系统不可用时保留手动路径。
4. 修复目录按缺陷隔离。
5. 任务可取消，状态可恢复。

### 10.3 可观测性

1. 连接器有健康状态。
2. AI 调用有 Token 和耗时记录。
3. 状态流转有历史记录。
4. PR 生命周期可追溯。
5. 页面错误可见且可重试。

### 10.4 易用性

1. 项目内操作不重复选择项目。
2. 缺陷详情优先展示摘要、AI 结论和当前进展。
3. 列表筛选组件保持一致。
4. 错误提示必须可理解。

## 11. 上线验收指标

| 指标 | 上线标准 |
|---|---|
| 缺陷主流程 | 创建、分析、修复、验证、关闭可完整走通 |

## 13. 上线风险

| 风险 | 影响 | 上线处理要求 |
|---|---|---|
| AI 分析失败率偏高 | 用户信任下降 | 展示明确失败原因，保留人工路径 |
| 外部连接器配置错误 | 信号无法进入问题池 | 提供健康状态和最近错误 |
| PR Webhook 未配置 | PR 状态不同步 | 缺陷详情允许手动补充 PR 状态 |
| Token 成本不可控 | 成本超预期 | 上线即开启 Token 统计 |
| 凭证配置错误 | 仓库访问失败 | 缺少凭证时明确提示 |
| 页面接口异常 | 页面不可用 | 核心页面必须提供重试和错误说明 |
