## 2. v5.1 新增用例 — 项目化信号接入与连接器生产化

> 来源 PRD: PRD-v5.1-project-intake-productionization.md

### TC-V51-01 信号接入入口仅存在于项目内

- 前置条件：管理员已登录
- 步骤：
  1. 检查平台级导航，确认不存在"信号接入"入口
  2. 进入项目内，确认侧边栏有"信号接入"菜单
  3. 访问旧平台级 URL `/integration-connectors`
- 预期结果：
  1. 平台导航无信号接入入口
  2. 项目内信号接入可用
  3. 旧 URL 返回 404 或重定向到项目内
- 覆盖方式：人工

### TC-V51-02 项目内创建连接器并归属当前项目

- 前置条件：项目管理员已登录
- 步骤：
  1. 进入项目 → 信号接入
  2. 创建 Webhook 连接器
  3. 检查连接器的项目归属
- 预期结果：连接器自动归属当前项目，无需手动选择项目
- 覆盖方式：人工

### TC-V51-03 连接器健康状态展示

- 前置条件：项目内存在至少 1 个连接器
- 步骤：
  1. 进入信号接入页
  2. 查看连接器列表
- 预期结果：每个连接器显示健康状态（正常/异常/未知），异常连接器有明确错误分类
- 覆盖方式：人工

### TC-V51-04 连接器同步记录与失败诊断

- 前置条件：连接器已执行过至少一次同步
- 步骤：
  1. 查看连接器同步记录
  2. 模拟同步失败场景
- 预期结果：
  1. 同步记录包含时间、状态、处理条数
  2. 失败记录有错误分类和诊断信息
- 覆盖方式：人工

### TC-V51-05 连接器重试机制

- 前置条件：存在同步失败的连接器
- 步骤：
  1. 在失败记录上点击重试
- 预期结果：重新执行同步，结果更新
- 覆盖方式：人工

### TC-V51-06 问题池重复识别与聚类增强

- 前置条件：问题池中存在相似问题簇
- 步骤：
  1. 接入多条相似信号
  2. 查看问题池聚类结果
- 预期结果：相似信号自动聚类，合并后的问题簇包含所有关联信号
- 覆盖方式：人工

### TC-V51-07 路由建议与批量分诊

- 前置条件：问题池存在未分诊问题簇，项目已配置路由规则
- 步骤：
  1. 查看问题簇的路由建议
  2. 执行批量采纳建议
- 预期结果：建议包含项目/模块/负责人/优先级，批量采纳后状态正确变更
- 覆盖方式：人工

### TC-V51-08 AI 分析模型版本与失败降级

- 前置条件：项目配置了多个 AI 模型
- 步骤：
  1. 触发 AI 分析
  2. 模拟主模型失败
- 预期结果：
  1. 分析结果包含使用的模型版本信息
  2. 主模型失败时自动降级到备用模型，不阻塞流程
- 覆盖方式：人工

### TC-V51-09 接口契约与页面联调验证

- 前置条件：前后端均在运行
- 步骤：
  1. 逐页访问所有项目内页面
  2. 检查浏览器控制台无 500/404 错误
- 预期结果：所有页面数据正常加载，无接口报错
- 覆盖方式：自动化 + 人工

## 3. v5.2 新增用例 — Chat-First 缺陷创建与详情重构

> 来源 PRD: PRD-v5.2-chat-first-defect-and-detail-redesign.md

### TC-V52-01 对话式创建缺陷为默认入口

- 前置条件：用户已进入项目缺陷列表
- 步骤：
  1. 点击"新建缺陷"
  2. 检查默认打开的交互模式
- 预期结果：默认打开对话式创建界面，而非传统表单
- 覆盖方式：人工

### TC-V52-02 对话式创建缺陷 — AI 生成结构化草稿

- 前置条件：项目已配置可用 AI 模型
- 步骤：
  1. 在对话界面输入自然语言描述问题
  2. 等待 AI 生成草稿
- 预期结果：AI 返回结构化草稿，包含标题、描述、严重级别、类型、标签等字段
- 覆盖方式：人工

### TC-V52-03 用户确认草稿后才落库

- 前置条件：AI 已生成草稿
- 步骤：
  1. 查看 AI 生成的草稿
  2. 修改部分字段
  3. 点击确认创建
- 预期结果：确认前缺陷不存在于列表中；确认后缺陷正式创建

### TC-V52-04 高级模式表单仍可用

- 前置条件：用户在缺陷列表页
- 步骤：
  1. 查找高级模式入口
  2. 点击进入传统表单
- 预期结果：高级模式表单可用，所有字段可正常填写和提交

### TC-V52-05 手动创建缺陷自动进入问题池

- 前置条件：用户通过对话或表单创建缺陷
- 步骤：
  1. 创建一个手动缺陷
  2. 进入问题池查看
- 预期结果：问题池中自动生成 `manual_chat` 或 `manual_form` 来源的信号和问题簇，与缺陷双向关联
- 覆盖方式：人工

### TC-V52-06 问题池覆盖手动来源

- 前置条件：存在手动来源的问题簇
- 步骤：
  1. 在问题池筛选"来源=手动"

- 预期结果：手动来源问题簇可见，详情中可跳转到关联缺陷
- 覆盖方式：人工

### TC-V52-07 缺陷详情页 Markdown 正确渲染

- 前置条件：存在包含 Markdown 格式的缺陷描述和评论
- 步骤：
  1. 打开缺陷详情页
  2. 检查描述区域和评论区的渲染效果
- 预期结果：标题、列表、代码块、链接等 Markdown 语法正确渲染，非纯文本展示
- 覆盖方式：人工

### TC-V52-08 AI 分析结果结构化展示

- 前置条件：缺陷已完成 AI 分析
- 步骤：
  1. 打开缺陷详情页
  2. 查看 AI 分析结果区域
- 预期结果：分析结果以结构化摘要展示（根因、影响范围、建议修复方案），非大段纯文本
- 覆盖方式：人工

### TC-V52-09 自动修复结果结构化展示

- 前置条件：缺陷已完成自动修复
- 步骤：
  1. 打开缺陷详情页
  2. 查看修复结果区域
- 预期结果：修复结果展示 PR 链接、修改文件列表、修复策略摘要，非纯文本堆叠
- 覆盖方式：人工

### TC-V52-10 回归预防与质量情报覆盖手动来源

- 前置条件：存在手动来源的缺陷和回归项
- 步骤：
  1. 进入回归预防中心
  2. 进入质量情报页
- 预期结果：手动来源数据纳入统计和展示
- 覆盖方式：人工

## 4. v5.3 新增用例 — 智能运营与加固

> 来源 PRD: PRD-v5.3-intelligent-operations-and-hardening.md

### TC-V53-01 统一筛选/搜索栏组件一致性

- 前置条件：管理员已登录
- 步骤：
  1. 逐页访问缺陷管理、问题池、回归预防、用户管理、审计日志、项目列表
  2. 检查每页搜索/筛选栏的视觉结构和交互行为
- 预期结果：所有页面搜索/筛选栏视觉结构一致，无空白按钮、双边框、错位等问题
- 覆盖方式：人工

### TC-V53-02 Webhook 连接器签名校验 — 正常签名通过

- 前置条件：连接器已配置签名密钥（Secret）
- 步骤：
  1. 使用正确的 HMAC-SHA256 签名发送 Webhook 请求
- 预期结果：请求通过，信号正常接入
- 覆盖方式：自动化 + 人工

### TC-V53-03 Webhook 连接器签名校验 — 非法签名拒绝

- 前置条件：连接器已配置签名密钥
- 步骤：
  1. 使用错误的签名发送 Webhook 请求
- 预期结果：请求被拒绝（401/403），审计日志记录签名失败事件
- 覆盖方式：自动化 + 人工

### TC-V53-04 Webhook 签名失败审计记录

- 前置条件：已触发签名校验失败
- 步骤：
  1. 进入审计日志页
  2. 搜索签名失败记录
- 预期结果：审计日志包含失败来源 IP、时间、原因
- 覆盖方式：人工

### TC-V53-05 智能推荐分配 — 返回推荐列表

- 前置条件：存在历史处理记录
- 步骤：
  1. 打开待分配缺陷
  2. 查看指派推荐
- 预期结果：返回 Top-N 推荐对象，每条推荐包含推荐理由（类型匹配/历史命中/负载）
- 覆盖方式：人工

### TC-V53-06 智能推荐分配 — 一键采纳

- 前置条件：推荐列表已返回
- 步骤：
  1. 点击一键采纳推荐
- 预期结果：缺陷自动分配给推荐人选，状态流转正确
- 覆盖方式：人工

### TC-V53-07 智能推荐分配 — 采纳行为记录

- 前置条件：已执行推荐采纳或手动覆盖
- 步骤：
  1. 查看分配历史或审计记录
- 预期结果：记录推荐是否被采纳，为后续优化提供反馈数据
- 覆盖方式：人工

### TC-V53-08 AGENT 自动推荐

- 前置条件：缺陷处于待分析状态
- 步骤：
  1. 查看 AGENT 推荐组合

### TC-V53-09 AGENT 推荐手动覆盖与偏好记录

## 5. v5.4 新增用例 — 人工修复、PR 生命周期与 Agent 记忆

> 来源 PRD: PRD-v5.4-manual-fix-pr-lifecycle-agent-memory.md

### 5.1 FR-1 人工修复路径

#### TC-V54-01 pending_fix 状态下触发人工修复

- 前置条件：缺陷处于 `pending_fix` 状态
- 步骤：
  1. 打开缺陷详情页
  2. 点击"人工修复"按钮
- 预期结果：缺陷状态变为 `manual_fixing`，页面展示人工修复表单
- 覆盖方式：人工

#### TC-V54-02 人工修复填写修复信息

- 前置条件：缺陷处于 `manual_fixing` 状态
- 步骤：
  1. 填写修复描述（必填）
  2. 填写关联 PR URL（选填）
  3. 填写修复分支名（选填）
- 预期结果：所有字段可正常填写和保存
- 覆盖方式：人工

#### TC-V54-03 人工修复提交完成

- 前置条件：缺陷处于 `manual_fixing` 状态，已填写修复描述
- 步骤：
  1. 点击"修复完成"
- 预期结果：
  1. 缺陷状态变为 `pending_verify`
  2. 系统自动创建一条 FixTask（`source=manual`）
  3. FixTask 包含修复描述和 PR URL
- 覆盖方式：人工

#### TC-V54-04 放弃人工修复回退

- 前置条件：缺陷处于 `manual_fixing` 状态
- 步骤：
  1. 点击"放弃人工修复"
- 预期结果：缺陷状态回退到 `pending_fix`，不产生脏数据
- 覆盖方式：人工

#### TC-V54-05 人工修复 FixTask 与 AI 修复 FixTask 统一展示且可区分

- 前置条件：同一缺陷存在 AI 修复和人工修复的 FixTask
- 步骤：
  1. 打开缺陷详情页
  2. 查看 FixTask 列表
- 预期结果：两种来源的 FixTask 统一展示，通过标签/颜色区分来源（`auto` / `manual`）
- 覆盖方式：人工

#### TC-V54-06 pending_verify 状态补关联 PR

- 前置条件：缺陷处于 `pending_verify` 状态，FixTask 无 PR URL
- 步骤：
  1. 在 FixTask 上补填 PR URL
- 预期结果：PR URL 保存成功，FixTask 更新
- 覆盖方式：人工

#### TC-V54-07 人工修复 API 鉴权与状态守卫

- 前置条件：缺陷不处于 `pending_fix` 状态
- 步骤：
  1. 尝试调用 `/defects/:id/manual-fix/start`
- 预期结果：返回状态冲突错误，不允许非法状态转换
- 覆盖方式：自动化 + 人工

### 5.2 FR-2 PR 拒绝处理与状态回退

#### TC-V54-08 手动标记 PR 被拒绝

- 前置条件：缺陷处于 `pending_verify`，FixTask 有关联 PR
- 步骤：
  1. 调用 `/defects/:id/fix-tasks/:taskId/reject`
  2. 填写拒绝原因
- 预期结果：
  1. FixTask 的 `PRStatus` 更新为 `rejected`
  2. 缺陷状态回退到 `pending_fix`
  3. 生成 `PRRejection` 记录
  4. 发布拒绝评论通知
- 覆盖方式：人工

#### TC-V54-09 手动标记 PR 已合并

- 前置条件：缺陷处于 `pending_verify`，FixTask 有关联 PR
- 步骤：
  1. 调用 `/defects/:id/fix-tasks/:taskId/merge`
- 预期结果：
  1. FixTask 的 `PRStatus` 更新为 `merged`
  2. 缺陷状态推进到 `fixed`
  3. 发布合并评论通知
- 覆盖方式：人工

#### TC-V54-10 查看 PR 拒绝历史

- 前置条件：FixTask 存在 PR 拒绝记录
- 步骤：
  1. 打开缺陷详情页
  2. 查看 FixTask 的拒绝历史
- 预期结果：可查看每次拒绝的拒绝人、原因、时间
- 覆盖方式：人工

#### TC-V54-11 PRRejection 记录完整性

- 前置条件：已执行 PR 拒绝操作
- 步骤：
  1. 调用 `/defects/:id/fix-tasks/:taskId/rejections`
- 预期结果：返回记录包含 `fixTaskId`、`prNumber`、`prUrl`、`rejectedBy`、`rejectReason`、`vcsProvider`、`createdAt`
- 覆盖方式：自动化 + 人工

#### TC-V54-12 VCS Webhook 接收 PR 状态变更（如已实现）

- 前置条件：已配置 VCS Webhook
- 步骤：
  1. 在 VCS 侧关闭 PR（不合并）
  2. 观察系统反应
- 预期结果：
  1. 系统收到 Webhook 事件
  2. 自动创建 PRRejection 记录
  3. 缺陷状态自动回退
- 覆盖方式：真实外部联调

#### TC-V54-13 VCS Webhook 签名校验

- 前置条件：Webhook 已配置签名密钥
- 步骤：
  1. 发送带正确签名的 Webhook 请求
  2. 发送带错误签名的 Webhook 请求
- 预期结果：正确签名通过，错误签名拒绝
- 覆盖方式：自动化 + 人工

#### TC-V54-14 PR 拒绝后状态回退率 100%

- 前置条件：多条缺陷处于 `pending_verify` 且 PR 被拒绝
- 步骤：
  1. 对所有缺陷执行 PR 拒绝
  2. 检查每条缺陷状态
- 预期结果：所有缺陷状态均回退到 `pending_fix`，无遗漏
- 覆盖方式：自动化 + 人工

### 5.3 FR-3 Agent 记忆体系

#### TC-V54-15 AI 分析完成后自动提取记忆

#### TC-V54-16 AI 修复完成后自动提取记忆

- 前置条件：缺陷完成 AI 修复
- 步骤：
  1. 触发 AI 修复并等待完成
  2. 检查 `AgentMemory` 表
- 预期结果：自动新增记忆条目，包含 `fix_strategy` 类别
- 覆盖方式：自动化 + 人工

#### TC-V54-17 PR 拒绝自动沉淀 avoid_strategy 记忆
