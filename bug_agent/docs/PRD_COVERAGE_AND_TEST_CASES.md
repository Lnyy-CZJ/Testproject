## 1. 结论摘要

### 1.1 当前结论

按当前仓库中的有效 PRD 范围核对，**未发现仍属于“当前交付要求”但尚未开发的功能缺口**。

当前状态应分三类理解：

1. **已实现并已进入代码、路由、页面和自动化覆盖**
   - v1 基线缺陷域
   - v2.0 交互与权限简化
   - v3.0 云效与 AI 目录数据库化
   - v4.0 平台凭证 / 项目通知 / 个人中心 / SMTP / AI 目录治理
   - v5.0 问题信号接入 / 问题池 / 路由治理 / 版本发布 / 回归预防 / 质量情报
2. **被后续 PRD 明确覆盖或替换，不应再视为缺口**
   - 基线 PRD 的组织管理模型，被 v2.0 的“移除 Organization”替换
   - v3.0 的“AI 目录失败时回退内置清单”，被 v4.0 的“数据库唯一数据源策略”替换
3. **属于路线图或后续规划，当前不应按“未完成”判定**
   - v5.0 路线图中的双向回写
   - v5.0 路线图中的更多外部渠道扩展
   - 更复杂的自定义规则编排与全渠道一次性接入

### 1.2 唯一需要单独区分的项

以下能力当前代码已具备，但**完整验收依赖真实外部环境**，因此在本文件中标记为“已开发，需真实外部联调验收”：

1. 云效真实仓库/成员导入
2. Bugly 真实问题拉取
3. 钉钉/飞书真实机器人入站
4. 阿里云日志平台真实 SLS 查询拉取

这类项不属于“未开发”，而属于“外部系统验收前提未满足时无法在本地完全闭环”。

### 2.1 被覆盖条目

1. **组织管理**
   - 基线 PRD 采用 `Organization -> Project -> Iteration` 三层模型。
   - `docs/PRD-v2.0.md` 明确要求移除 Organization，项目成为顶层。
   - 因此当前代码不再以组织管理为交付目标，不应判定为缺失。

2. **AI 目录 fallback**
   - `docs/PRD-v3.0-phase3-yunxiao-ai-db.md` 要求数据库空时回退内置目录。
   - `docs/PRD-v4.0-phase4-platform-credential-notify-config.md` 明确改为数据库唯一数据源，不再回退代码清单。
   - 因此当前实现按 v4 判定才是正确结果。

### 2.2 规划项

以下条目存在于 v5 路线图或总体规划中，但当前不属于“必须已经开发完成”的阻塞项：

1. 外部系统状态/评论双向回写
2. 企业微信/邮件/更多质量平台接入
3. 复杂规则编排引擎
4. 自研 App 崩溃采集 SDK

## 5. 完整测试用例

说明：

1. `当前评估` 用于标记当前代码状态。
2. `覆盖方式` 分为：`自动化`、`人工`、`自动化 + 人工`、`真实外部联调`。
3. 对真实外部环境有依赖的用例，若无凭证/真实数据，执行结论应标记为 `BLOCKED(环境)`，而不是 `FAIL(未开发)`。
