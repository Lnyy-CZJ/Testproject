# V5.1 Project-Scoped Intake Productionization Design

> Date: 2026-04-13
> Status: Draft
> Scope: v5.1

---

## 1. Context

`v5.0` 已经完成问题信号接入、问题池、路由治理、版本影响、回归预防和质量情报主干能力，但当前版本仍有三类明显落差：

1. **信息架构落差**
   - `问题池 / 路由治理 / 回归预防 / 质量情报` 已经在项目内闭环。
   - `信号接入` 仍然停留在平台级页面 `/integration-connectors`。
   - 这要求用户先在平台层创建连接器、再人为选择项目归属，和产品主链路不一致。

2. **生产可用性落差**
   - 连接器代码已存在，但真实外部联调仍大面积依赖 mock 或占位凭证。
   - 缺少健康检查、同步诊断、失败重试、错误分类、死信与接入运营能力。

3. **体验与稳定性落差**
   - 页面数据获取失败在体验过程中已多次出现。
   - 部分页面对接口结构耦合过深，错误态、空态和重试态不统一。
   - 接口契约与页面联调缺少系统性收口。

因此，`v5.1` 的目标不是继续增加更多外围功能，而是把 `v5.0` 已有主线推进到“可真实接入、可稳定分诊、可可信 AI 处置”的生产级阶段。

---

## 2. Product Direction

`v5.1` 继续沿用 `v5.0` 产品定位：

> 面向 App 团队的缺陷信号接入、智能分诊、AI 处置与质量闭环平台。

但交付重心从“能力补齐”转为“能力落地”。

本期聚焦四个方向：

1. `P0` 接口测试与页面联调专项
2. `P1` 项目内信号接入中心重构
3. `P2` 真实连接器生产化
4. `P3` 分诊智能准确率
5. `P4` AI 处置可信化

其中 `P0` 是贯穿项，不是可选项。

---

## 3. Core Decisions

### 3.1 信号接入入口完全下沉到项目内

结论：**不保留平台级接入页和平台级接入接口。**

具体决策：

1. 删除平台菜单中的接入中心入口。
2. 删除前端路由 `/integration-connectors`。
3. 删除前端平台级接入页面作为用户入口。
4. 删除后端平台级连接器接口，不做兼容保留。
5. 所有连接器能力改为通过项目上下文访问：
   - 创建
   - 编辑
   - 删除
   - 测试
   - 同步
   - 同步记录
6. 数据模型保留 `project_id` 即可，不引入“平台级连接器”语义。

原因：

1. 当前产品主链路已经围绕项目展开。
2. 接入、问题池、路由、回归、质量情报应处于同一上下文。
3. 双入口和兼容层只会留下历史负债，不符合当前“未上线、允许直接收敛”的现实条件。

### 3.2 `v5.1` 不做平台级连接器模板页

结论：本期不做全局模板能力。

原因：

1. 当前首要问题是入口错位和生产化不足，不是模板复用。
2. 模板能力会重新引入平台层复杂度。
3. 等项目内接入中心稳定后，再评估是否以平台级“模板库”形式引入，而不是直接返回平台级接入页。

### 3.3 接口测试与页面联调作为版本强约束

结论：`P0` 贯穿所有 Sprint。

要求：

1. 所有新页面必须提供加载态、空态、错误态和重试动作。
2. 所有新增 API 必须有 handler/service 层自动化测试。
3. 所有项目主链路页面必须纳入浏览器回归。
4. 发现“数据获取失败”类问题时，优先收口契约与错误语义，不用前端规避替代真实修复。

### 3.4 真实外部系统联调必须进入版本 DoD

结论：`v5.1` 不接受只靠 mock 宣布完成。

最低要求：

1. 至少 1 条真实接入链路稳定跑通。
2. 最好覆盖 2 类：
   - 1 个拉取型连接器（如 Bugly / 阿里云日志）
   - 1 个入站型连接器（如钉钉 / 飞书 / Webhook）
3. Yunxiao 作为已有历史链路，至少要把凭证失效诊断流程补齐。

## 4. Information Architecture

### 4.1 Platform-Level Navigation

平台层保留：

1. 用户管理
2. 审计日志
3. AI 目录
4. 平台凭证
5. 平台配置

平台层删除：

1. 信号接入入口

### 4.2 Project-Level Navigation

项目侧建议统一为：

1. 工作台
2. 缺陷
3. 问题池
4. 信号接入
5. 路由治理
6. 回归预防
7. 质量情报
8. 迭代管理
9. 成员管理
10. 仓库管理
11. AI 配置
12. 通知管理
13. 项目设置

### 4.3 Project Intake Center

新增项目页：

`/projects/:projectId/integrations`

页面职责：

1. 查看当前项目连接器列表
2. 新增/编辑/删除连接器
3. 测试连接器
4. 手动同步
5. 查看同步记录
6. 查看最近错误
7. 查看健康状态与诊断结果

关键变化：

1. 不再让用户手动选择项目归属
2. 当前项目上下文即唯一归属
3. 所有接入数据默认按当前项目隔离

### 4.4 Cross-Page Linking

1. 问题池为空时，应引导去“信号接入”页配置连接器。
2. 问题池中某来源失败或长时间无新信号时，应可跳到对应连接器查看同步记录。
3. 路由治理应能解释：新信号进来后命中哪些规则、为什么建议某负责人。

## 5. Module Breakdown

### 5.1 P0: API Test And Frontend-Backend Integration Hardening

目标：系统性收口“页面数据获取失败”。

交付范围：

1. 核心接口冒烟测试
2. 关键页面联调清单
3. 前后端响应契约统一
4. 页面级空态/错误态/重试态规范
5. 错误语义标准化

成功标准：

1. 主链路页面不再频繁出现“数据获取失败”。
2. 获取失败时错误信息可读、可重试、可恢复。
3. 页面不依赖刷新或重新登录恢复正常。

### 5.2 P1: Project-Scoped Intake Center Migration

目标：把信号接入完全迁入项目上下文。

交付范围：

1. 项目内“信号接入”页面
2. 删除平台级接入页与平台级路由
3. 项目级接入接口
4. 权限与导航同步收口
5. 测试与文档同步迁移

成功标准：

1. 不再存在平台级接入入口
2. 所有连接器管理动作均可在项目内完成
3. 问题池、路由、信号接入在同一项目上下文闭环

### 5.3 P2: Connector Productionization

目标：连接器从“可用”提升为“可运营”。

交付范围：

1. 健康检查
2. 同步任务中心
3. 错误分类
4. 手动重试
5. 死信/失败记录
6. 配置诊断
7. 连接器测试结果标准化
8. 接入审计

成功标准：

1. 连接器失败原因可诊断
2. 失败后可重试，不依赖手工重建
3. 至少一条真实接入链路稳定跑通

### 5.4 P3: Triage Accuracy Improvement

目标：提高问题池建议的可信度和效率。

交付范围：

1. 重复问题识别增强
2. 聚类质量优化
3. 路由建议置信度
4. 推荐依据展示
5. 批量分诊
6. 人工修正反馈记录
7. 建议采纳率统计

成功标准：

1. 建议可解释，不是黑盒
2. 分诊人员修正成本下降
3. 高频重复问题不会持续冲击缺陷域

### 5.5 P4: AI Handling Trustworthiness

目标：让 AI 分析/修复链路具备生产可信边界。

交付范围：

1. 模型/Prompt 版本记录
2. 调用链路审计
3. 分析失败降级策略
4. 多模型 fallback
5. 风险摘要
6. 修复前验证建议
7. AI 成本/延迟/成功率观测

成功标准：

1. AI 分析失败不会打断主流程
2. AI 输出具备足够解释性
3. AI 链路可观测、可审计、可复盘

---

## 6. Execution Order

顺序固定为：

1. `P0`
2. `P1`
3. `P2`
4. `P3`
5. `P4`

原因：

1. 不先做稳定性专项，后续每个模块都会继续制造页面联调问题。
2. 不先迁移接入中心，就会在错误的信息架构上继续叠加生产化能力。
3. 没有真实连接器数据，分诊准确率优化收益有限。
4. 上游接入和分诊稳定后，AI 可信化的价值最大。

---

## 7. Risks

### 风险 1：删除平台级入口带来一次性破坏性改动

应对：

1. 直接迁移，不做兼容
2. 一次性同步路由、导航、测试、文档

### 风险 2：真实外部系统联调继续被环境阻塞

应对：

1. 把真实凭证、测试组织、SLS 查询规则列为 Sprint 前置物料
2. 没有物料则该连接器项不算验收完成

### 风险 3：功能继续压过稳定性治理

应对：

1. 每个 Sprint 设置联调通过门槛
2. 任何“数据获取失败”类问题优先级高于新页面微调

### 风险 4：分诊与 AI 能力继续黑盒化

应对：

1. 推荐必须展示依据
2. AI 必须记录版本、失败原因和降级路径

---

## 8. Definition Of Done

`v5.1` 完成时，必须同时满足：

1. 信号接入已完全迁入项目内
2. 平台级接入页与平台级接入接口已删除
3. 至少 1 到 2 条真实连接器链路完成联调闭环
4. 问题池分诊建议具备可解释性和批量处理能力
5. AI 分析/修复链路具备基本可信化与可观测能力
6. 核心接口测试、页面联调、浏览器回归全通过
