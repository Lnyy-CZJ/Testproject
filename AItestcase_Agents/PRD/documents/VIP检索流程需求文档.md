
## 一、流程概述

### 1.1 流程定位

VIP用户点击「Search」后，进入**真实检索加载 → 候选集匹配 → 单一人物报告**流程。VIP用户享受完整的深度检索能力，系统真实执行多源数据查询并生成人物报告。

### 1.2 完整流程链路

```
线索页（VIP用户点击 Search）
    │
    ▼
检索加载页（真检索 · Deep Search）
    ├── 真实进度展示（分组检索策略）
    └── 异常处理（超时/异常 → 弹报错 → 回线索页）
    │
    ▼
获得候选集结果
    │
    ├── 候选集为空？ ──是──→ 候选人为空页 → 补充线索页 → 重新Search
    │
    └── 否
         │
         ├── 单候选 & 置信度≥70分？ ──是──→ 进入「单一人物报告页」
         │
         └── 否 ──→ 潜在候选人页
                      ├── 用户选择人物 + 点击「Continue」──→ 进入单一人物报告页
                      └── 用户点击「Not Find?」──→ 补充线索页 → 重新Search
```

## 二、检索加载页（真检索）

### 2.1 页面触发路径 & 条件

| 条件   | 说明                     |
| ---- | ---------------------- |
| 来源页面 | 线索页                    |
| 触发操作 | 点击「Search」按钮           |

- 做一个**通用加载页**（动画可轮播），后端进行检索过程中持续展示
- 如超时或其他异常则弹报错弹窗，返回线索页并保留已填写内容

### 2.3 页面布局

| 元素      | 说明                           |
| ------- | ---------------------------- |
| 关闭按钮（×） | 右上角，点击返回线索页                  |
| 主标题     | "**Deep Search**"            |
| 主标题下方   | "搜索输入框的缩小版画面"                |
| 中心视觉    | 动画IP展显                       |
| 下方提醒    | 小字说明提醒                       |
| 进度步骤    | 采用：入场动画 + 核心循环动画 + 回调完成后收尾动画 |

### 2.4 检索进度步骤

| 步骤       | 状态        | 说明           |
| -------- | --------- | ------------ |
| Step 1   | 动画ip入场    | 建立正在生成完整报告感知 |

## 三、潜在候选人页

### 3.1 页面布局

| 元素      | 说明                                                |
| ------- | ------------------------------------------------- |
| 返回按钮（←） | 左上角，点击返回线索页                                       |

| 底部按钮    | 「Not Find?」（白色）+「Continue」（黄色主按钮）                 |


### 3.2 候选人列表展示

每个候选人卡片包含以下信息：

| 字段    | 说明                                          |
| ----- | ------------------------------------------- |
| 姓名    | 全名（如 Elon Musk）                             |
| 标签    | "Most Likely" 标签（最高分候选人）                    |
| 头像    | 人物照片                                        |
| 社交账号  | 平台 icon 展示（X、IN、FB 等）+ "+N more"            |
| 职业/描述 | 职业信息（如 Entrepreneur · CEO of Tesla, SpaceX） |
| 年龄    | 年龄信息（如 52）                                  |
| 位置    | 地理位置（如 Palo Alto, CA, USA）                  |

### 3.3 候选人列表排序规则

- 维度&重要性：资料完𡍶度＞社交信息丰富度＞社交信息活跃度＞公众影响力＞地理相关性
- 排序期望：排名按照「加权公式得分」由高到低排列

#### 加权公式规则

- Score = 0.35*资料完整度+0.25*社交信息丰富度＋0.2*社交活跃度＋0.1 公众影响力＋0.1*地理相关性
可以将公式标准化并明确写成如下形式：
## 总评分（Score）

# [  
\text{Score}

0.35 \times C  
+  
0.25 \times S  
+  
0.20 \times A  
+  
0.10 \times I  
+  
0.10 \times G  
]

其中：

- (C) = 资料完整度（Completeness）
    
- (S) = 社交信息丰富度（Social Coverage）
    
- (A) = 社交活跃度（Activity）
    
- (I) = 公众影响力（Influence）
    
- (G) = 地理相关性（Geo Relevance）
    

所有维度评分范围均为 ([0,1])。

> 权重总和为：
> 
> [  
> 0.35+0.25+0.20+0.10+0.10=1.00  
> ]
> 
> 因此最终 Score 范围也是 ([0,1])。

# 1. 资料完整度（C）

### 字段得分

基础字段共 7 项：

- 姓名
    
- 性别
    
- 年龄
    
- 所在地区
    
- 职业
    
- 公司
    
- 教育背景
    

每存在一项：

[  
+1  
]

### 社交账号

[  
\begin{cases}  
+2,& \text{社交账号数}\ge1\  
+1,& \text{否则}  
\end{cases}  
]

### 私人联系方式

[  
\begin{cases}  
+1,& \text{联系方式数}\ge1\  
+0,& \text{否则}  
\end{cases}  
]

### 完整度计算

总分满分为 10：

[  
C=  
\frac{  
N_{basic}  
+  
P_{social}  
+  
P_{contact}  
}{10}  
]

其中：

- (N_{basic})：已填写基础字段数量（0~7）
    
- (P_{social})：社交账号得分（1或2）
    
- (P_{contact})：联系方式得分（0或1）
    

---

### 示例

已知：

- 姓名、地区、职业、公司存在（4项）
    
- 有社交账号（+2）
    
- 有联系方式（+1）
    

则：

# [  
C=  
\frac{4+2+1}{10}

0.7  
]

---

# 2. 社交信息丰富度（S）

统计以下 6 个平台：

- LinkedIn
    
- Instagram
    
- Facebook
    
- YouTube
    
- X（Twitter）
    
- TikTok
    

同平台多个账号只计一次。

[  
S=  
\frac{N_{platform}}{6}  
]

其中：

# [  
N_{platform}

\text{已发现URL的平台数量}  
]

---

### 示例

发现：

- LinkedIn
    
- Facebook
    
- X
    

共 3 个平台：

# [  
S=  
\frac{3}{6}

0.5  
]

---

# 3. 社交活跃度（A）

首先计算：

## [  
D=  
\text{当前日期}

\text{最近一次公开发帖日期}  
]

然后映射：

[  
A=  
\begin{cases}  
1.0,& D\le7\  
0.8,& 8\le D\le30\  
0.4,& 31\le D\le90\  
0.1,& 91\le D\le180\  
0.0,& D>180\ \text{或无数据}  
\end{cases}  
]

---

# 4. 公众影响力（I）

## 粉丝影响力

设：

[  
F=  
\text{所有平台粉丝数总和}  
]

粉丝贡献：

# [  
I_{fans}

\min\left(\frac{F}{10000},1\right)\times0.8  
]

即：

- 粉丝数达到 1 万即封顶
    
- 粉丝部分最高得分 0.8
    

---

## Wikipedia加分

# [  
I_{wiki}

\begin{cases}  
0.2,& \text{存在任意语言Wikipedia页面}\  
0,& \text{否则}  
\end{cases}  
]

---

## 公众影响力总分

[  
I=  
I_{fans}  
+  
I_{wiki}  
]

---

### 示例

粉丝总数：

[  
5000  
]

有 Wikipedia：

# [  
I=  
\left(\frac{5000}{10000}\times0.8\right)  
+0.2

# 0.4+0.2

0.6  
]

---

# 5. 地理相关性（G）

比较：

- 用户提供城市：`user_city`
    
- 候选人城市：`location`
    

[  
G=  
\begin{cases}  
1,& user_city = location\  
0,& user_city \ne location  
\end{cases}  
]

---

# 最终完整公式

# [  
\boxed{  
Score

0.35C  
+  
0.25S  
+  
0.20A  
+  
0.10I  
+  
0.10G  
}  
]

展开后：

# [  
\boxed{  
Score

0.35\left(  
\frac{  
N_{basic}  
+  
P_{social}  
+  
P_{contact}  
}{10}  
\right)  
+  
0.25\left(  
\frac{N_{platform}}{6}  
\right)  
+  
0.20A  
+  
0.10\left[  
\min\left(\frac{F}{10000},1\right)\times0.8  
+  
I_{wiki}  
\right]  
+  
0.10G  
}  
]

该公式最终输出范围：

[  
0 \le Score \le 1  
]

可直接用于产品文档、PRD 或工程实现。

## 六、关键交互状态汇总

| 编号 | 交互点 | 触发条件 | 行为 |
|------|--------|---------|------|
| 1 | 进入真检索加载页 | VIP用户点击 Search | 展示 Deep Search 页面，真实执行检索 |
| 2 | 检索进度展示 | 检索过程中 | 分组检索策略，步骤逐步点亮 |
| 3 | 检索异常处理 | 超时或其他异常 | 弹报错弹窗，返回线索页保留已填内容 |
| 4 | 候选人为空 | 检索完成无匹配结果 | 跳转候选人为空页 |
| 5 | 补充线索 | 点击 Add more clues / Not Find? | 跳转线索页，填写后重新 Search |
| 6 | 潜在候选人页展示 | 候选人非空且非单候选高候选人评分 | 展示 Top 10 候选人列表，默认选中 Top 1 |
| 7 | 切换人物选择 | 点击其他候选人卡片 | 切换选中状态（单选） |
| 8 | Continue | 点击 Continue 按钮 | 进入单一人物报告页 |
| 9 | 自动进入单一人物报告页 | 单候选 & 候选人评分≥70分 | 跳过候选人页，直接进入单一人物报告页 |
| 10 | 返回线索页 | 点击返回按钮 | 保留已加线索内容 |
