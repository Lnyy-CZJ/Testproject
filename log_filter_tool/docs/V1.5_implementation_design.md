# Log 工具 V1.5 实现设计

## 目标

在现有日志过滤功能上增加基础接口分析：识别请求和响应，提取 `method`、`request_id`、`trace_id`、HTTP 状态码，并统计接口请求、响应、成功、失败、未响应和成功率。

## 实现范围

- 保留现有 method 精确过滤和控制台前缀清理。
- 增加日志块结构化解析。
- 增加请求/响应类型识别。
- 增加 request_id、trace_id、时间和状态码提取。
- 增加按 method 的接口统计和状态码分布。
- 在现有 Flask 页面增加统计概览和接口统计表。
- 增加解析函数、统计函数和页面路由测试。

## 统计口径

- 请求次数：包含 `[HTTP] -->` 的请求头日志块数量。
- 响应次数：包含 `[HTTP] <--` 且能提取状态码的响应头日志块数量。
- 请求体和响应体只作为上下文，不重复计数。
- 成功次数：响应状态码为 200 到 299 的数量。
- 失败次数：响应状态码大于等于 400 的数量。
- 未响应次数：`max(request_count - response_count, 0)`。
- 成功率：`success_count / response_count * 100`，无响应时为 0%。

## 解析规则

- method 支持 `method=xxx` 和 `"method_name": "xxx"`。
- request_id、trace_id 支持冒号、等号和 JSON 字段格式。
- 状态码优先识别 `[HTTP] <-- 200`，其次识别 HTTP 状态行和 `status_code` 字段。
- `[HTTP] -->`、`[HTTP] request:` 识别为 request；`[HTTP] <--`、`[HTTP] response:` 识别为 response。
- 无法识别的内容归类为 other，不影响原始日志展示。

## 代码结构

在 `app.py` 中新增独立函数：

- `extract_request_id`
- `extract_trace_id`
- `extract_status_code`
- `detect_log_kind`
- `parse_log_block`
- `parse_log_blocks`
- `build_interface_statistics`

解析函数不依赖 Flask，便于单元测试。页面继续使用当前 `/` 路由和内存数据，不引入数据库或新依赖。

## 页面变化

在原有过滤结果上方增加：

- 总接口数、请求数、响应数、成功数、失败数。
- 当前接口统计。
- HTTP 状态码分布。

选择“全部”显示全部接口统计，选择具体 method 显示当前接口统计；原始日志过滤行为保持不变。

## 测试范围

- request_id、trace_id、状态码和日志类型提取。
- 单个日志块解析。
- 多接口统计和成功率计算。
- 无响应和缺少字段处理。
- 页面 POST 返回统计信息。
- 现有过滤、精确匹配、前缀清理和大日志测试继续通过。

## 非目标

本版本不实现请求和响应的一一关联、耗时计算、业务失败识别、超时分析、异常根因分析、脱敏、实时日志和数据持久化。
